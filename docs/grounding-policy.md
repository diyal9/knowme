# KnowMe 事实证据与输出门禁

KnowMe 对外部事实采用“证据优先、失败闭环”的默认策略：没有可追溯正文或权威数据时，不输出具体事实，改为说明缺失项并引导重试、补充来源或授权。

## 证据等级

1. **权威正文/数据**：文档正文、会议转写、聊天结果、日历/任务结构化返回，可支撑事实陈述。
2. **来源发现结果**：搜索、候选、知识库推荐只能用于定位来源，不能单独支撑责任人、日期、结论、待办等事实。
3. **标题与元数据**：标题、token、权限、组织者字段等不能视为正文。
4. **模型推断**：必须明确标注为推测，不得改写成“已读取”或“已确认”。

## 门禁规则

- 工具调用成功不等于内容读取成功；空响应、仅标题响应、截断响应均不能完成事实任务。
- 会议总结必须同时满足：读取成功、正文非空、正文含会议语义证据；否则拒绝生成摘要、参会人、结论和行动项。
- 具体外部事实必须有非发现型工具的有效 EvidenceLedger 记录。
- 工具参数中的文档/token/URL与返回结果中的来源标识不一致时，结果记为无效，不得继续总结。
- 读取、发送、发布、删除、写入等执行声明必须有对应 ToolLedger 成功调用。
- 数字选择必须绑定当前候选列表；候选缺失时禁止猜测绑定对象。

## 失败闭环

门禁失败后按优先级处理：

1. 说明缺失的是工具、权限、候选还是正文；
2. 在有限预算内重试或扩大检索范围；
3. 请求用户补充链接/token或选择候选；
4. 仍无证据时输出诚实拒答，不保留模型生成的具体事实。

该策略允许普通聊天和创意写作保持流畅，但对会议、文档、人员、日期、任务和外部实时信息默认严格校验。

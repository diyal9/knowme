# KnowMe 视觉系统治理契约

本契约收敛视觉语言，不重做产品。现有导航、页面分区、卡片/侧栏/抽屉关系、控件顺序和业务流程均为冻结基线。任何结构调整必须另立 OpenSpec、提供前后对照并由用户明确确认。

## 体验目标

KnowMe 应在五秒内让用户回答三个问题：我在哪里、当前焦点是什么、下一步做什么。界面保持温暖中性底色、炭黑信息骨架与矿物青绿行动色；视觉层级依靠字号、留白、密度和表面关系，而不是增加装饰。

## 六项审查

1. **比例与平衡**：标题、正文、控件和容器形成稳定层级；并列区域先校验视觉重量，不用更多边框补救。
2. **留白与呼吸感**：默认使用标准密度，阅读和创作使用舒展密度，高频工具条使用紧凑密度；同一容器不得混用密度。
3. **节奏与韵律**：重复项共享基线、间距和交互节奏；列表、卡片、步骤和对话形成可预测的纵向行进感。
4. **光影与材质**：阴影只表达层级。页面、面板、卡片、浮层按固定表面层级递进，禁止用随机阴影制造“高级感”。
5. **尺度与人感**：文本最小 12px；常用正文 13–14px；交互目标遵循共享 control token；长文控制阅读宽度。
6. **情绪与叙事**：工作台克制、协作区专注、审阅区清晰、设置区安静。强调色只指向行动、选中或明确状态。

## 令牌语法

- 字体角色：`--type-page`、`--type-section`、`--type-card`、`--type-body`、`--type-support`、`--type-meta`。
- 间距：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px，对应 `--space-1` 至 `--space-9`。
- 密度：`relaxed` 用于阅读/创作，`standard` 用于页面主体，`compact` 用于工具条和高频控制区。
- 圆角：5 / 7 / 10 / 12px，加 pill 与 circle；外层半径不得小于其内层。
- 阴影：rest、raised、overlay 三层；普通卡片默认无阴影或使用 rest，浮层才可使用 overlay。
- 表面：app → page → panel/card → overlay。相邻层优先用底色和细边界区分。

## 迁移规则

1. 先记录截图和审计数字，再迁移单一体验域。
2. 只替换样式值与层叠来源，不改变 DOM/React 结构、路由、状态、IPC、数据或行为。
3. 每次迁移应降低至少一项视觉熵预算，且不得提高其他预算。
4. 组件专属几何值可以暂留，但字体、常用间距、圆角和阴影必须优先消费共享令牌。
5. `!important` 只允许保留有注释的第三方覆盖或不可规避的兼容场景。
6. CSS 拆文件仅在计算样式、截图和行为测试均等价后进行。

## 完成标准

- 硬编码字体像素值不超过 50 处，至少 90% 文本使用语义字体角色或字号/字重令牌。
- 常用圆角收敛为 6 种；非令牌阴影不超过 10 种。
- 至少 85% 常用间距声明消费 `--space-*`；`!important` 不超过 30 处且逐项说明。
- 核心截图矩阵覆盖工作台、专家协作、工作流、管线、能力中心、设置及窄窗口。
- 功能回归为零、结构差异为零；视觉差异均可对应本契约中的规则。

执行 `npm run visual:audit` 查看当前状态；执行 `npm run visual:check` 校验不回退预算。

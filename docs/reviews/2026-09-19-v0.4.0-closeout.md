# KnowMe v0.4.0 封版评估

日期：2026-09-19

分支：`develop`
结论：**允许作为结构与平台基线封版并推送；不允许宣称全部生产专家已经完成专业资格认证。**

## 封版判断

v0.4.0 已经形成可继续演进的产品骨架：本地优先的数据边界、项目与知识上下文、我的 KnowMe、专家协作、工作流、管线服务和能力中心有了相对清晰的运行时分层。下一阶段不应继续横向增加概念和入口，而应集中改善产品心智、关键任务体验与 Agent 专业交付质量。

本次封版按两种口径分别判断：

- **工程基线：通过。** `npm run check` 全部通过；后端/集成测试、lint、91 个渲染测试文件的 704 项用例和渲染层类型检查均成功。
- **全量生产承诺：不通过。** `npm run audit:production-capabilities` 返回 `packageReady=true`，但 `productionReady=false`、`executionReady=false`、`qualificationGatePassed=false`。7 个生产专家均缺少完整、与当前配置绑定的专业资格报告，部分条件路线仍缺真实执行证据。

因此，本版适合作为下一阶段的稳定开发起点，也可以用于受控试用；对外描述必须区分“能力包可加载”和“专家已通过真实任务认证”。

## 本轮封版处理

- 修复多图成果从第二张原图入口打开时，预览对话框仍显示第一张标题的问题；定向回归 80/80 通过。
- 移除 3 个全仓零引用的废弃兼容导出：`CONNECTORS`、`compactDaemonCardBrief`、`COMPILE_AS_AGENT`。
- 保留仍承担旧任务、旧配置或历史数据迁移职责的兼容层，不做激进删除。
- 将 `.tmp*`、Playwright 本地状态、QA/qualification 运行用户数据、会议逐字稿等本机产物排除出版本控制，避免提交缓存、会话或连接器配置。

## 残余风险与流程债务

1. **专业资格证据不足。** 生产名册为 7 个专家，但当前审计未加载完整 qualification report；办公室伙伴、产品经理、研究分析师的部分条件路线缺少真实运行证据。
2. **OpenSpec 过载。** 当前有 19 个活跃 change，高于健康检查建议的 12 个；`establish-project-work-context`、`fix-agent-display-contracts`、`harden-expert-plan-confirmation`、`specialize-web-development-expert` 仍缺部分 QA、验收或评审工件。
3. **大文件继续增长。** 6 个 TypeScript/测试文件超过 1200 行建议线，其中 `ExpertTaskRoom.tsx`、`expert-task-runtime.ts` 与 `phases-model-tool.ts` 是后续变更的高冲突区，但尚未触发 2000 行硬顶。
4. **循环依赖仍存在。** GitNexus 检出 5 个循环组件，其中产品端包括 `store-types.ts ↔ store-link-preview.ts` 与 `api.ts ↔ api-extended.ts`；本次不扩大封版范围处理。
5. **当前差异规模大。** GitNexus 对未提交差异给出 CRITICAL 范围评级，原因是 389 个已跟踪文件、871 个符号和 183 个流程受影响。提交后应刷新索引并在 v0.5.0 开始前建立更小的纵向 change。

## Go / No-Go

- **GO**：提交并推送 v0.4.0 当前结构基线；进入 v0.5.0 规划与小步实现。
- **NO-GO**：发布“全部专家生产可用”“全路线已验收”之类承诺；在没有 qualification report 的情况下提升专家就绪状态。
- **下一步**：先收敛 19 个活跃 OpenSpec change，再按产品属性、体验闭环、Agent 专业度三个版本主题推进，见 [v0.5.0 版本计划](../v0.5.0-plan.md)。

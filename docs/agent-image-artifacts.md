# 图片产物与可核验元数据

通用图片预览由 `ArtifactPreview` 渲染；专家、工具或普通对话不应自行拼接另一套图片卡片。图片独立展示、保持比例、点击查看整图。验收状态和修改操作留在对话区域，修改意见仍使用主输入框。

## 已保存图片的事实回执

生成适配器先下载（如需要）、完整解码校验、保存原字节，再返回 `artifactRefs`。元数据放在 `artifact.meta.image`，因此可以经过通用 artifact 归一化、专家任务晋升和会话保存。`receipt.images` 用 `artifactId` 关联同一份事实。现有 artifact ID、路径与 `receipt.effects` 不变。

```json
{
  "protocol": "knowme.image-metadata/v1",
  "source": "decoded-file",
  "width": 1088,
  "height": 1440,
  "frames": 1,
  "mimeType": "image/png",
  "byteLength": 1772980,
  "sha256": "b35a1e161e1cbf3d2c666c9abeaaba726156ba1d408135ddbedd2848f9b30129"
}
```

- `width` / `height`：完整解码校验后的显示画布像素；考虑 EXIF 方向，动图使用逐帧逻辑画布，不使用多帧叠加高度。
- `frames`：图片帧数；不是候选图数量。
- `byteLength` / `sha256`：保存的原文件字节大小和完整摘要。测量不会隐式缩放、裁剪、旋转或重新编码文件。
- `mimeType`：校验后的实际格式，不复制模型或服务声称的格式。

工具正文和媒体观察会提供上述数值，即使当前模型不支持视觉输入，也能比较请求尺寸与实际尺寸。请求参数与服务原始说明不是成品事实；服务说明单独标记为未核验。旧产物没有该字段时不推定尺寸，也不伪造或追填历史校验回执。

## 能证明什么

这个数据协议不是权限令牌，也不是专家验收结论。正常生成链的事实来源是主机对保存字节的校验，不是 `source` 标签本身。文件后来被外部改写时，旧回执不能证明新字节仍相同。

尺寸和格式回执不能证明主体、材质、构图、文字、保留条件或用户满意度。专家应依据实际视觉输入判断这些项目；没有视觉输入时说明未检查。工具返回成功不等于达标，尺寸不符也不授权专家额外付费重试或悄悄改图。

新增适配器应复用相同的校验、回执和预览契约，而不是根据专家 ID 添加展示或放行分支。

## 本轮附件的参考编辑引用

用户本轮交给模型的图片附件，由共享上下文构造器按原字节生成 `attachment:image_<完整SHA256>`。引用以数据字段紧邻对应视觉输入提供，文件名只是显示信息。参考编辑解析器使用同一份本轮附件集解析引用，不按专家 ID 分支，也不把可见图片误当成只能观看、不能编辑的材料。

引用不是全局文件访问令牌：只匹配本次实际提供的附件，不能凭文件名、任意路径、另一会话的引用或被截去的第 4 张图片扩大读取范围。当前最多处理该附件集中的 3 张图片；上下文草稿显式为空时不得退回旧 payload 附件。标准图片 data URL 要通过大小和规范 base64 检查，但字节摘要本身不证明它是可解码图片。附件引用仅确认本轮可引用字节，当前不保证参考附件在发送前已完成本地像素解码；生成输出仍需完整解码并保存后才能产生图片成果与事实回执。

专家材料快照能恢复本轮附件；这不意味着普通聊天所有历史图片自动获得新一轮的编辑权限。历史图片应通过平台明确的材料/产物引用再次提供。

## 调用未发出与调用结果未知

空提示词、参考图解析失败等宿主本地前置失败，发生在生成服务调用之前，应作为“尚未发出”处理，不伪装成图片成果，也不误报为可能已经扣费的未知操作。

该判断使用进程内可信失败对象身份，不信任服务或模型自己返回的 `executionStarted: false`。一旦已调用生成服务，超时、断连、下载或保存失败不能借此前置标记恢复自动重试权限；未知副作用仍须按原有核对/重试策略处理。

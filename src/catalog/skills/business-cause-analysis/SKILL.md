# 业务异常归因

## 先分清三层证据

1. **材料事实**：只包含用户或真实来源明确提供的事件、样本、版本覆盖、人群和数值。逐项追问自己“在哪一条材料中？”；找不到的不是事实。
2. **算术解释**：总量、结构、组内变化可复算；这回答数值如何组成，不回答哪个动作造成了变化。
3. **业务假设**：动作如何影响曝光、行为及结果，列出支持、反证、尚缺的识别条件。没有证据时用“可能/需验证”，不要把假设偷偷带进最终建议的前提。

尤其注意：只知道改版日期，不代表知道哪些人用了新版；只有按周汇总，不代表知道日内先后；一个历史流量点不是市场容量/扩量上限。没有成本与供给曲线，不能由高转化率推出增投收益。这些缺口不能由行业常识补写成该项目事实。

## 根据设计选择结论强度

- **两期前后对比/渠道对比**：列出会改变决策的竞争性解释，例如人群结构、版本暴露、投放策略或采集口径。只比较与已知事实相容的假设，不凑清单。混杂无法区分时保持未识别；组内变好也不能证明改版无害。
- **随机同期实验**：在分组、观察窗口及测量有效的前提下，允许对随机入组人群、当前渠道和已测目标作出有依据的选择。未测长期收益不应阻止已达成短期目标的范围内决策，也不能据此声称所有渠道有效或更盈利。
- **观察到的新旧版本用户**：并非天然可比；选择进入版本的人群、渠道、时间和设备差异可能造成偏差。没有识别条件，不能因为两组同时存在就叫它可信对照。

对关键主张写一个最小证据链：已知输入 → 可复算变化 → 可支持的判断 → 尚不能支持的外推。反证检查包括“若另一种合理机制成立，这份数据是否也会出现？”；能出现就不声称唯一原因。

## 把判断变成受约束动作

直接回答用户要作出的决策，并区分现在可做、验证后再做、目前不应做。建议说明适用人群、成本/权限、可逆性和观测指标；没有授权不执行投放、部署或发送。

停止条件优先采用用户预先设定的业务护栏。需要新增阈值、灰度比例或时间窗时，明确这是待确认的建议，并解释样本成熟度、最小可检测变化或成本依据；不要把任意百分比包装成统计标准。样本量与流量未知时不承诺一周就能分辨效果；未成熟D7数据不能用于当天回滚。

## 自检与修改轮

把结论中的每个“因为/证明/唯一/已经/必然”反查证据；删去无依据的确定词还不够，依赖该前提的建议也要重写。不要一边声明不能归因，一边又声称某渠道是唯一受到版本影响的组。

收到用户纠正后明确撤回事实错误和依赖它的判断，重新评价各候选原因，不只是替换数字。反证、计算或范围检查未通过时，将不确定部分直说；仍可交付已知事实和最小验证路径，不制造空报告或虚构完成。

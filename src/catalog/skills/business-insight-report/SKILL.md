# 商业洞察报告

## 先确定要支持什么决策

从用户问题中提取决策、可选动作和不能改变的约束。已有数据可以分析就先分析，不为填齐模板重复澄清。只追问会改变决策的关键缺口；缺少成本时可以判断转化变化，却不能判断哪个渠道更赚钱。

这是分析与建议，不是执行授权。不要自动调预算、发布文档或发送消息。默认在对话里交付；用户明确需要文件时再生成文件，不能把错误提示包装成成果。

## 工作方法

### 1. 建立可复核的证据账

对会影响结论的数据记录来源（用户表格的行列、文件/版本、实际工具回执）、时间窗、单位、分子/分母、去重口径和已知缺失。已有指标定义或历史决策材料可通过当前可用知识工具读取并标明版本；没有读取就不能声称已核对。

先核对合计、重复/漏行、零分母、样本成熟度及指标定义变化。冲突来源并列保留，说明各自能回答什么；不挑一个支持预设结论的来源，也不把两个不同分母的“转化率”直接比较。读取失败时报告失败和影响，仍可分析用户已提供的数据。

### 2. 计算变化，再检验总体是否误导

- 给出当前值、基线、绝对变化；比例的差用“百分点”，相对变化用 `(当前值-基线)/基线`。基线为零时不报有限增长百分比。
- 总体率用分子合计除以分母合计，不能直接平均各组百分比。检查分组是否互斥且覆盖总体；不满足时不要强行加总。
- 同时有分群和两期数据时，对比组内变化与权重变化。总体下降并不自动说明每组变差。需要量化时可固定一组权重比较两期组内率，再计算换权重的差；说明固定基期还是当期，确认各项之和等于总变化。
- 数量、金额或比率选择适合的拆分，写出可复算的中间量。大表使用可用计算工具；工具不可用时只做可复核的小规模运算或明确未计算部分，不猜测结果。

### 3. 区分算术解释与业务原因

为会改变行动的主要解释列出支持证据、冲突证据和仍缺什么。竞争性解释应来自该案例，例如流量结构、产品变化、归因或采集口径，而不是凑固定数量的通用清单。

分解能说明观察到的变化由哪些量构成，不能证明某动作导致变化。没有对照、随机分配或足够识别条件时，用“与……一致 / 尚不能区分……”而不是“已证明”。不要把“没有发现反证”写成“排除了其他原因”，也不要编造统计显著性、置信区间或收益预测。

### 4. 将建议绑定到证据和可撤回的动作

先区分现在可以做、需要验证后再做、当前不应做的动作。每个重要建议说明依据、成本/权限等限制、验证步骤、观察指标与停止或调整条件。负责人和时间未知时用“建议由……负责 / 建议窗口”，不虚构已分配或已获批。

高风险或不可逆决策需要更强证据。证据不足不等于没有价值：给出范围受限的结论和最小补数/验证路径。没有单位成本、利润和规模上限，就不要由转化率直接推出增投收益；情景估算需明确假设，不能充当实测预测。

### 5. 用户纠正后重新判断

保留未被否定的目标与约束，明确哪些数值/证据已被新输入替换，重算受影响的合计、比较和建议。点明撤回、保留和新提出的结论；不要把旧版错误归因留在摘要里，也不要仅替换几个数字。原有反馈在当前输入中不可见时，诚实说明缺失，不假装记得。

## 对话交付

先直接回答用户的决策问题，再用最少必要篇幅给出：

1. 支持答案的关键数值与来源，通常一张小表足够。
2. 已知解释、尚未验证的原因与会改变判断的缺口。
3. 有条件的行动建议及验证/停止条件。

篇幅随问题复杂度调整，不要求每次六个章节。不能只写“建议进一步分析”；要说分析哪份数据、验证什么、什么结果会改变建议。交付前检查摘要与正文是否一致、数字能否复算、建议是否越过证据边界，以及是否真正回答了用户问题。

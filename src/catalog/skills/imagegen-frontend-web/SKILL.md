# 网页视觉参考设计

把用户的品牌与页面目标转成可实现、可核验的分区视觉方案。视觉创意服务于页面信息层级和转化目标，不把随机情绪图当成网站设计。

## 先判断本轮交付

1. 识别用户要的是：
   - **文字参考方案**：构图、配色、排版、素材方向与响应式实现说明；
   - **真实分区参考图**：必须有可用且已授权的生图工具；
   - **页面代码**：本技能只负责视觉方向，具体实现交给前端实现能力。
2. 若用户明确说“不生成图片”“只要文字方案”或当前没有生图工具，直接交付文字方案。明确写出“本轮未真实生成图片”，不要虚构图片、文件、链接或工具回执。
3. 若用户要求真实图片但工具不可用，仍可交付清晰的文字方案和待执行提示词，但必须把它们标为方案，不得冒充生成成果。

## 真实生图的硬规则

- 每个页面分区对应一张独立横向参考图：3 个分区就是 3 张图，不能合成一张长图或拼贴图。
- 每张图单独调用一次生图工具，并按 `Section 1/N`、`Section 2/N` 依次交付。
- 工具返回成功文字、Prompt、参数或 URL 都不能替代真实可读取图片。
- 工具未返回图片时停止在事实边界，说明缺少成果并给出可重试步骤，不自动重复付费调用。
- 用户没有指定分区数量时，落地页默认规划 6 个分区；完整网站模板默认 8 个分区。文字方案可按用户明确的较少分区交付。

## 设计流程

### 1. 固定 brief

先提取并保持一致：

- 品牌与受众；
- 页面目标与主 CTA；
- 必须出现的内容和禁用元素；
- 风格关键词；
- 桌面端与移动端约束；
- 本轮是方案、图片还是实现。

信息足以完成任务时直接执行，不重复追问。缺少非关键细节时做保守假设并显式说明。

### 2. 给每个分区一个职责

每个分区只承担一个主要任务，例如：

- Hero：建立价值主张并提供主 CTA；
- 信任条：提供品牌、数据或客户证据；
- 产品功能：解释核心能力与使用方式；
- 使用流程：降低理解和上手成本；
- 场景/案例：把能力绑定到具体结果；
- CTA：收束价值并提供明确下一步。

避免多个分区重复同一种标题、卡片和构图。

### 3. 选择统一视觉系统

统一定义：

- 主色、辅助色、中性色和对比规则；
- 标题、正文、标签和按钮的字阶与字重；
- 圆角、边框、阴影、纹理和图像处理方式；
- 桌面端最大内容宽度、栅格和间距节奏；
- 图片风格与品牌语气。

用户 brief 优先于默认风格。不要自动套用紫蓝霓虹、漂浮光球、泛滥玻璃拟态或密集 dashboard 卡片。

### 4. 让构图有变化但仍可实现

默认左文右图过于常见，只在它确实最合适时使用。一个页面至少使用三种构图锚点，可从以下方式选择：

- 居中宣言；
- 文案叠在全幅图的安全区；
- 左下或右下 CTA 聚合；
- 左侧三分之一说明 + 右侧三分之二维度图；
- 反向分栏；
- 错位编辑式排版；
- 图像作为画布；
- 极简纵向堆叠。

构图变化不能牺牲阅读顺序、CTA 可见性和组件可编码性。

## 风格映射

- **极简 / Swiss / typography-only**：留白大、纯色表面、少量色块、清晰网格，不强加全幅图片。
- **编辑 / 杂志 / 时尚**：强字阶、错位构图、克制图像处理与不对称节奏。
- **电影感 / 高端 / 大胆**：可用全幅图、调色遮罩和大标题，但必须保证文字对比。
- **SaaS / 产品 / 金融科技**：产品界面清晰、信任证据优先、渐变克制、实现边界明确。
- **创意机构 / 作品集**：可采用海报式、双色块或非对称构图，但保持导航和 CTA 清楚。
- **电商 / 产品页**：商品主导、价格与 CTA 明确，视觉效果不得压过购买决策。

需要更丰富的构图组合、视觉母题和提示词细则时，可按需读取 `references/art-direction-playbook.md`；不要为了普通三至六分区方案一次性加载整份参考。

## 分区方案模板

文字方案对每个分区使用以下结构：

### [分区名]

- **目标**：该分区解决什么用户问题、推动什么动作。
- **桌面构图**：主体位置、文案安全区、CTA、图像或 UI 元素关系。
- **视觉细节**：背景、色彩、字阶、图像风格、层次与留白。
- **移动端**：堆叠顺序、裁切策略、字号与交互变化。
- **实现提示**：适用于 Vue/React 的容器、CSS Grid/Flex、响应式断点和可访问性注意点。
- **成果状态**：写清本轮是“文字方案”还是“已生成并核验的图片”。

最后补充一段全局规范：统一色板、字体层级、栅格、间距、按钮、图片处理和 CTA 一致性。

## 响应式与实现边界

- 桌面端优先使用 12 列或可解释的网格；移动端改为单列或明确的两层堆叠。
- 说明图片在窄屏的裁切焦点，避免仅写“自适应”。
- 标题使用 `clamp()` 或明确断点范围，保持最小可读字号。
- CTA 在移动端不得被背景图、浮层或折叠内容遮挡。
- Vue/React 实现建议使用语义化分区组件和数据驱动内容，视觉参考不是可运行代码。
- 交互建议应覆盖键盘焦点、对比度、减少动态效果偏好与触控目标尺寸。

## 交付前检查

- 分区数量和用户要求一致；
- 每区职责、构图和 CTA 不重复；
- 品牌色、字体、圆角和图像风格一致；
- 桌面与移动端都给出具体实现边界；
- 方案、真实图片和代码成果三者没有混淆；
- 没有生图工具时明确未生图；
- 真实生图时，每区都有独立、可读取的图片证据。

# 盘古真实生图与证据验收

本 Skill 负责一次受授权的真实生成操作，并把工具回执、媒体字节和版本关系交给 KnowMe 通用成果合同。生成服务返回成功只是执行证据，不等于画面符合 Brief。

## 1. 执行前门禁

必须同时满足：用户已确认最终 Brief；当前任务工具面包含 `generate_image`；Prompt 冲突检查已通过；编辑任务有可读取的基图引用；本次数量、模型与付费范围没有超出确认。

模型未指定且确有必要时调用一次 `list_paint_models`。已有明确可用模型时不重复查询；模型目录查询不能替代生成，也不能作为成果。

## 2. 组装调用

向 `generate_image` 传递完整 prompt、negative、`aspect_ratio`、`n`、quality/model 和经授权的 `reference_images`。探索任务默认 `n=1`；只有用户明确要求多版时才设置 2–4，不为了“提高成功率”擅自增加付费调用。

编辑任务只把指定基图作为 base reference，风格参考保持独立角色。引用解析失败时在提供方请求之前停止，说明哪个引用不可用；禁止退化为纯文生图。

## 3. 识别真实成功

只有同时存在以下证据才可进入验收：

- 本轮 `generate_image` 调用回执明确成功。
- 至少一个真实 `image artifact` 已保存并属于当前任务。
- 媒体可由 `decoded-file` 回执解码，得到实际格式、宽高和必要的动画画布信息。

请求参数、Prompt 回显、URL 字符串、模型文字描述、任务 ID 或“待验收”状态都不能替代图片 artifact。没有图片时不得创建空白卡片、文档占位或用 Prompt 冒充成果。

## 4. 区分三类事实

- 请求事实：希望的比例、像素、数量、格式和视觉要求。
- 文件事实：decoded-file 提供的实际格式、像素、帧/画布和字节身份。
- 视觉事实：通过实际可见图像判断的主体、构图、色彩、文字、材质和保留项。

只拿到文件元数据时可以报告实际尺寸，不能声称看过构图或文字。只有实际图像可见时才能判断视觉符合度；看不到时明确“尚未做画面检查”。

## 5. 视觉与技术验收

按 Brief 检查主体身份/数量、信息层级、构图与裁切、缩略图识别、比例和安全区、色彩/对比度、光线/材质、文字/品牌、禁用项。请求像素与 decoded-file 不一致时报告实际值和偏差，不把近似比例写成精确命中。

编辑任务分别检查变更集和保留集：目标变化是否发生、未授权对象是否保持。合理局部光影变化可以接受，但形状、颜色、位置或相邻对象改变必须如实列出，不能用“整体更协调”掩盖越界修改。

## 6. 失败与未知副作用

在宿主确认请求尚未发出时，可修正本地参数或引用后由用户再次执行。请求发出后超时、断连或响应丢失属于副作用未知：可能已经计费或生成，禁止自动重试，也禁止并行发起第二次调用。

提供方明确失败且宿主能确认没有成功 artifact 时，说明失败工具、阶段和下一步；保留 Brief、Prompt 与已确认范围。工具返回成功但没有图片，同样不得完成任务，应进入可恢复等待状态。

不要把所有失败都归因于“缺少 Skill”。区分连接器未配置、工具未发现、权限拒绝、引用不可读、提供方失败、响应未知和媒体保存/解码失败，并给出与该状态匹配的恢复动作。

## 7. 版本与修改

每次真实返回图建立新版本，保留旧版 artifact、生成回执和基图关系。修改轮基于用户指定或最近版本，不覆盖旧图，不把修改意见丢失在新 Prompt 中。

用户要求修改后重新整理变更集/保留集、重新确认必要冲突，再进行一次新调用。未要求新增数量或多版时仍保持 `n=1`。接受成果只改变验收状态，不触发额外生成。

## 8. 对话交付

图片单独作为成果预览；状态、偏差和下一步放在正常对话中。默认用两三句话说明生成数量、实际尺寸/格式（有 decoded-file 证据时）、视觉核查结论与关键偏差。参数长表、Prompt 全文和自查清单仅在用户要求时展开。

不生成额外文档，不把“服务返回结果”写成“用户已验收”，不声称已发布、已商用或已完成版权检查。

# 软件变更与验证

## 先判授权，再建立契约

确定本次是实现、只读诊断还是静态提案。只在用户授权与当前权限的交集内读取、修改和运行；禁工具包括内部计划工具。材料充分时直接分析，不为静态委托索取真实仓库。实现获准但缺执行能力时交付补丁提案及阻碍，不称已修改。方法名称不是可调用函数，Skill不授予工具或发布权限。

列出目标、非目标、验收条件及已知接口的参数、返回值、错误、状态和副作用。按源码或材料位置绑定证据，标明未知、假设和建议；已给契约直接使用，不臆造API或把已知条件重新问成缺口。授权读取仓库时先检查规则、现有约定与用户未提交改动。仅追踪影响结论的调用方、数据流和依赖，不以全面重写代替定位。

题面给出输入上限、数据规模、延迟、内存或吞吐约束时，必须把它们转换为可检查的资源预算：写明核心路径的时间复杂度、额外空间复杂度及最坏情况，解释为什么与已知上限相容；需要真实设备或数据才能判断的绝对耗时、容量和吞吐只列为待测指标，不凭经验保证。即使代码功能输出正确，漏掉明确规模约束也属于未完成交付。

## 用完整时序解释缺陷

选最小可复现输入，明确初态与必须保持的不变量，例如数量守恒、租户隔离、同一操作不重复生效、失败不留下半成状态。按参与者列读值、判断、写入、提交、返回及故障发生点，写到调用方结果和持久状态，而非止于中间一步。区分请求总量、已确认业务效果与实际存储值；比较预期与实际，说明违反哪条契约。条件性反例须写成立前提，不能把假设性风险说成当前实现已发生的缺陷。

## 选最小完整修正

把每个根因映射到必要改动与回归面，保持公开接口、错误语义和现有约定；说明更小替代为何仍有反例。并发问题分别检查进程内、跨进程及数据库边界：局部锁不自动跨进程，请求唯一键不保护其他请求共享的数据，多步单操作原子不等于整体原子。使用已有事务或并发控制契约；可串行化保证结果等价，不证明物理执行无穿插。能力缺失时列所需前提或待选方案，不杜撰现成接口。

涉及幂等时确定作用域、请求身份、参数一致性及首次结果保存，覆盖同内容重放、异内容冲突和隔离；不能把当前状态重算值当原结果。超时或取消不证明副作用未发生：区分尚未执行、已确认完成与结果未知，检查提交点及回执。未知状态先按已有查询/幂等契约核对，不能换身份盲重做；只在安全且获准时有限重试。跨系统副作用不冒充本地事务能回滚，必要的补偿、对账和恢复方案明确为建议。

## 让验证能判定成败

为关键不变量给“初态—操作/故障点—返回或错误—最终状态—通过判据”，检查错误实现是否也能通过。按风险选择正常、边界、无效输入、同键/不同键并发、隔离、部分写入失败及提交后响应丢失等场景，不机械套全表。用屏障、可控队列、虚拟时钟或显式调度保证竞态发生，不靠sleep碰运气；调度遵守真实契约，勿让串行事务互等而制造夹具死锁。故障注入明确在变更前后、提交前后哪个点，既断言错误透传，也断言数据、账本和副作用状态；重放检查原结果与执行次数。

授权实现时先获得能证明缺陷的失败测试，再最小修复并运行风险相称的定向回归；无执行授权则交付同样可落实的设计，标明未运行。已存在测试只按实际读到的范围陈述，未知覆盖不猜测；通过记录关联代码版本、环境、命令、退出结果及范围，隔离夹具通过不等于真实系统资格通过。

## 交付前复核

分别说明诊断/变更或提案、验证结果或设计、剩余风险与下一步。检查代码、注释、示例和结论是否一致，失败与不确定状态是否被隐藏，工具使用声明是否与本轮记录一致。先保证关键时序、完整代码和判据，再删重复背景以遵守用户篇幅；不以计划打勾、模型正常结束或平台verified替代专业验收。发布、迁移及真实外部副作用另按授权验证，不扩大本轮完成声明。

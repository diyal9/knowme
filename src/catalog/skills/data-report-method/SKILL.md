# 数据报告叙事与一致性核验

## 明确编辑边界

本方法编辑已经完成的分析，不把缺失计算补成事实。先确认读者、周期、要支持的决策和可引用的分析结果；原始结果缺关键口径时标记待确认，而不是自行换分母、补样本或声明统计显著性。

若用户实际要求重新计算，应说明当前是报告整理任务，并请求已验证结果或转交数据分析能力。材料中的结论彼此冲突时保留冲突及来源。

## 建立指标账本

对每个进入正文的数字在内部核对：指标名称、定义、单位、时间范围、群体范围、基线、当前值、来源和限制。正文不必展示整张账本，但必须让读者能判断比较是否成立。

- 百分比变化同时区分“百分点”和“相对变化”，不能互换。
- 样本、渠道、平台、税费、退款或统计窗口变化时，不直接做同比环比结论。
- 没有显著性检验就写“未检验”，不能用“显著提升”代替“观察到上升”。
- 缺失数据、异常值和口径调整不得只藏在附录。

## 组织决策叙事

按“结论—证据—业务影响—行动”建立层级。管理摘要先回答发生了什么、证据有多强、影响什么决策和下一步是什么；它必须保留会改变判断的范围与限制。

正文按问题而非数据源堆叠：每节先给受证据支持的标题结论，再给数字、图表或分析依据，随后解释限制和竞争性解释。相关性不能写成因果；建议要说明依据、风险和可观察的判断指标。

## 图文与全篇一致性

每张图或表都应有一个明确的信息任务，并在同一阅读单元注明指标口径、时间、范围和来源。图题、正文、管理摘要与行动建议中的数字和状态必须一致；装饰性图表不能替代证据。

若图表无法读取，只描述已提供的文字结论并标出图表核对缺口，不能臆测趋势、颜色或数据点。

## 交付方式

默认输出一个完整答案，依次包含管理摘要、必要正文、来源与限制、行动建议。按任务复杂度缩放结构，单一数字追问不强制套用长报告模板。

行动只建立在已验证结果上：明确建议对象、预期影响、成本或依赖、验证指标；证据不足时给可逆验证动作，不给确定性承诺。

交付前核对数字、单位、时间、分母、页面间结论和图文引用。发现不一致时先修正或显式列为待确认，不为了让故事流畅而选择性隐藏。

# Why

Cursor 仓库导入只注册技能、专家和 stdio MCP，项目自带工作流被遗漏；用户无法把一条外部生产管线完整带入 KnowMe，也无法在专家对话内完成导入闭环。

# What Changes

- Cursor 仓库扫描增加 `.cursor/workflows`，并把外部 Agent 引用映射为实际导入专家 ID。
- 新增一级资产“智能体运维专员”，将只读预览、显式确认、防陈旧导入工具和 SOP 内聚到 Expert，不发布同名独立 Skill。
- 能力中心预检展示专家、技能、连接器和工作流数量。
- 以 th-art 的 PSD → ArtBundle 管线完成真实目录扫描和临时用户目录注册验证。
- 为受支持的外部工作流增加运行配方：把确定性步骤升级为受控工具节点，启动前验证输入、依赖和写入边界。
- th-art PSD → ArtBundle 配方只允许运行仓库内固定 Node 脚本，并为 PSD 预读、切图出包、Creator 导入与结构验收保留可追溯回执。
- 已导入的旧版工作流在加载/启动时可获得运行时升级，无需卸载后重新导入。

# Impact

旧仓库导入保持兼容；无工作流存储依赖时仅工作流注册失败，能力注册结果仍会如实报告。deprecated/hidden 工作流不会进入工作流库。外部执行不会导入项目中的明文密钥，也不接受任意命令字符串；Creator MCP 等带认证连接器仍由用户在 KnowMe 中显式配置。

# 收敛渲染层视觉系统

## 问题

KnowMe 的整体 UI 结构与功能路径可继续使用，但 24 个 CSS 文件已经积累大量硬编码字体、间距、圆角、阴影和 `!important`。颜色系统相对统一，几何与节奏却在不同体验域中各自生长，导致局部优化难以稳定复用，后续改动容易产生层叠回归。

## 目标用户

- 需要长时间阅读、协作、审阅与执行任务的 KnowMe 用户。
- 需要在不破坏既有功能的前提下持续维护前端体验的产品、开发与测试人员。

## 体验与商业价值

保持用户已经熟悉的页面结构，同时让字号、密度、层级和反馈更一致，降低认知负担。工程侧用可量化预算阻止视觉债务继续增长，使新功能更快达到一致品质，减少发行前逐页修补成本。

## 验收标准

- 建立可重复运行的视觉熵审计与非回退预算，并纳入 lint。
- 发布字体、间距、密度、圆角和阴影的共享契约及令牌。
- 能力中心卡片作为首个样板，保持现有结构和行为，仅收敛文字与密度。
- 后续按体验域迁移，每批次提供截图、计算样式和行为回归证据。
- 最终达到字体、间距、圆角、阴影及 `!important` 的量化目标。

## 非目标（Non-goals）

- 不更换导航、信息架构、页面布局模型或组件顺序。
- 不修改 React 组件层级、路由、状态、IPC、数据模型和业务功能。
- 不引入新 UI 框架、字体依赖或动画库。
- 不为减少 CSS 文件数而机械合并文件，也不一次性重写全部样式。

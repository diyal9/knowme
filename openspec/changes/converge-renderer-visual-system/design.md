# 设计

## 决策

采用“冻结结构、收敛视觉、逐域迁移”的渐进方案。`brand-tokens.css` 继续独占原始颜色，`tokens.css` 负责跨入口的字体、间距、密度、尺度、圆角、阴影和动效语义；feature CSS 只消费令牌并保留必要的专属几何值。

视觉治理不以 CSS 文件数量为目标。文件仍按体验域归属，先降低值域和层叠熵，再在等价证据充分时拆分过大的责任域。

## 进程与边界

- Electron 主进程、preload、IPC 和产品数据不变。
- React DOM 结构、路由、状态与事件处理不变。
- 渲染进程只新增静态令牌、CSS 消费规则、只读审计脚本和契约测试。
- 审计脚本扫描源码，不启动 Electron、不访问网络、不写用户数据，启动性能与运行时内存不受影响。

## 令牌层级

- 字体：6 个语义角色，组件可用共享字号/字重令牌做有限组合。
- 间距：4px 基础节奏，提供 4–48px 九级刻度与三种密度别名。
- 圆角：sm / control / md / lg / panel / pill / circle；常用可见值收敛为 6 类。
- 阴影：rest / raised / overlay。兼容别名保持旧样式计算结果不变。
- 表面：app → page → panel/card → overlay，阴影强度随层级单向增加。

## 审计与预算

`scripts/audit-renderer-visual-system.js` 将 `tokens.css` 与 `brand-tokens.css` 视为值定义区，其余 CSS 视为消费者。脚本统计硬编码字体、间距、圆角、阴影、`!important` 与令牌使用情况。初始 ceiling 固定为实测基线，CI 只允许持平或下降；每完成一个体验域即下调预算，禁止为通过检查而上调 ceiling。

## 迁移顺序

1. 基线、令牌与非回退门禁。
2. 能力中心样板：卡片文字与密度，不改结构/功能。
3. 专家协作 → 工作流 → 管线与审阅的纵向主旅程。
4. 设置、知识库、文件与辅助入口。
5. 在计算样式与截图等价后清理层叠和拆分超大文件。

## 风险控制

- 每批只迁移一个体验域，失败可通过单文件回退。
- 核心交互测试保证功能差异为零；CSS 契约与截图保证结构及视觉差异可解释。
- 当前工作区存在大量未提交改动，本 change 仅新增独立文件并对共享文件做最小增量，不清理或覆盖其他变更。

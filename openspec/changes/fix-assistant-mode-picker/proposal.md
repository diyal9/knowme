## Why

目标用户：使用 KnowMe 办公助理的日常办公用户。

助手头部的加号按钮当前是一条坏掉的入口。`relocate-agent-authoring-to-capability-hub` 把「切换内置模式」和「启动专家包」合并成同一条路径后，菜单里的每一项都会被当作磁盘上的专家包去加载：

- 四个内置模式（通用 / 知识管家 / 写作 / 编程）在 `capabilities/experts/` 下并不存在对应目录，点击后主进程 `loadExpert` 返回 `not_found`，用户只看到一条红色 toast「专家不存在: steward」，连模式都切不了。
- 菜单同时把已安装专家目录合并进来，包含 QA 遗留的副本（`qa-copy-*`、`th-*`），原本 4 项的模式列表膨胀成十几项，用户无法分辨哪些是模式、哪些是专家。

专家已经在能力中心（我的专家）里有完整的浏览、说明与「开始使用」入口，助手头部这个加号不需要再承担专家分发职责。它应该回到唯一职责：以某个内置模式开一个新会话。

## What Changes

- 助手头部加号菜单只列出内置助手模式，不再合并已安装专家目录。
- 选择内置模式时直接按模式新建会话，不再走专家包加载路径，因此不会再出现「专家不存在」错误。
- 保留 `startExpertChat` 作为能力中心启动专家会话的路径；并让它在收到内置模式 id 时退回模式新建，避免同类错误从其他入口复现。
- 更新既有契约测试，使其断言「加号菜单 = 内置模式」这一语义。

验收标准：
- 打开加号菜单只看到 4 个内置模式，且当前模式有选中态。
- 依次点击 4 个模式都能新建对应模式的会话，无任何错误 toast，空状态与输入框提示随模式切换。
- 从能力中心「开始使用」启动专家会话的行为不变。
- `npm test` 与 `npm run lint` 通过。

非目标（Non-goals）：
- 不改能力中心的专家浏览、编辑与启动体验。
- 不清理用户数据目录中 QA 遗留的专家副本（属数据清理，不在本次代码变更范围）。
- 不新增模式，也不改动四个内置模式各自的空状态与快捷任务。

## Capabilities

### Modified Capabilities

- `office-assistant`：「选择我的专家」调整为「选择助手模式」，明确菜单只含内置模式且切换不依赖专家包。

## Impact

- `src/workspace-agent.js`：加号菜单数据源与选择分支。
- `tests/office-assistant-mvp.test.js`：更新为模式语义断言。
- 不涉及 IPC 协议变更、不新增依赖、不改用户数据结构。

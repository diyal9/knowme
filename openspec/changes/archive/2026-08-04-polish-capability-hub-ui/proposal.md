## Why

能力 Hub 已具备专家、技能与 MCP 连接器的完整浏览和管理路径，但当前界面层级弱、卡片尺度偏小、工具条堆叠明显，无法体现 KnowMe“整洁、克制、有设计感”的产品主题。现在统一三类页面的视觉与交互规则，可降低发现和管理能力的认知成本，并增强能力生态作为产品扩展入口的可信度。

## What Changes

- 将专家、技能、MCP 连接器三个 Tab 统一为 KnowMe 暖灰中性色视觉系统。
- 重构顶部标题、搜索、Tab、分类和已安装筛选的信息层级，减少横向拥挤。
- 将精选能力改为具有明确主次关系的横向展示区，将全部能力改为更易扫描的响应式目录卡片。
- 系统化完善卡片状态、悬停/按压/键盘焦点、加载骨架、空状态和错误状态。
- 同步优化详情抽屉和添加能力弹窗，使其与目录页保持一致的版式、间距与控件质感。
- 保留现有数据、IPC、安装管理与深链行为，不增加第三方前端依赖。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `capability-hub`: 更新 Hub 浏览布局的视觉与交互要求，使三类目录具备一致的信息层级、响应式结构和完整 UI 状态。

## Target Users

- 希望为工作伙伴安装专家或技能的普通 KnowMe 用户。
- 需要查看、启停和维护 MCP 连接器的进阶用户。
- 通过本地目录、ZIP、HTTPS 或 Cursor 仓库导入能力的开发者。

## Acceptance Criteria

- 三个 Tab 在 1024×500 及常见桌面窗口尺寸下均无横向溢出，主要操作无需滚动即可识别。
- 标题、搜索、导航、筛选、精选和能力目录具有稳定且一致的视觉层级。
- 能力卡片可快速识别名称、类型/来源、描述、状态与版本，悬停和键盘焦点清晰。
- 加载、空结果、加载错误、详情抽屉和添加能力弹窗均符合统一主题。
- 原有搜索、分类、已安装筛选、Tab 切换、详情打开和添加入口行为保持可用。
- `npm test` 与 `npm run lint` 通过，浏览器控制台无新增错误。

## Non-goals

- 不改变能力 Catalog、安装存储、IPC 或导入安全策略。
- 不新增能力推荐算法、排序逻辑或新的能力类型。
- 不引入 React、Tailwind、动画库或图标依赖。
- 不重做工作台其他页面。

## Impact

- 主要影响 `src/capability-hub.html`、`src/capability-hub.css` 与 `src/capability-hub.js`。
- 可能补充能力 Hub UI 冒烟测试和 OpenSpec 验收证据。
- 无 API、数据结构或依赖变更；商业化上提升能力生态入口的专业感与可发现性，为后续精选能力与连接器分发建立稳定展示框架。

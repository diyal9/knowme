## Context

工作台聊天由渲染进程中的 `workspace-agent.js` 生成 assistant 消息与执行时间线，`workspace.html` 提供原生 CSS。当前等待态先用 `trace.length` 判断是否隐藏独立 `thinking-status`，再单独调用 `renderExecutionTimeline`；这使 plan/run-tree 等非 trace 轨迹存在时仍可能同时渲染时间线与等待浮条。步骤行又分别占用标题、结果入口和固定 56px 耗时列，窄窗口下视觉基线与留白不稳定。

主进程、预加载和 IPC 只负责传递既有事件，本次不修改这些边界。时间线仍在渲染进程内由同一消息状态派生，不新增状态副本。

## Goals / Non-Goals

**Goals:**

- 以实际生成的时间线 HTML 作为“是否已有执行表面”的唯一判断，避免重复状态。
- 使用统一的步骤元信息容器对齐结果入口与耗时，同时保留标题的弹性空间。
- 通过 CSS 层级、间距、状态色和焦点态提升精细度，不改变事件归并与 DOM 原地 patch 机制。
- 保持零依赖、零额外网络请求，并避免引入逐帧 JS 动画或额外常驻节点。

**Non-Goals:**

- 不修改 Agent reducer、事件协议、主进程、预加载或 IPC。
- 不重做 note/editor-pane 的独立聊天时间线。
- 不改变工具结果内容、审批动作或完成态折叠规则。

## Decisions

### 1. 以已渲染时间线而非 trace 数量判断单一状态表面

等待态先计算一次 `timelineHtml`，只要其非空就隐藏独立 `thinking-status` 并应用 `has-execution`。这样 trace、plan checklist 和 run tree 共用同一规则，也避免同一轮重复执行时间线渲染。

备选方案是继续扩大 `hasTrace` 条件，分别检查 trace、plan 和 run tree；该方案会复制 `renderExecutionTimeline` 的存在条件，后续新增轨迹类型时容易再次分叉。

### 2. 将步骤次级信息收敛到元信息容器

步骤行保持“状态标记 / 弹性标题 / 元信息”三列；工具结果入口与步骤耗时放入同一个 `.agent-trace-meta` 容器。宽窗口横向排列，窄窗口允许稳定换行，不再依赖固定 56px 空列。

备选方案是仅调整现有四列宽度；它不能解决有无结果入口时列结构不同和窄窗口挤压问题。

### 3. 视觉强化只使用现有暖灰与低饱和绿色

卡片使用更克制的边框与内层分隔，当前步骤以左侧强调线和浅色表面聚焦，完成步骤降低颜色但保持可读对比。状态图标统一尺寸；可展开结果入口增加 hover、active 和 `:focus-visible` 反馈。

备选方案是引入新图标库或高饱和进度色；这会增加依赖并破坏现有 KnowMe 视觉语言。

### 4. 保留原地 patch 契约

新增包装节点必须具有稳定结构，现有 `reconcileKeyedChildren` 仍只替换变化步骤；总耗时仍由 summary 内的文本节点更新。CSS 动画仅使用 transform/opacity，并继续遵守 reduced-motion。

## Risks / Trade-offs

- [静态字符串测试可能对 CSS 排版过于敏感] → 使用语义类名与关键契约断言，避免断言完整样式串。
- [步骤元信息换行会增加单行高度] → 仅在空间不足时换行，完成步骤仍保持紧凑间距。
- [隐藏重复等待浮条后，空时间线阶段缺少反馈] → 只有实际时间线非空时隐藏；完全无时间线时继续显示原等待状态。
- [样式调整影响长资料入口或多语言文案] → 元信息允许换行，标题列保持 `minmax(0, 1fr)`，并在窄宽度 Electron smoke 中验证。

## Migration Plan

1. 更新工作台渲染标记与样式，不迁移持久化数据。
2. 运行静态契约、全量测试和 lint。
3. 重启 Electron，用受控长检索场景验证运行中、工具结果展开和完成折叠。
4. 如需回滚，仅回退工作台 JS/CSS 与测试；无数据或协议兼容成本。

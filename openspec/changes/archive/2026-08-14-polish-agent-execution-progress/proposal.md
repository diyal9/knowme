## Why

执行进度卡片同时使用标题计时、当前步骤高亮和独立等待浮条表达同一运行状态，导致信息重复、基线松散，削弱 KnowMe 作为专业知识工作台的完成度。需要在不改变 Agent 执行语义的前提下，把运行状态收敛为一个清晰、紧凑且可核验的视觉表面。

## What Changes

- 将有执行轨迹的运行状态统一收敛到执行进度卡片，避免卡片外重复显示当前动作或耗时。
- 重构卡片的标题、步骤、结果入口和耗时对齐关系，突出当前步骤并紧凑弱化已完成步骤。
- 统一状态图标与交互语法，优化资料入口、步骤耗时、展开箭头及窄窗口换行表现。
- 保持完成自动折叠、工具结果按需展开、待审批持续可见及流式原地更新行为不变。
- 补充静态契约测试与 Electron 视觉冒烟证据。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-thinking-timeline`: 增加执行中单一状态表面、精细视觉层级和步骤元信息对齐要求。

## 目标用户

- 在 KnowMe 中执行检索、研究、总结和工具操作，希望快速判断当前进度而不被重复状态干扰的知识工作者。
- 通过步骤、资料来源与耗时判断结果可信度的专业用户。

## 验收标准

- 有执行轨迹时，同一 assistant 消息只显示一个运行状态表面，不再出现独立的“正在组织回答 · Ns”浮条。
- 卡片标题仅承担总状态与总耗时；当前步骤、步骤耗时和资料入口在各自步骤内对齐且不争抢主层级。
- 当前步骤清晰突出，已完成步骤仍可读但视觉弱化；状态图标、箭头和交互反馈一致。
- 窄窗口下标题、资料入口与耗时不重叠，资料入口仍可点击并保持键盘焦点可见。
- 原地增量更新、完成折叠、详情展开状态和 pending_review 行为通过回归测试。

## 非目标（Non-goals）

- 不改变 Agent 事件协议、工具执行顺序、检索结果内容或回答生成策略。
- 不重做聊天消息整体布局，也不调整便签编辑器中的独立聊天时间线。
- 不引入新的 UI 框架、图标库或运行时依赖。

## Impact

- 主要影响 `src/workspace-agent.js` 的执行轨迹标记与 `src/workspace.html` 的时间线样式。
- 更新 `tests/workspace-agent.test.js` 及该 change 下的 Electron 视觉冒烟/证据。
- 无 IPC、存储格式、外部 API 或依赖变更。

## MODIFIED Requirements

### Requirement: 时间线降噪

系统 MUST 在推理过程中突出当前动作，并默认折叠工具原始结果。执行过程 MUST 在运行时默认展开，并在回答完成且无 pending 或 pending_review 步骤时原地折叠；存在待确认步骤时 MUST 保持审批入口可见。有执行轨迹时，系统 MUST 将总状态、总耗时和当前动作收敛在同一个执行进度表面，不得在其外重复显示当前动作或耗时。步骤状态、结果入口与耗时 MUST 具有稳定且不重叠的视觉层级。

#### Scenario: 执行中

- **WHEN** Run 仍有 pending 步骤
- **THEN** 总摘要显示「执行进度」，当前步骤高亮，已完成步骤紧凑弱化
- **AND** 执行过程默认展开

#### Scenario: 有轨迹时只显示一个运行状态表面

- **WHEN** assistant 消息正在运行且已有至少一条执行轨迹
- **THEN** 系统仅在执行进度卡片中显示运行状态与总耗时
- **AND** 卡片外不显示重复的当前动作、加载点或耗时浮条

#### Scenario: 步骤元信息保持清晰层级

- **WHEN** 同一步骤同时包含标题、结果入口和步骤耗时
- **THEN** 标题保持主要阅读层级，结果入口和耗时作为次级元信息对齐展示
- **AND** 窄窗口下三者不得重叠或截断关键操作文案

#### Scenario: 工具结果

- **WHEN** 工具步骤含详细结果
- **THEN** 结果默认折叠，提供「查看结果」类入口

#### Scenario: 完成后

- **WHEN** 回答完成且无 pending 或 pending_review 步骤
- **THEN** 时间线在现有节点上自动收起为「执行过程」
- **AND** 用户可再次手动展开查看

#### Scenario: 完成后仍有待确认步骤

- **WHEN** 回答生成结束但工具步骤仍为 pending_review
- **THEN** 时间线 MUST 保持展开
- **AND** 批准与拒绝入口 MUST 继续可见

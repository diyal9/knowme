## Why

当前工作台把“日常办公 / 软件研发 / 视觉创作”作为用户必须先理解的一级选择，导致用户在真正表达目标前就要做内部分类决策；选错模式还会产生空工作流页面。需要把工作台从“选择模式后找能力”改成“先说目标，再由系统组织执行”。

目标用户：希望借助 KnowMe 完成会议整理、方案写作、软件研发、视觉创作等任务，但不熟悉 Agent、工作模式和工作流内部概念的普通桌面用户。

商业化与体验价值：降低首次启动和首次任务的理解成本，让用户更快获得第一次成功结果；同时保留专业用户的团队、模板和高级筛选能力，为后续能力安装、任务连续使用和专业服务转化提供自然入口。

## What Changes

- **BREAKING** 将工作台头部的模式选择器从默认用户路径移除，头部只保留“开始 / 任务 / 团队”三个用户语言页面。
- 将首页改为目标驱动入口：目标输入框、常用起点、继续工作的任务卡。
- 常用起点使用“整理会议、写一份方案、开发一个功能、制作宣传图”等目标语言；点击后进入既有工作流启动流程，不要求用户先选择模式。
- 将“工作流”降级为开始页中的“浏览全部模板”入口，保留搜索、高级目录和既有启动协议。
- 将最近运行、失败详情和任务恢复集中到“任务”页；保留跨模式历史和旧任务兼容。
- 保留底层 `activeModeId`、Agent 绑定和工作流 `workModes` 元数据，用于推荐、排序和高级筛选，不再默认硬性阻断普通用户。
- 为原有模式选择和团队绑定保留兼容入口，避免已有用户数据和执行协议迁移。

验收标准：

- 新用户无需理解“工作模式 / Agent / 工作流”，30 秒内可以从首页启动一个目标。
- 首页首屏可直接输入目标或点击常用起点，不出现“请选择工作模式”。
- 任意模式元数据缺失时，目标入口仍可用，不因模式过滤显示空白首页。
- 任务页能够查看进行中、失败和历史任务，失败任务仍可打开详情。
- 高级用户仍可进入团队、浏览全部模板和模式筛选，不破坏原有启动与持久化。
- 默认窗口和窄窗口下头部、目标输入和起点卡片无横向溢出。

非目标（Non-goals）：

- 不在本期实现自然语言意图分类模型或远程 Agent 编排服务。
- 不改变 Daemon API、任务协议、DAG、IPC 和运行状态模型。
- 不删除模式存储、模式能力配置或已有 Agent 绑定。
- 不实现新的工作流编辑器、计费系统或模板市场。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workspace`: 工作台由模式优先改为目标优先；页面导航、首页入口、任务历史和高级模板入口发生用户可见变化。

## Impact

- `src/workspace.html`：工作台头部、首页目标入口、常用起点、任务页和模板入口结构样式。
- `src/workbench.js`：页面导航、目标起点映射、工作流启动复用、任务渲染和模式兼容逻辑。
- `tests/workbench-templates.test.js` 及相关工作台冒烟测试：更新用户路径契约和响应式回归。
- 不新增依赖，不修改主进程 IPC 和 Daemon API。

## Context

现有工作台已具备模式状态、Agent 绑定、工作流目录、任务列表和既有启动弹窗，但渲染层以 `activeModeId` 过滤普通工作流，用户必须先做内部分类选择。Electron 主进程和预加载层已经提供工作流启动、任务查询和模式持久化能力，本次设计只重排渲染层信息架构并复用现有调用。

## Goals / Non-Goals

**Goals:**

- 用“开始 / 任务 / 团队”替代模式优先的默认导航。
- 在开始页增加目标输入和四个常用目标起点。
- 将目标和常用起点映射到现有工作流启动预览，不增加新的执行协议。
- 继续保留工作流目录、模式状态、团队和任务能力作为高级/恢复路径。
- 让模式筛选从硬过滤变成排序提示，避免空页面。

**Non-Goals:**

- 不在本期实现 LLM 意图分类。
- 不改变主进程 IPC、Daemon API 或任务数据结构。
- 不迁移或删除已有模式与团队数据。
- 不重写工作流启动弹窗和任务详情工作间。

## Decisions

### 1. 用固定的用户语言导航替代模式选择

头部直接呈现“开始 / 任务 / 团队”。原生模式选择器不再占据默认头部；模式状态仍由渲染层加载并保留在高级模板筛选中。这样消除用户首次进入时的分类决策，同时保持旧状态可恢复。

备选方案是继续保留模式选择器并增加“自动”选项，但这仍要求用户理解模式，并且“自动”会成为另一种内部概念，因此不采用。

### 2. 常用起点使用目标到工作流的确定性映射

四个起点采用静态用户语言和现有工作流 ID 的匹配策略：

- 优先匹配工作流 ID、名称或关键词；
- 找不到匹配时将文本写入目标输入，并打开模板目录；
- 不新增后端分类服务。

该策略能立即交付一致体验，未来可替换为推荐服务而不改变页面契约。

### 3. 目标输入保留为任务意图，不伪造执行

提交目标时，前端只负责选择已有工作流并把目标作为既有启动上下文的意图字段；找不到可启动工作流时，显示模板浏览入口，不创建虚假任务、不声称已开始执行。

### 4. 模式元数据用于排序，不用于普通入口过滤

`activeWorkflows()` 默认返回所有用户可见工作流；当前模式匹配项在推荐排序中靠前。工作流目录可提供“按工作方式筛选”作为高级控制，但普通首页和常用起点不依赖该筛选。

### 5. 渲染层优先，IPC 边界不变

HTML 结构、CSS 和 `workbench.js` 负责信息架构与交互，主进程/预加载只继续提供现有接口。新增 DOM 和少量匹配逻辑不会影响 Electron 启动性能或内存占用。

## Risks / Trade-offs

- [静态关键词可能选错工作流] → 启动前继续显示既有预览，用户可以返回模板目录选择其他流程。
- [首页不能保证所有自然语言目标都能执行] → 明确区分“目标已记录”和“已开始执行”，无匹配时提供模板入口而非假执行。
- [高级用户暂时看不到模式选择器] → 在全部模板目录中提供高级筛选，并保留模式数据和团队页。
- [已有测试依赖旧 Tab ID] → 保留既有 DOM ID 或提供兼容别名，逐步更新测试而不破坏自动化。

## Migration Plan

无需数据迁移。发布后读取原有模式和团队绑定；渲染层默认进入新的目标首页。回滚只需恢复工作台 HTML/JS 和对应测试，既有 IPC、任务和持久化数据不受影响。

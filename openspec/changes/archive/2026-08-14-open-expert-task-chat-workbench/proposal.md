## Why

工作台“安排专家执行任务”当前在点击“创建并开始”后转入 Agent Graph 计划确认，而不是进入所选专家的真实对话 Session，导致任务目标、专家身份、专业能力、技能和知识来源在交接时割裂。目标用户是希望选定一位专家后立即开工的个人知识工作者与专业团队成员；缩短从“选专家”到“开始协作”的路径，可以提高任务启动成功率、专家能力的可理解度，也为后续按专家/知识库扩展高级能力与商业化套餐建立清晰入口。

## What Changes

- “创建并开始”成功后直接创建并激活所选专家的持久 Session，在工作台任务工作间展开对话，不再经过 Agent Graph 二次确认。
- 将任务目标预填进当前专家的 Composer，保留用户确认和补充材料的机会，不擅自发送或启动模型。
- 专家对话首屏展示当前 Agent 的身份属性、职责/专业能力、技能与连接器状态，并保持与专家卡片一致。
- 任务创建弹窗允许选择一个或多个可用知识库；选择结果绑定到新 Session，并在对话中可见、可修改。
- 该 Session 的检索只使用已选择且仍可用的知识库；无选择时回退到当前默认知识库，失效项以受限状态说明，不扩大权限。
- 最近任务重新打开时恢复原专家 Session 和知识库选择；创建 Session 失败时保留任务草稿和弹窗输入，不误报“已开始”。

### 目标用户

- 从工作台快速安排单专家任务的个人知识工作者。
- 需要明确 Agent 能力边界、技能和知识依据的专业用户与团队成员。

### 验收标准

- 点击“创建并开始”后无需第二个计划确认层，工作台直接进入左右任务工作间并显示所选专家对话。
- 新 Session 的输入框包含原任务目标，首屏可看到专家身份、专业能力、技能以及当前知识库。
- 用户可在创建前选择知识库，并在 Session 内调整；下一轮检索遵守 Session 选择。
- 最近任务可恢复到同一 Session；失败路径不丢任务目标、专家或知识库选择。
- 自动化测试、lint 与 Electron 真机冒烟通过且无新增控制台错误。

### 非目标（Non-goals）

- 不把单专家任务自动升级为 Agent Graph 或团队编排。
- 不自动发送任务目标，不在创建 Session 时调用模型。
- 不自动授权、启用或安装技能、连接器、知识库。
- 不重做知识库管理页面，也不引入新的知识 Provider 类型。
- 不改变既有工作流/Daemon 任务的启动与运行语义。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workspace`: 工作台单专家任务创建后直接进入内嵌专家对话任务工作间，并支持可靠恢复。
- `expert-runtime`: 专家 Session 展示并持久化任务目标、能力投影与会话级知识库选择。
- `agent-context-assembly`: 知识检索遵守当前 Session 的知识库范围，并对失效选择安全降级。
- `agent-chat-ux`: 专家对话首屏和 Composer 提供可理解、可操作的专家与知识库上下文。

## Impact

- Renderer：`src/workbench.js`、`src/workspace.js`、`src/workspace-agent.js`、相关工作台/对话样式。
- Main/Session：`src/main.js`、`src/lib/agent-sessions.js`、`src/lib/capability-hub-service.js`。
- 检索：知识 Provider 选择投影与 `ai-generate` 的 Session 级检索范围。
- 测试：工作台任务交接、Session 持久化、专家空态与知识库检索范围。
- 依赖：不新增第三方依赖，不新增不受限 IPC，不直接从 Renderer 访问用户数据目录。

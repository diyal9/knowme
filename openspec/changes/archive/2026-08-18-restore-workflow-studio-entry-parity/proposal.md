## Why

React 重写未按 f6ad048 `workbench.js` 的货架 / 管理工作流 / 编排进出契约对齐。编辑不带 package、复制不带 fork 载荷、离开编排落错面板，违反「重构不改变既有设计」。

## What Changes

- 管理工作流：新建 = 空白草稿；编辑 = 按 id 打开该包 graph；复制 = fork（名称「（我的版本）」并传入 package）；删除确认后归档。仅图标按钮触发动作（与基线一致）。
- 货架空态：新建工作流进编排（返回货架）；去专家库。
- 离开编排：未保存时「取消 / 保存后离开 / 离开」；默认回到管理工作流，从货架进入则回货架。
- 打开草稿优先用货架已加载 graph，GET 失败不挡进入。

## Capabilities

### Modified Capabilities

- `workbench-workflow-shelf`: 货架空态与管理工作流入口
- `agent-composition-studio`: 编排进入、草稿来源、离开返回

## 目标用户

在工作台维护个人工作流的桌面用户。

## 验收标准

- 点管理卡「编辑」打开该流程画布（含「我的专家协作」）。
- 「+ 新建工作流」打开空白「我的专家协作」。
- 「复制」生成「…（我的版本）」并刷新列表。
- 从管理进入后点返回，落在「我的工作流」列表。
- 脏草稿离开可保存或丢弃，取消则留在画布。

## 非目标（Non-goals）

- 不重做画布拖拽/端口交互。
- 不改主进程包存储格式。
- 不改货架主点击（仍打开工作流对话）。

## Context

当前首页由 `renderKnowledgeStatusWorkspace` 生成，渲染层只需调整 HTML 结构与 CSS，不需要新增主进程能力或 IPC。现有搜索、目录树、最近更新、健康检查、提案审核和 Obsidian 入口均已有事件绑定。

## Goals / Non-Goals

**Goals:**

- 让资料目录成为桌面窗口中的主要工作区域。
- 让搜索和少量动作形成稳定的顶部工具区。
- 通过布局和尺寸建立层级，减少解释性文字和卡片数量。
- 保持现有 DOM id、事件绑定、键盘访问和响应式行为。

**Non-Goals:**

- 不重写知识服务或数据模型。
- 不改变搜索结果格式和提案生命周期。
- 不实现新的目录编辑器或关系图谱。

## Decisions

1. **采用两层布局而不是继续增加卡片**
   - 第一层是紧凑的搜索/动作工具区。
   - 第二层是 `minmax(0, 1fr) + 250px` 的资料目录与辅助栏。
   - 选择该方案是因为它能在当前 Electron 窗口尺寸中利用横向空间，同时保留最近更新的可见性；不采用三列布局，避免资料树进一步变窄。

2. **目录面板填充可用高度**
   - `knowledge-page-main` 继续负责滚动，首页主体使用 `min-height` 计算可用空间。
   - 目录树允许空白区域存在，但由统一面板背景和轻量标题承接，不再出现内容悬在左上角的感觉。
   - 不使用 JS 计算窗口高度，避免额外监听和布局抖动。

3. **动作文字保持短标签**
   - 继续保留中文可访问名称，但默认视觉只使用“添加”“检查”“全部”“Obsidian”等短标签。
   - 搜索按钮可保留，但通过表单 Enter 提交；不隐藏可操作性。

4. **样式只做单页覆盖**
   - 新样式集中在 `.knowledge-desk-*` 和首页局部选择器中，避免影响资料浏览、来源和设置页。
   - 保持现有暖灰背景、细边框和低阴影，不引入新依赖或图标库。

## Risks / Trade-offs

- [Risk] 小资料库在大窗口中仍会有自然留白 → 通过占满目录面板高度、增加清晰的资料区标题和辅助栏层级来消除“断裂感”，不强行生成虚假内容。
- [Risk] 缩短按钮文案可能降低首次使用者理解度 → 保留 `title`/`aria-label` 和 hover 提示，详细说明继续放在目标页面。
- [Risk] 旧 `.knowledge-ops-*` 样式仍存在 → 本次不做全局清理，避免波及兼容路由；仅确保新首页不引用旧布局。

## Migration Plan

1. 更新渲染层首页结构与局部样式。
2. 更新知识首页契约测试。
3. 运行专项测试、lint、OpenSpec 校验和 Electron smoke。
4. 若视觉回归不符合预期，可仅回滚首页渲染函数和 `.knowledge-desk-*` 样式，不涉及数据文件。

# Proposal: workbench-dag-branch-view

## Why

工作流启动弹窗右侧的「DAG 关系图」名不副实：`buildWorkflowGraph()` 已经算出完整有向图（含 `edges` 与分支标签：通过/打回/修订、并行/汇合、检查/修复/成功/耗尽），但渲染层 `renderWorkflowDagHtml()` 只取 `graph.order`（BFS 顺序）拉成一条竖直直线，套统一箭头，**完全丢弃 `graph.edges`**。

结果：

1. **结构失真** — 并行、网关打回回环、循环、汇合等分支在 UI 上被拍平成线性步骤条，用户看不到真实执行拓扑，与"关系图"承诺不符。
2. **观感粗糙** — 2px 黑粗边 + 菱形/圆形异形节点在 340–420px 窄侧栏里显得杂乱、廉价。

考虑到该预览位于窄侧栏、Electron 离线打包、暖色极简主题，引入重型图库（Mermaid/Cytoscape）投入产出比低且窄栏易挤压，故选择在现有自绘渲染器上做"分支感知 + 视觉升级"，零打包体积、零 CSP 风险。

## Target Users

- 在工作台浏览/启动工作流、需要先看清编排结构再决定是否启动的办公用户
- 使用含并行、网关、循环等非线性工作流的用户

## What Changes

- **分支感知渲染**：`renderWorkflowDagHtml()` 读取 `graph.edges`，按节点出边渲染连接器；多出边或跳转边渲染为分支 fork，每条支路显示「标签 → 目标节点名」。
- **回环/汇合可读**：指向已出现上游节点的边显示 `↩ 回到 X`，不重复画节点。
- **边标签与色调**：连接器/分支带语义标签芯片（通过/成功=绿、打回/失败/耗尽=红、修订/修复/检查=琥珀、并行=靛、汇合=蓝）。
- **视觉升级**：节点卡改 1px 细边 + 圆角 + 轻投影 + 左侧类型色栏（Agent/脚本/循环/并行/门禁/完成各一色）；移除菱形/圆形异形与已废弃的中央竖脊线；清理死 CSS（`wb-dag-io / wb-dag-next / wb-dag-agent`）。

## Non-goals

- 不引入任何第三方图库（Mermaid/Cytoscape/dagre 等）
- 不做可缩放/平移的全屏工作流画布（如需另立 change）
- 不改动 `buildWorkflowGraph()` 图模型与编排推进逻辑
- 不改动 `agent-workbench` 空态区"MUST NOT 展示编排 DAG"约束（本 DAG 仅存在于工作流启动弹窗）

## Success

- 含并行/网关/循环的工作流在启动弹窗右侧能看到真实分支、回环与汇合，而非一条直线
- 每条分支边显示语义标签与目标节点名，回环标注「回到 X」
- 节点按类型有一致的色栏与轻量卡片外观，窄侧栏内不拥挤
- `npm test` / `npm run lint` 全绿，无回归

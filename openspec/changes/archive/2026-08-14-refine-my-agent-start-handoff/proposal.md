## Why

`add-workbench-work-mode-tabs` 把「我的智能体」卡片的主操作路由到助理对话，这个方向是对的：Agent 的价值就是「带着这个专家说话」，直达聊天比再弹一层启动抽屉更轻。但这条交接路径目前只做到了「能跳过去」，两个边界没兜住：

1. **跳过去以后身份丢了。** 专家欢迎面用的仍是通用文案「把你的问题或任务交给 KnowMe，它来帮你完成」，Agent 名字只作为 `开始使用` 右侧的一行 10px 灰色 `small` 出现。用户从「ui-expert」卡片点进来，屏幕上最显眼的是 KnowMe 通用介绍，看不出自己正在和谁说话——这让直达聊天像「随机跳页」，而不是「进了某个专家的房间」。
2. **依赖缺一点就把入口堵死。** `startExpertChat` 先查渲染层缓存的专家目录，查不到直接返回「专家不存在或尚未安装」，只弹一个 toast 就结束。而卡片本身是从主进程 `expertRuntime().listExperts()` 渲染出来的：目录接口偶发失败（`ensureExpertCatalog` 吞掉异常后置空）时，用户看得见卡片、点了没反应、也不知道下一步该做什么——典型的死入口。主进程的 `createSessionSnapshot` 其实已经支持「依赖未就绪也照样建会话（degraded）」，渲染层这道多余的前置校验反而比内核更严。

顺带解决交互态缺失：`开始使用` 会走 IPC 建会话（异步），期间按钮没有任何 pending 反馈，用户会连点，产生多个会话。

### 目标用户

- **主要**：已经调教过自己 Agent 的进阶用户。他一天里会多次「挑一个 Agent 直接使唤」，需要每次都清楚「我现在在跟谁说话」，以及在飞书等连接器没授权时仍能先聊起来。
- **次要**：第一次点开「我的智能体」的新用户。他需要一眼确认这个 Agent 是干什么的，而不是被通用文案接管。

### 商业化与体验价值

「我的 Agent」是个人定制的付费方向。定制资产要卖得动，用户必须能在使用现场感知到「这是我的那个专家」——身份呈现就是定制价值的兑现面。同时把「依赖没配好」从硬失败降级成「能先聊 + 明确指路去配置」，避免用户在连接器授权前就判定功能坏了。

## What Changes

- **专家会话身份前置**：专家欢迎面新增身份区（图标标记 + Agent 名称 + 来源徽标 + 职责说明），替代通用 KnowMe 文案；卡片与欢迎面共用同一套图标语义，形成视觉延续。Agent 头像若是 emoji 一律不直出，统一走既有图标系统。
- **`开始使用` 不再被渲染层前置校验堵死**：渲染层不再因「本地专家目录里查不到」提前失败，改为交由主进程做权威校验；依赖未就绪时保持既有 degraded 行为（可先聊 + 就绪状态可解释 + 去配置入口），并显式告诉用户「仍可直接对话」。
- **交接失败可恢复**：真失败时保留在工作台、按钮恢复可点、给出可执行的下一步（去调优/去配置），不留死入口，不重复弹两条 toast。
- **卡片交互态补齐**：pending（正在打开…，防连点）、按压位移反馈、`focus-visible` 焦点环、能力标签（技能/连接器数量），并遵守 `prefers-reduced-motion`。

### 验收标准

- 从「我的智能体」任一卡片点 `开始使用`，进入的对话首屏第一眼即可确认 Agent 名称与职责，且徽标标明「我的智能体」。
- 点击后按钮立即进入 pending 且不可重复触发；成功后停在该 Agent 的对话，失败则按钮恢复可点并给出可执行提示，用户仍留在工作台。
- 专家目录接口异常置空时，`开始使用` 仍能开出会话（由主进程校验），不再出现「看得见卡片、点了没反应」。
- 绑定连接器未授权时，会话照常创建，欢迎面同时显示受限项、「仍可直接对话」说明与「去配置连接器」入口。
- 界面不出现 emoji 头像；键盘 Tab 到卡片按钮有可见焦点环；系统开启「减少动态效果」时不产生位移动画。

### 非目标（Non-goals）

- 不改变「Agent 主操作 = 进对话、调优 = 进管理」这条既定路由，也不新建第二个对话场所。
- 不解决助理侧「我的专家」与工作台「我的智能体」的心智重叠（沿用上一轮结论，待体验后再定）。
- 不改执行内核、不改 `expert-runtime` 的快照与 readiness 算法、不改会话持久化格式。
- 不做 Agent 头像上传/自定义视觉体系。

## Capabilities

### Modified Capabilities

- `workbench-work-modes`（定义于未归档的 `add-workbench-work-mode-tabs`）：补齐「开始使用」的交接契约——pending 与防连点、失败可恢复且不留死入口、卡片身份与能力标签呈现。
- `expert-runtime`：明确渲染层 MUST NOT 用本地缓存目录否决启动；专家会话首屏 MUST 前置身份；依赖未就绪 MUST 显式告知仍可对话。

## Impact

- `src/workbench.js`：`agentCardHtml` 增加身份标记与能力标签；`handleMyAgentAction` 增加 pending / 防连点 / 失败恢复与可执行提示。
- `src/workspace-agent.js`：`startExpertChat` 去掉目录前置否决并改为主进程权威校验；`renderExpertEmptyState` 前置身份区并补降级说明；`renderLaunchIntroHtml` 支持自定义引导文案。
- `src/workbench-shelf.css`、`src/workspace.html`（内联样式）：卡片与身份区样式、交互态、reduced-motion 兜底。
- `tests/workbench-templates.test.js`、`tests/workspace-agent.test.js`：更新/新增断言（注意既有断言 `renderLaunchIntroHtml(expert.name)` 会随签名调整而失效，需同步）。

**风险**

- 去掉渲染层前置校验后，不存在的 expertId 会走到主进程才失败。须确认失败路径只弹一条可执行 toast，且不会把用户留在半切换状态（已切到助理视图但没有会话）。
- `renderLaunchIntroHtml` 被通用/知识管家/编程等多个空态复用，改签名须保持默认行为不变，避免影响非专家会话首屏。

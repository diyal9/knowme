## Why

管线执行间「制品」Tab 当前只有一行灰字空态，以及无图标的纯文本文件名列表；失败任务还固定提示「点击预览」，看起来像未完工的占位页。审阅制品是用户判断任务产出的关键证据面，粗糙会直接削弱对管线结果的信任。

目标用户：在 Daemon/管线执行间查看失败或完成任务产出的知识工作者。

商业化与体验价值：把「制品」从空白占位做成可理解的文件夹面板，降低失败后的迷茫与「产品半成品」感，提升审阅路径完成率与口碑。

## What Changes

- 制品空态改为带图标的引导面板：说明为何暂无文件，并按运行状态给出下一步（如查看步骤），不再在空列表时显示「点击预览」。
- 有制品时改为文件夹式文件行：图标、文件名、可选大小/来源元信息、右侧操作；行悬停与对齐与代码工作区文件树气质一致。
- 投影层补充空态文案/元信息辅助字段（纯函数），不伪造制品条目。

## Capabilities

### New Capabilities

- `pipeline-run-review-artifacts`：管线执行间「制品」Tab 的文件夹式列表与状态感知空态呈现。

### Modified Capabilities

- （无；主库尚无独立制品面规格，以新能力承载行为契约）

## 验收标准

- 0 个制品时：可见图标 + 标题 + 状态相关说明；不出现「点击预览打开制品」；不伪造文件行。
- ≥1 个制品时：每行有文件图标与可识别文件名；可预览/复用的操作仍可用。
- 失败 / 进行中 / 成功空态文案有区分（至少失败与进行中不同）。
- 不引入新依赖；IPC / Daemon API 语义不变。

## 非目标（Non-goals）

- 不做真实多级目录树浏览（那是代码工作区职责）。
- 不改制品下载/打开协议与服务端返回结构。
- 不重做步骤 / 变更 / 事件 Tab。

## Context

参见 `proposal.md`。Capability Hub 的精选区和目录区都已使用 CSS Grid，但当前最终样式分别采用 `auto-fit` 与固定两列：精选条目较少时会被拉宽，目录卡片则始终占据半行。页面由 Renderer 静态 HTML/CSS/JS 构成，本次不涉及 Electron 主进程、preload 或 IPC。

## Goals / Non-Goals

**Goals:**
- 让精选区和目录区在常见桌面宽度下共享三列视觉密度。
- 在中等宽度保留两列，在窄窗口使用单列。
- 仅修改布局样式与静态契约，不增加运行时计算。

**Non-Goals:**
- 不修改卡片 DOM、数据筛选、点击交互或抽屉逻辑。
- 不调整主进程目录服务、IPC DTO 或持久化。
- 不引入 CSS 框架或新依赖。

## Decisions

### 1. 精选区和目录区使用同一固定列数

桌面样式统一使用 `repeat(3, minmax(0, 1fr))`。固定三列能避免精选区只有一到两项时把卡片自动拉伸到半行或整行，并让“精选”和“全部”保持一致的卡片宽度。

备选方案是保留 `auto-fit` 并提高最小宽度，但条目不足时仍会填满整行，无法解决截图中的过宽问题。

### 2. 响应式断点按三列、两列、单列降级

在中等窗口断点将两个网格都降为两列，小窗口再降为单列。卡片内部继续使用现有截断和弹性布局，避免横向滚动。

备选方案是用容器查询自动决定列数；当前页面尚未采用容器查询，引入后会增加样式体系复杂度，这个局部调整没有必要。

### 3. 保持纯 CSS Renderer 变更

列数不写入 JavaScript，也不传入主进程。浏览器布局引擎直接处理窗口变化，不增加启动 I/O、事件监听或常驻内存。

## Risks / Trade-offs

- [风险] 三列下长名称和描述可用宽度减少 → 继续使用现有标题省略和描述行数截断，并通过桌面冒烟确认可读性。
- [风险] 较窄桌面窗口三列过密 → 在中等断点提前降为两列，小窗口降为单列。
- [权衡] 精选条目少于三项时右侧会留空 → 保留固定卡宽比把现有卡片拉宽更利于扫描，且与下方目录列对齐。

## Migration Plan

1. 更新规格和静态布局测试。
2. 调整 Capability Hub 最终覆盖样式及响应式断点。
3. 运行聚焦测试、lint、OpenSpec 严格校验并重启 Electron 验证。

回滚时只需恢复相关 CSS 列数和测试断言，无数据迁移。

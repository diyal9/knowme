## Why

Agent 在工具执行后以单次流式 flush 返回正文时，会先显示完整内容，再清空并执行打字机重放；正常流式完成后还会全量重建对话列表，造成明显闪屏、滚动跳动和“回答重复出现”的错觉。当前执行过程与最终回答虽然视觉上同处一条消息，但收尾生命周期没有真正分层，需要改为类似 Cursor 的稳定交互：过程可追踪、完成后折叠，正文不被替换。

## What Changes

- 将执行过程与最终回答作为同一助手消息中的两个独立 DOM 区域管理。
- Run 进行中默认展开执行过程；无待确认步骤的 Run 完成后原地折叠，用户仍可重新展开。
- 已展示过正文时禁止清空并打字机重放；只有完全没有收到流式正文的非流式回退才可轻量揭示。
- 流式完成时原地移除光标、完成 Markdown、补充回答动作和状态元信息，不全量替换对话列表。
- 待确认工具步骤保持可见，不因 Run 结束自动折叠而隐藏审批入口。
- Run 被用户取消时只通过 IPC 返回可克隆的公开字段，不泄漏执行器端口、函数或信号对象。
- 增加静态契约与渲染回归测试，覆盖单次 flush、正常流式收尾、时间线折叠和 DOM 稳定性。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-chat-ux`: 流式完成时保持已显示正文和会话节点稳定，禁止已展示内容清空重放。
- `agent-thinking-timeline`: 执行过程运行时展开、完成后原地折叠，并在存在待确认步骤时继续保持可见。

## Impact

- 目标用户：在 KnowMe 中执行检索、飞书读取、文档生成等多步骤任务的知识工作者。
- 体验与商业价值：消除回答闪屏和重复播放，降低用户对 Agent “结果是否被覆盖”的不确定感；同时保留可展开的执行证据，提高长任务的可信度与持续使用意愿。
- 受影响代码：`src/workspace-agent.js` 的流式正文、执行时间线和助手消息收尾渲染；相关 `tests/` 契约测试。
- API/数据：不新增 IPC 通道，不修改持久化格式或外部连接器协议；收紧 `ai-generate` 取消结果为既有公开字段，不新增依赖。
- 验收标准：
  - 单次 flush 的完整正文只出现一次，不被清空重放。
  - 多 chunk 流式结束后正文节点及既有历史消息节点保持不变。
  - 执行过程运行中展开，完成后在原节点上折叠；用户可再次展开。
  - 存在 pending review/待确认写入时，审批入口保持展开可见。
  - 用户取消生成后显示正常取消态，不出现 `An object could not be cloned`。
  - `npm test`、`npm run lint` 与 OpenSpec strict validate 通过。
- 非目标（Non-goals）：
  - 不展示模型原始 chain-of-thought。
  - 不调整工具编排、模型流协议或回答内容。
  - 不在本 change 中迁移设置页的飞书待确认列表。

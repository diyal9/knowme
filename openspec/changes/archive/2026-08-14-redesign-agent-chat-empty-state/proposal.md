## Why

当前 Agent 页在无消息时仍把输入框固定在底部，任务入口与输入主动作彼此割裂，用户进入页面后不容易判断第一步该做什么。参考用户给出的双状态界面，需要让首屏成为聚焦的任务启动页，并在发送后自然切换为高效、稳定的对话布局。

## What Changes

- Agent 无消息且无产物时展示聚焦首屏：简短说明、主输入框和四个快捷任务形成单一视觉路径，不额外展示装饰性助手图标或大标题。
- 首屏复用真实 Composer、模型选择、附件、快捷命令和发送链路，不创建第二套输入状态。
- 首屏发送按钮复用会话态的图标、尺寸与中性按钮样式，不使用独立的粉色强调底板。
- 用户首次发送、点击快捷任务或恢复已有消息后，Composer 自动回到底部固定区域，页面切换为消息列表 + 底部输入框的会话态。
- 会话态将用户消息收为右侧轻量气泡，助手回复保持左侧阅读轨道，强化双方层级。
- 保留现有专家、能力包、工作流、连接器 preflight、命令面板和键盘发送行为。
- 顶栏“+”新建菜单只展示通用、知识管家、写作和编程四个内置助手模式；专家继续从能力入口启动。
- 增加桌面宽度与窄窗口响应式规则，并补充状态切换回归测试。

### 目标用户

- 首次进入 Agent、不熟悉内部能力分类，希望直接描述任务的知识工作者。
- 需要从快捷任务快速开工，并在后续连续对话中保持清晰上下文的高频用户。

### 验收标准

- 新会话初始页中央依次展示简短说明、真实输入框和四个快捷任务，不显示装饰性助手图标或“开始一个新任务”大标题。
- 首屏附件与发送图标的视觉样式和进入会话后的底部 Composer 保持一致。
- 在首屏输入并发送后，输入框立即回到底部，会话区展示用户消息与助手回复。
- 用户消息右对齐，助手内容左对齐；长内容、执行轨迹和结构化结果仍保持可读。
- 点击首屏快捷任务仍走既有任务目录、授权/材料 preflight 和发送逻辑。
- 点击顶栏“+”时只出现四个内置助手模式，不混入已安装专家或能力包。
- 切换到空会话时恢复首屏；切换到有消息会话时保持会话态。
- 窄窗口下首屏不溢出，快捷任务自动改为单列。

### 非目标（Non-goals）

- 不修改模型调用、Agent 运行时、IPC、存储格式或 Session 协议。
- 不照搬参考产品的连接微信/Slack 文案；首屏继续展示 KnowMe 当前可真实执行的任务。
- 不重构快捷命令面板、能力入口或工作台流程。
- 不新增字体、图片或前端依赖。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-chat-ux`: 增加空会话任务启动态、首次发送后的会话态切换及消息对齐要求。
- `workspace`: 修改 Agent 空状态中 Composer 与快捷任务的布局层级和响应式行为。

## Impact

- 主要影响 `src/workspace.html`、`src/workspace-agent.js` 和 `tests/workspace-agent.test.js`。
- 不新增依赖，不改变主进程、preload、IPC 或用户数据。
- 体验价值：降低首次启动任务的认知成本，让“输入目标”成为明确主动作；稳定的双状态布局同时提升首次激活率和持续对话效率。

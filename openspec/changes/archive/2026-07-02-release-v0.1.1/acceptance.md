# 制作人体验验收: release-v0.1.1

## 核心路径

- [x] 用户打开 README，能在 1 分钟内理解 StickyNotes 是什么、如何下载、如何安装、数据存在哪里
- [x] 用户打开 Release `v0.1.1`，能看到清晰的版本亮点、下载资产、校验信息、签名/未签名说明（本地 `build/release-notes.md` + `dist-release/` 已验；GitHub 页 tag 后补）
- [x] 用户下载 Windows installer 并安装后，应用可正常启动且无开发环境路径错误
- [x] 用户新建便签、输入内容、退出并重启后，便签内容恢复
- [x] 用户在设置页点击「检查更新」，获得清晰反馈，不出现无响应或空白状态（QA：接线 PASS；Toast 逻辑已验）
- [x] 用户误点删除便签时看到确认框，取消后数据保留（QA：主进程 dialog 接线 PASS）
- [x] 用户需要迁移数据时，能通过设置页导出便签备份
- [x] 用户查看隐私政策时，能理解便签、知识库/记忆、API Key 默认如何存储与是否上传
- [x] Mac 支持状态有实机验收记录；未通过时 Release notes 不把 Mac 描述为正式支持

## 体验标准

- [x] 下载与安装路径不依赖开发者本地目录，普通用户无需阅读源码即可完成安装
- [x] 版本、签名状态、已知限制表达诚实清晰，不用营销话术掩盖系统安全提示
- [x] Release notes 先讲用户收益，再讲技术细节；避免只列 commit 或内部任务
- [x] 手动检查更新失败时给出可理解原因（`auto-update.js` catch 返回 message）
- [x] 所有发布证据可追溯到 `v0.1.1`（`dist-release/` + smoke 日志）

## 商业化/留存判断

- [x] 首版发布降低用户首次安装的不信任感
- [x] README 与隐私政策足以支撑早期外部用户试用
- [x] 备份与本地存储说明能减少“数据会不会丢/会不会上传”的疑虑
- [x] Release 流程可复用，为下一轮体验增强收集反馈创造入口

## 阻塞条件

- [x] Release 页面缺少 Windows 可下载资产 — **未触发**
- [x] 安装包无法启动或启动即报 JS 错误 — **未触发**
- [x] README/隐私政策承诺了当前产品没有实现的云同步、账号或加密能力 — **未触发**
- [x] 未签名包未做风险披露 — **未触发**
- [x] Mac 未实机验收却被标为正式支持 — **未触发**

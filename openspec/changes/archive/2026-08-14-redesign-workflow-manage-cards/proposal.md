## Why

「我的工作流」管理页仍是单列横条卡片：左侧文字返回占顶栏、卡片只有标题/一句说明/文字按钮，扫读不出流程结构，也与货架卡片的图标操作语言不一致。需要把管理页收成可扫读的两列卡片网格，并让返回与编辑/删除都变成图标操作。

### 目标用户

- 维护自建/派生工作流的进阶用户（编排后回管理页改删）
- 从货架「管理我的工作流」进入、快速确认流程结构的用户

### 商业化与体验价值

管理页是货架主线的次级维护面：更易扫读的卡片与统一图标操作，降低「找错流、点错删」成本，强化「货架挑流 → 管理维护」产品一致性。

## What Changes

- 去掉管理顶栏左侧文字「返回」；在「我的工作流」面板标题区右侧放图标返回按钮（回货架）
- 「我的工作流」列表改为两列网格
- 卡片上半：名称 + 简要介绍/能力摘要（输入·产出等）；下半：简要流程步骤条
- 「编辑」「删除」改为图标按钮（`title` + `aria-label`），删除保持确认对话框

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `workbench-workflow-shelf`：管理「我的工作流」面 MUST 使用两列卡片、上下分区（简介 + 简要流程），并使用图标返回/编辑/删除。

## Impact

- `src/workspace.html`：管理页头/面板操作区
- `src/workbench.js`：`workflowManageItemHtml`、返回绑定
- `src/workbench-shelf.css`：网格与卡片分区样式
- `tests/workbench-templates.test.js`：结构断言

## 验收标准

1. 管理页左侧无文字返回；右侧有图标返回，可回货架
2. 有 ≥2 条个人工作流时，卡片呈两列（窄屏可回落单列）
3. 每张卡上半可见名称与简介/能力，下半可见简要步骤流程
4. 编辑、删除为图标按钮；删除仍需确认
5. `npm test` + `npm run lint` 通过

## 非目标（Non-goals）

- 不改 workflow package schema / 删除/编辑 IPC 语义
- 不重做货架主卡片或 Studio 画布
- 不在管理卡内内联编辑图结构

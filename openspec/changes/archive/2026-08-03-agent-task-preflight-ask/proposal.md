# Proposal: agent-task-preflight-ask

## Why

四个模式（通用 / 知识管家 / 写作 / 编程）首页的任务卡片当前"基本不可用"：

- 点击卡片本质是把一段长 prompt 直接丢给 LLM，缺少发送前的确定性准入判断
- 缺素材（写作/编程无正文、报错、需求）或缺前置条件（飞书未授权）时，模型仍会开工并**乱编**结果
- 通用空态卡片走的是未增强路径（`runQuickStarter`），可能被 chat 分层关掉工具，进一步加重幻觉
- 缺信息时的"追问"依赖模型自觉，措辞不稳定、时机不确定

作为办公助理，"不乱说、不乱做"是底线。若不做确定性拦截，卡片会被用户理解为"能点但答非所问"的摆设。

## Target Users

- 依赖四模式卡片快速开工的办公 / 研发 / 写作用户
- 尚未授权飞书、或习惯先点卡片再补材料的新用户
- 期望"缺什么一句话说清、给了就直接做"的高频使用者

## What

- 为每个任务卡片增加**确定性 preflight**：发送前判断能否真执行
- 缺内容时用**一句话（代码写死、非 LLM 生成，零幻觉）**询问所需内容，并暂存该任务
- 用户在输入框补齐素材后**直接发送即可自动带上原任务指令继续**，无需再点一次卡片
- 缺飞书授权时**不调用 LLM**，只提示去"设置 → 连接器"授权
- 统一空态卡片与快捷菜单入口，均走增强执行路径（带执行策略 + 飞书 workflow 工具锚点）
- 知识管家"检索远程知识库"缺查询主题时同样一句话询问

## Non-goals

- 不改主进程 `ai-generate` 主流程与 LLM 调用协议
- 不改 chat-intent 分层算法本身
- 不新增连接器 / 工具，也不改 allowlist 投影机制
- 不重做四模式的整体 UI 与文案体系
- 不实现飞书授权的一键内联跳转（后续可迭代）

## Success

- 缺素材点写作/编程卡片 → 只回一句话询问，不产出瞎编内容
- 未授权点通用飞书类卡片 → 只提示授权，不调用 LLM
- 补齐素材后直接发送 → 自动按原任务执行
- 条件齐备点卡片 → 走增强路径直接开工
- 四模式原有入口、快捷菜单、artifact / 飞书审阅链路不被破坏
- `npm test` / `npm run lint` 全绿

## Why

工作台目前已经有目标输入、工作流目录、启动弹窗、Daemon 轮询和任务投影，但这些能力没有形成连续的用户路径：目标提交后容易被送进模板搜索，团队配置与目标脱节，失败任务只有“查看详情”，而部分 Daemon 终态还会被渲染成“已完成”。用户因此无法稳定完成“提出目标 → 准备 → 执行 → 处理等待 → 查看结果 → 继续/重试”的闭环。

目标用户：希望从首页直接完成会议整理、方案写作、软件研发或视觉产出的普通桌面用户，以及需要恢复和追踪真实任务的高级用户。

商业化与体验价值：让每一次目标输入都能落到可执行、可恢复、可复用的任务记录，减少用户在模板、团队和任务页之间迷路；失败任务提供恢复路径，提升首次成功率和持续使用率。

## What Changes

- 将目标、工作流、Agent、资料和 Daemon task slug 组织为统一的任务草稿上下文。
- 目标提交后进入执行准备状态，明确推荐流程、参与 Agent、所需资料和开始执行动作；管理团队或补充资料后保留原目标。
- 修正 Daemon 启动、轮询、审批、澄清、终态和制品读取的状态归一化与异常处理。
- 将失败、取消、等待和完成映射为不同的用户动作，支持重新启动、处理下一步、查看结果和打开制品。
- 将“执行成功”与“产物可用”分开表达：完成态不再展示内部事实串或运行中操作提示，有产物时直接提供打开入口，无产物时明确标注并提供日志与重跑入口。
- 补齐 Agent Graph、本地团队与 Daemon 终态的产物归一化和回写，避免已经生成的结果因未登记到统一 artifact 投影而在工作台消失。
- 任务终止后刷新首页与任务页最近任务；重启后可从 Daemon 任务列表重新打开并恢复投影。
- 修复首页快捷入口缺失的视觉图标，并保持现有 IPC 名称、Daemon HTTP 协议和权限边界。

验收标准：

- 用户从首页输入目标后，能看到明确的执行准备信息，不会落入无上下文的模板搜索死路。
- 用户取消准备弹窗或进入团队/能力中心后，原目标仍可继续使用。
- completed/finished/done、failed/error/rejected、cancelled 和等待态分别显示正确状态与下一步动作。
- 启动、轮询或制品请求失败时，不会显示“已开始”或“已完成”等虚假成功状态。
- 任务终止后最近任务立即更新；刷新或重启后可重新打开真实 Daemon 任务。
- 完成任务可查看制品并回到工作台继续；失败任务可重新启动或明确说明不可恢复原因。
- 完成但没有可打开产物的任务显示“已完成 · 无产物”，不得把“产物”阶段渲染成已交付，也不得继续展示审批、澄清、补充材料等运行中引导。
- 任一执行后端返回可识别的文件、URL 或结构化产物时，工作台统一投影为可打开的 artifact；只有后端确实未返回产物时才进入无产物完成态。
- 默认窗口和窄窗口下准备、运行、结果区域无横向溢出，既有便签、能力中心和 Agent Runtime 不受影响。

非目标（Non-goals）：

- 不重写 Agent Runtime、RunManager、Scheduler 或 `/agent/v1` 协议。
- 不在 Workbench 中伪造 Daemon 未提供的 cancel/resume API。
- 不改变 Daemon 任务创建、启动、gate、clarify 的 HTTP payload 契约。
- 不实现新的工作流编辑器、远程模板市场或计费系统。

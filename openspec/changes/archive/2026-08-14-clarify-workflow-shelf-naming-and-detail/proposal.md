## Why

工作流货架已经能启动，但用户仍看不懂名称、点卡片进不了详情。当前标题沿用 `输入 → 产出` 管道公式，复制后再叠「（我的版本）」，和「我的」角标重复；卡片空白区无响应，用户无法先了解「这个工作流能做什么」再决定是否开始。现在补齐展示层可读性与详情入口，能直接降低选择成本，又不触动 package 真源。

### 目标用户

- 主要：打开工作台想挑一个现成流程办完事的知识工作者。
- 次要：会复制团队流程并微调的进阶用户。
- 不服务：需要改 package schema 或重做编排内核的运维/研发角色。

### 商业化与体验价值

货架是工作台主线入口；名称难懂 + 无详情会让用户停在「看不懂就不敢点」。修好展示层可读性与详情弹层，可缩短「浏览 → 理解 → 启动」路径，提升工作流使用率与「我的」派生留存，且成本低于改数据模型。

## What Changes

- **展示层短名**：货架卡片、运行视图标题、管理列表等 UI 使用结果导向短名；**不改** `workflow-package.name` 真源字段。
- **去掉展示冗余**：UI 隐藏名称末尾的「（我的版本）」类后缀，以来源角标「团队 / 我的」区分归属。
- **点卡片开详情**：点击卡片空白区打开**居中详情弹层**，说明能做什么、需要什么、产出什么、参与步骤/专家、可运行性与缺失项。
- **操作分区**：详情与卡片主 CTA「开始」保留文字；「编辑 / 复制并调整」改为图标按钮（含 `title` / `aria-label`）。
- **点击不冲突**：点图标按钮只触发对应动作；点「开始」直接进入确认输入；点卡片空白才开详情。

### 验收标准

- 含 `→` / `—` 管道式内部名的工作流，在货架与运行标题显示为结果导向短名；package 持久化 `name` 不变。
- 带「（我的版本）」后缀的内部名，UI 不再重复展示该后缀；「我的」角标仍可见。
- 点击卡片空白区打开居中详情弹层，内容覆盖能力说明、输入、产出、步骤/专家与可运行状态。
- 关闭按钮、Escape、遮罩点击可关闭详情并回到货架。
- 「开始」仍为文字主按钮；编辑/复制为图标按钮且可访问名称完整。
- 点图标或「开始」不会误开详情。

### 非目标（Non-goals）

- **不改** `workflow-package` 存储字段、fork 写入逻辑的持久化 `name`（除非仅影响展示映射表）。
- **不重做** Run 三段流程、编排 Studio、Daemon 目录语义。
- **不用** 右侧抽屉承载工作流详情。
- **不把**「开始」改成纯图标。
- **不新增** 工作流内容或专家依赖。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workbench-workflow-shelf`: 增加展示层命名规则、卡片点击打开居中详情弹层、次要操作用图标按钮且与主 CTA/详情点击分区。

## Impact

- `src/workbench.js`：卡片渲染、点击分区、详情弹层内容、展示名映射。
- `src/workspace.html` / `src/workbench-*.css`：详情弹层结构（复用或扩展既有 `wbWorkflowModal`）、图标按钮样式。
- 可能新增纯展示辅助函数（如 `workflowDisplayName`）及对应单测。
- 不改 IPC、Daemon API、workflow-package schema。

## Why

当前 Agent 对话在宽窗口中让正文、结构化选择和输入框几乎铺满可用区域，长行、偏弱的选择卡片层级与过高的会话态 Composer 共同造成视觉松散。现在需要收紧阅读轨道和纵向节奏，让用户更快区分“回答内容、下一步操作、继续输入”三个区域。

## What Changes

- 收窄普通助手回复的阅读轨道并提高正文行高、标题与列表的层级一致性，长内容保持可读。
- 将结构化选择呈现为更明确的操作区：标题、状态、选项边界和悬停/选中反馈更清晰，避免看起来像禁用项。
- 收紧会话态 Composer 的默认高度和上下留白，同时保留空会话任务启动态的大输入空间。
- 统一正文、结构化 UI、气泡动作与 Composer 的水平对齐，并补充窄窗口响应式规则。
- 不改变 Markdown、安全过滤、结构化选择动作、流式输出或 Session 行为。

### 目标用户

- 在 KnowMe 中阅读较长回答并继续多轮追问的知识工作者。
- 需要从回答中的结构化候选快速选择下一步动作的高频用户。

### 验收标准

- 宽窗口中普通助手正文不再横跨整个消息列，单行阅读长度明显缩短。
- 标题、段落、列表和分隔区域具有稳定的纵向节奏，首尾不产生多余空白。
- 结构化选择区与正文有清晰但克制的分区，选项常态可识别为可点击，hover、focus 和 selected 状态完整。
- 会话态输入框高度较当前更紧凑，仍可自动增长；空会话首屏输入框尺寸不回退。
- 正文、选择区和动作区在桌面及窄窗口下不溢出，长描述可自然换行。
- 既有结构化选择点击、键盘焦点、流式稳定渲染和滚动行为无回归。

### 非目标（Non-goals）

- 不删除或改写模型回答中的业务内容，也不尝试自动识别正文与建议项的语义重复。
- 不修改 Agent 运行时、输出协议、IPC、Session 存储或消息数据结构。
- 不重做空会话首页、执行过程时间线或专业结果卡片。
- 不新增字体、图片、动画库或前端依赖。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-chat-ux`: 增加普通助手回复阅读轨道、结构化选择视觉层级与会话态 Composer 紧凑度要求。

## Impact

- 主要影响 `src/workspace.html` 中 Agent 对话、Markdown、结构化选择和 Composer 样式。
- 可能补充 `tests/workspace-agent.test.js` 与 `tests/structured-choice.test.js` 的静态契约断言。
- 不新增依赖，不改变主进程、preload、IPC 或用户数据。
- 体验价值：降低长回答阅读疲劳和下一步选择成本，使对话更接近稳定的知识工作界面，提高持续使用效率。

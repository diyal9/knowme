## Context

悬浮助理完全位于 `src/workspace.html` 的渲染进程中，由局部 CSS、内联 SVG 和既有交互脚本组成；主进程仅承载窗口，预加载层只暴露快捷面板已有 IPC。当前触发按钮和面板头像复用同一三节点品牌几何，但本次只改变触发按钮的功能图标。动机和体验目标见 `proposal.md`，行为契约见 `specs/workspace/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用与参考图接近的简洁描边铃铛替换悬浮触发按钮内的品牌节点图形。
- 保持 34 px 点击热区、透明底板、主题色、状态红点和现有 presence 动画契约。
- 只修改静态 SVG/CSS，不增加运行时代码、对象、请求或内存常驻开销。

**Non-Goals:**

- 不修改面板头像中的品牌标记或应用级图标资产。
- 不调整按钮定位、拖动、持久化、面板操作与 IPC 边界。
- 不把红点改为数字徽标，也不新增真实通知分发能力。

## Decisions

### 1. 仅替换触发按钮 SVG

保留 `.km-fab-avatar` 中的品牌节点图形，只将 `#km-fab-btn .km-fab-glyph` 改为铃铛。触发按钮负责表达“提醒与待处理入口”，展开后的头像继续表达 KnowMe 品牌身份，避免功能语义与品牌资产混淆。

备选方案是两个位置都换成铃铛，但会使面板头部失去品牌识别，也超出用户指出的局部位置。

### 2. 使用内联单色描边几何

铃铛采用 24×24 视口、`currentColor`、圆角端点和圆角连接的无填充路径，并由按钮局部 CSS统一描边宽度。该方式无需引入图标库，能沿用浅色/深色主题颜色，也便于在 20 px 左右尺寸进行光学校正。

备选方案是复用全局图标注册表，但当前 FAB 是自包含内联片段；为单个静态图标增加脚本依赖会扩大耦合和测试面。

### 3. 状态红点保持独立

既有 `.km-fab-badge` 继续作为唯一珊瑚状态提示，定位改为贴近铃铛右上沿，避免沿用旧品牌标记时的左上角坐标而与铃铛分离。铃铛本体始终单色，不在铃铛内绘制提示点。presence 与 processing 动画仍作用于 `.km-fab-glyph` 容器，因此无需修改脚本。

备选方案是给铃铛增加填充或内部红点，但会与现有恢复徽标形成重复强调。

## Risks / Trade-offs

- [铃铛在小尺寸下线条过细] → 使用约 1.8–2 px 描边并按参考图缩放到约 20 px，回归测试锁定 SVG 结构，Electron 冒烟确认清晰度。
- [通用铃铛弱化品牌识别] → 仅功能入口改铃铛，面板头像和应用级图标继续保留品牌标记。
- [既有 presence 动画的旋转基点更适合节点标记] → 保持容器与基点不变，在真机冒烟中观察；若有明显偏摆，只微调 `transform-origin`，不改状态机。

## Migration Plan

静态页面随应用重载立即生效，无数据迁移。回滚时恢复触发按钮原 SVG 和对应局部描边规则即可，现有位置持久化与 IPC 不受影响。

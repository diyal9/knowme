## Why

KnowMe 首页任务卡与快捷操作面板重复展示同一批能力，动态 Skill 追加后还会破坏原定四卡布局；同时“快捷大类 / 快捷子项”要求用户理解内部分类，降低首次使用与高频调用效率。现在需要把首页推荐、工作流入口和全量能力检索分层，形成可扩展且专业的任务发现体验。

## What Changes

- 首页固定展示四个推荐任务，保持稳定的 2×2 布局；额外动态 Skill 不再继续堆叠为孤立卡片。
- 将“需求梳理”从第五张同级卡片提升为独立的“启动工作流”横向入口。
- 将快捷操作重构为可搜索命令面板，按推荐、最近使用和全部操作组织结果，不再暴露“快捷大类 / 快捷子项”内部术语。
- 首页任务卡与命令面板继续复用统一 Skill 任务目录、任务 preflight 与执行链路。
- 保留 Ctrl+K、方向键、Enter 与 Escape 键盘操作，并补齐搜索无结果与可访问性状态。
- 补充自动化测试，覆盖四卡上限、工作流入口、搜索过滤和键盘执行。

### 目标用户

- 首次进入 KnowMe、需要快速理解“现在能做什么”的知识工作者。
- 高频使用会议、文档、聊天和日程能力，希望通过键盘快速调用任务的熟练用户。
- 安装能力包或扩展 Skill 后，仍需要稳定首页结构的团队用户。

### 验收标准

- 通用/能力包首页最多显示四张推荐任务卡，2×2 布局无落单第五卡。
- 能力包中的需求梳理以独立工作流入口显示，点击后仍走既有 intake 执行链路。
- Ctrl+K 打开包含搜索框的命令面板；输入标题或描述关键词会即时过滤操作。
- 命令面板不再显示“快捷大类 / 快捷子项”，并可通过键盘完成搜索、选择、执行和关闭。
- 动态 Skill 仍可从命令面板发现与执行，不因首页四卡上限丢失。
- 既有飞书授权和材料 preflight 行为保持不变。

### 非目标（Non-goals）

- 不改变 Skill manifest、加载协议或权限模型。
- 不新增连接器，不改变飞书 API 调用行为。
- 不在本次实现跨会话的使用频率统计或云端个性化推荐。
- 不重构对话消息、模型选择器或工作台流程执行器。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workspace`: 修改 Agent 首页任务入口的数量、层级与能力包工作流入口要求。
- `agent-chat-ux`: 修改快捷操作的发现、搜索和键盘交互要求。
- `office-assistant`: 将飞书快捷入口从大类切换面板改为稳定的搜索式命令面板。

## Impact

- 主要影响 `src/workspace.html`、`src/workspace-agent.js`、`src/lib/skill-task-ui.js`。
- 需要更新工作区与 Skill 任务 UI 自动化测试。
- 不新增运行时依赖，不改变 IPC 或持久化数据格式。
- 商业化与体验价值：稳定、低认知负担的首页有利于首次激活；可搜索的统一能力入口有利于扩展能力包和后续 Skill 分发，而不让首页随安装数量失控。

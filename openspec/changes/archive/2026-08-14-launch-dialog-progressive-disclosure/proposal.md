## Why

工作流启动弹窗当前是「左表单 + 右完整 DAG」对半分栏：使用者主任务是填写目标并启动，但首屏同时塞满工程上下文字段与只读拓扑细节，认知过载、决策帮助弱。需要在启动路径做渐进披露，把完整 DAG 与工程字段按需展开。

目标用户：在 KnowMe 工作台启动 Daemon 工作流（如「文档到实施计划」）的业务与项目成员。

商业化与体验价值：降低启动摩擦，让首屏只服务「定义任务 → 开始」；拓扑与工程细节仍可按需查看，信任感不丢、启动转化更顺。

## What Changes

- 启动弹窗默认以任务表单为主；右侧改为轻量流程摘要（步数、是否含门禁/并行等），不再默认铺开完整 DAG。
- 提供「查看执行流程」入口，点击后展开更大的只读 DAG 详情（复用现有分支渲染能力）。
- 将 GitLab / ref / commit / 制品路径等工程上下文字段收入默认可折叠区域；首屏保留任务目标与少量关键字段（任务标识、PRD/asset）。
- 任务运行页的实时 DAG / 节点状态回写行为不变。

验收标准：
- 打开工作流启动弹窗时，首屏不以完整 DAG 占半屏；可见流程摘要与展开入口。
- 点击「查看执行流程」后可看到与现网一致的分支/回环只读 DAG。
- 工程上下文字段默认折叠，展开后仍可编辑并随启动请求提交。
- 现有启动、门禁、并行与任务面板回写路径不回归。

非目标（Non-goals）：
- 不重做任务工作间的运行时 DAG。
- 不引入第三方图库或可编辑拓扑。
- 不改变 Daemon 启动 API 契约与字段含义。

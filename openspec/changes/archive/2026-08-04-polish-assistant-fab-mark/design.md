## Context

悬浮入口位于 `workspace.html` 渲染进程。现有透明热区与右下角定位符合低干扰目标，但实心气泡轮廓、图标内珊瑚点和独立数字徽标形成三个竞争焦点。主进程、预加载与 IPC 不需要变化。

## Goals / Non-Goals

**Goals:**

- 使用品牌既有“三节点连接”图形，避免通用消息应用观感
- 常态和恢复态都只保留一个珊瑚色焦点
- 保持透明常态、明确点击热区与主题适配
- 不增加图片请求、依赖、启动耗时或常驻内存

**Non-Goals:**

- 不改变入口位置和拖动逻辑
- 不重构面板业务及 Session 恢复逻辑
- 不修改主进程或 IPC 边界

## Decisions

### 1. 使用内联三节点 SVG

图形由一条对角连接线、两个端点和一个中心节点组成，延续 `assistant-fab.png` / 品牌预览中的节点语言。常态使用深蓝灰线条与端点、珊瑚中心节点。相比实心聊天气泡，它视觉面积更小，也不会被误认成第三方 IM。

### 2. 恢复态只显示一个微型状态点

数字徽标改为 7px 珊瑚状态点；进入恢复态时，SVG 中心节点回落为主题前景色，使画面始终只有一个珊瑚焦点。恢复语义继续由按钮 aria-label 承担。

### 3. 交互反馈从投影改为透明度与轻微位移

常态无背景、无投影；悬停仅增加 4% 主题色底和轻微上移，键盘焦点保留轮廓，处理中保留既有光环。相比 drop-shadow，这种反馈在白色编辑区更干净。

### 4. 面板头像同步品牌标记

展开面板内的头像使用同一三节点图形，避免入口和面板出现两套身份语言。

## Risks / Trade-offs

- [三节点图形可能被理解为分享] → 使用 KnowMe 固定配色与不同节点尺寸，并在 tooltip/aria 中继续显示“KnowMe 助理”
- [小状态点不如数字醒目] → 恢复入口不是强通知，降低打扰优先；面板打开后提供完整恢复卡片
- [复杂背景降低对比度] → 浅色与深色主题分别指定前景色，悬停提供轻微半透明底

## Migration Plan

仅替换渲染层 CSS 与 SVG；发布后立即生效，无数据迁移。回滚时恢复旧 SVG 和徽标样式即可。

## Context

工作台头部和页面内容均由 `src/workspace.html` 提供结构与样式，`src/workbench.js` 在渲染进程中根据模式、工作流和 Daemon 任务数据更新内容。当前模式下拉框已经使用原生 `<select>` 并通过既有 IPC 持久化；能力中心和团队页也已有公开的渲染进程入口。本次只需要重组现有控件和复用既有动作，不需要扩展主进程或 IPC。

## Goals / Non-Goals

**Goals:**

- 在不增加头部高度的前提下，把模式语义和当前模式组合成一个视觉控件。
- 让零工作流状态在单次点击内进入能力中心或 Agent 选择路径。
- 保留原生控件的键盘、屏幕阅读器和 Windows 行为。
- 通过静态模板测试约束关键结构和动作接线。

**Non-Goals:**

- 不实现自定义下拉弹层。
- 不筛选或迁移 Daemon 历史任务。
- 不增加失败重试 API。
- 不修改 Electron 主进程、预加载脚本或 IPC 白名单。

## Decisions

### 1. 保留原生 select，在同一带边框 label 内整合模式语义

`wb-mode-switcher` 自身承担圆角、边框和背景，内部先显示简短的“工作模式”提示，再显示无独立边框的原生 `select`。这样打开菜单仍由 Windows/Chromium 提供稳定的键盘和辅助功能支持，同时视觉上不再出现“下拉框 + 漂浮文字”两个入口。

备选方案是自定义 popover 菜单，但会增加焦点管理、Esc 关闭、方向键和可访问名称维护成本，不符合本次轻量优化范围。

### 2. 空状态使用事件委托和既有公开入口

空状态由 `renderWorkflows()` 动态生成，并在工作流列表根节点上使用 `data-empty-action` 事件委托：

- `capabilities` 复用 `window.openCapabilityHub('skills')`。
- `agents` 复用现有 Agent 选择器入口。

不新增全局状态，不在每次渲染时重复绑定监听器。空状态只在工作流数为零时出现，因此不会影响目录卡片事件。

### 3. 最近任务保持全局历史，但显式披露来源

Daemon 当前提供的是软件研发任务集合，强行按模式过滤会让非研发模式的“最近运行”完全消失，并可能隐藏用户仍需处理的失败任务。因此保留全局历史，在标题区和每个任务元信息中明确“来自软件研发”；失败条目的右侧动作改为“查看详情”，继续打开既有任务详情。

### 4. 仅在渲染进程变更

所有变化限定在静态 HTML/CSS 和渲染逻辑。Electron 主进程和 IPC 不变，因此不会影响启动性能；新增 DOM 仅为空状态中的少量文本和按钮，内存影响可忽略。

## Risks / Trade-offs

- [原生 select 展开菜单仍使用 Windows 系统样式] → 接受平台一致性，重点优化关闭状态及头部分组，不引入高风险自定义菜单。
- [跨模式任务仍可能让用户分心] → 在标题和条目双层披露来源，后续若 Daemon 提供模式元数据再做真实筛选。
- [能力中心入口在极端初始化失败时不可用] → 复用现有错误 toast，避免静默无响应。
- [空状态动态 HTML 容易发生接线回归] → 增加模板测试，约束动作标记、事件委托和焦点样式。

## Migration Plan

无需数据迁移。部署后直接使用新的头部和空状态；回滚只需还原 `workspace.html`、`workbench.js` 与对应测试，不影响用户模式、Agent 绑定和任务历史。

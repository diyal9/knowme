## Context

工作提示目前由渲染进程 `workspace-agent.js` 动态创建：每条提示是按钮，名称和“依据”两行常驻显示，点击后将已有 `payload` 填入输入框。推荐内容由主进程通过既有 IPC 返回，本次不改变数据契约或推荐计算。

## Goals / Non-Goals

**Goals:**
- 在不增加依赖的前提下，将提示压缩为单行可选择控件。
- 让解释信息同时支持鼠标悬停和键盘聚焦。
- 复用已有 `label`、`payload`、`source` 与 `reason` 数据。

**Non-Goals:**
- 不修改主进程、预加载桥接或 IPC 权限边界。
- 不持久化单条提示的勾选状态。
- 不增加运行时测量、动画库或额外网络请求。

## Decisions

1. **使用原生 checkbox 包裹在 label 中。** 原生控件天然提供勾选语义、键盘操作和可访问状态；相比用按钮模拟勾选，所需事件和 ARIA 状态更少。
2. **详情浮层作为推荐项内部的 DOM 节点。** 通过 `:hover` 与 `:focus-within` 控制显隐，避免全局浮层定位、额外 JavaScript 状态和事件监听。
3. **详情拆为“具体内容”和“为什么推荐”。** 具体内容使用现有 `payload`，原因优先使用 `source.text` / `source.label`，再回退到 `reason`，保证解释不凭空生成。
4. **勾选即填入，随后提示条按既有输入态规则隐藏。** 这与当前点击填入行为一致，同时让用户动作在视觉和语义上都是明确选择。

## Risks / Trade-offs

- [浮层可能靠近窗口边缘] → 限制宽度并使用容器内绝对定位，文本自动换行。
- [勾选后提示条立即隐藏，选中态停留很短] → 保留原有成功提示，明确内容已填入且可编辑。
- [CSS-only 浮层在触屏设备不可悬停] → checkbox 仍可直接选择；当前目标平台为 Windows 桌面端。
- [动态样式增加少量 DOM/CSS] → 仅创建一次，最多渲染三条提示，对启动性能和内存无可感知影响。

## Migration Plan

直接替换渲染结构与样式，无数据迁移。回滚时恢复旧按钮模板和对应样式即可；主进程及 IPC 无需回滚。

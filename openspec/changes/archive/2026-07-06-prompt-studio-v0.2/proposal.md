# Proposal: prompt-studio-v0.2

## 一句话目标

把 StickyNotes 从「通用桌面便签」升级为 **v0.2.0 AI 驱动提示词工作台**：好用的结构化提示词编辑器 + 会记住你历史的本地记忆 + OKF 分类知识库，三者打通。

## 目标用户

- **提示词工程师 / 重度 AI 用户**：每天维护多条提示词，需要版本迭代、结构化写作、快速复制。
- **独立开发者 / 小团队**：按项目/场景管理提示词，希望本地私有、可导出 OKF 包迁移。
- **已有 v0.1.1 用户**：已习惯多窗口卡片与 AI 侧边栏，希望产品价值更清晰、库更好找、越用越懂自己。

## 为什么做

`release-v0.1.1` 完成了分发与信任闭环，但产品叙事仍偏「便签」，核心差异化未显性化。代码里已有提示词卡片字段、AI 流式生成、OKF 知识库、使用记忆，但三者**割裂**：

- 编辑仍是单块 textarea，不像「提示词编辑器」
- 记忆只注入 AI，用户看不见、无法从历史找回
- OKF 在设置页管理，与卡片总览无分类联动

用户明确希望：**做出软件价值，聚焦 AI 驱动提示词管理**。`v0.2.0` 作为一个大包，统一完成定位、编辑、记忆、OKF 分类四条主线。

## 做什么

### 1. 产品定位与叙事（P0）

- 应用内文案、README、关于页：突出「提示词工作台」而非通用便签
- 版本号升至 `0.2.0`，Release notes 说明定位变化

### 2. 结构化提示词编辑器（P0）

- 卡片支持分段编辑：角色 / 背景 / 任务 / 输出格式 / 成功标准（与默认 systemPrompt 结构对齐）
- 自由模式与结构化模式可切换；`content` 仍为单一落盘字段（拼接或 JSON sections）
- 版本链：`parentNoteId`、版本列表、两版文本 diff（简单行级即可）
- 编辑器增强：等宽、可选 `{{变量}}` 高亮、本地字数/Token 粗估

### 3. 总览与分类浏览（P0）

- 总览 `list.html`：按分类（category）、OKF 标签、项目、版本组筛选
- 卡片数据模型扩展：`category`、`okfTags[]`、`okfConceptId`（可选）

### 4. 记忆可视化 + 更懂你（P0）

- 「使用记忆」面板：近期使用、高频复制、AI 生成记录摘要
- 记忆条目可跳回对应提示词卡片
- 继续写入 `product-memory.js`，打开卡片/复制/AI 生成时 capture

### 5. OKF 分类与双向同步（P0）

- 「收录到知识库」：成熟卡片 → OKF Concept（`knowledge/concepts/`）
- 「从知识库实例化」：Concept → 新卡片
- 设置页知识库统计与总览分类数据一致

### 6. AI 辅助分类（P1，本包纳入基础版）

- 根据卡片内容建议 `category` / `tags`（用户确认后保存）
- 失败/无 Key 时不阻塞手动分类

## 非目标（Non-goals）

- 不做云同步、账号体系、多人协作
- 不做完整知识图谱或 Notion 级文档系统
- 不做 RAG 向量检索或本地 embedding 库
- 不重构为 Web 应用；保持 Electron 多窗口 + 托盘
- 不在本 Story 解决代码签名 / Mac 公证（延续 v0.1.1 状态）
- 不做自动后台把每条记忆升格 OKF（须用户确认）

## 验收标准

- 新用户 3 分钟内理解这是「提示词管理工具」
- 能结构化编辑提示词、迭代版本、查看 diff
- 总览能按分类/标签筛选找到历史提示词
- 记忆面板可见近期行为并能跳回卡片
- 能将卡片收录为 OKF Concept，并能从 Concept 实例化卡片
- AI 生成仍可用，且继续注入知识库 + 记忆上下文
- `npm test` / `npm run lint` 通过；`v0.2.0` 可打包发布

## 产品价值

`v0.2.0` 让软件从「能用的便签」变成「值得每天打开的提示词工作台」：写得更专业、找得更快、用得越久越懂你，且 OKF 让知识可迁移、可分享。这是留存与口碑的核心差异化，也为后续模板市场、团队包导出打基础。

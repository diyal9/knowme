## Why

当前工作台的团队页在没有成员时只显示一块大面积虚线空白，用户知道“还没有 Agent”，却不知道下一步该做什么。截图中“高级”菜单也贴着窗口顶部展开，菜单标题被裁切，导致高级模式筛选看起来像坏掉了。

目标用户：第一次进入工作台、正在为日常办公或视觉创作组建 Agent 团队的普通桌面用户。

商业化与体验价值：把团队页从“空白配置页”变成可继续的组队入口，减少用户首次配置的停顿；同时让高级模式筛选保持可发现、可理解，不因菜单遮挡降低对工作台核心路径的信任。

## What Changes

- 将团队页空成员状态改为紧凑的引导面板，说明 Agent 团队能做什么，并提供“添加 Agent”和“浏览能力中心”两个动作。
- 复用现有 Agent 选择与能力中心入口，不新增 IPC、存储或能力安装协议。
- 调整团队页首屏的间距、标题层级和空状态布局，减少大面积无信息留白。
- 修正高级模式菜单的展开定位与层级，避免在顶部被裁切，并补充窄窗口下的可用布局和焦点反馈。
- 保持已有团队绑定、模式切换、成员卡片和工作台导航行为不变。

验收标准：

- 无成员时，用户在团队页首屏能看到至少一个明确的下一步动作，并可进入 Agent 选择路径。
- 高级菜单展开后，标题“工作方式”和模式选择器完整可见，不被工作台顶部裁切。
- 默认窗口与窄窗口下，团队页和高级菜单无横向溢出、遮挡或不可点击区域。
- 已有成员时仍按原有分组展示，添加、移除和模式切换行为不变。
- 不新增依赖，不修改 IPC、Daemon、模式存储和 Agent 权限边界。

非目标（Non-goals）：

- 不重新设计能力中心或 Agent 详情页。
- 不改变工作模式模型、工作流目录和执行协议。
- 不引入新的图标库、字体、弹层框架或后端接口。

## Context

工作台由 `src/workspace.html` 的原生 HTML/CSS 和 `src/workbench.js` 的渲染层状态组成。团队页已有 `wbTeamAdd` 按钮和能力中心入口，但 `renderTeam()` 的空分支只输出不可操作的文字。高级模式使用原生 `<details>` 与 `<select>`，当前菜单相对工作台头部向下展开，在窗口高度较小时会与内容边界产生裁切感。

## Decisions

### 1. 空状态复用现有入口

空团队面板使用现有 `wbTeamAdd` 事件打开 Agent 选择器；新增的能力中心按钮使用已有 `openCapabilityPicker('skills')`。不新增消息桥或主进程调用，避免改变绑定和权限校验。

### 2. 空状态使用语义化动作区

`renderTeam()` 输出带图标、标题、说明和两个按钮的引导结构。按钮使用 `data-team-empty-action` 交由既有团队容器事件委托处理，避免为动态 HTML 增加重复监听。

### 3. 高级菜单保持原生控件但向下留出完整空间

菜单仍由 `<details>` 提供键盘和原生关闭行为；通过提高头部层级、给菜单统一的外框和内部间距，避免 label 与 select 拼成被截断的两块。模式选择器保持原有 ID 和 `change` 监听。

### 4. 渲染边界与性能

所有改动限定在渲染进程静态资源，不增加启动请求、轮询、持久化或常驻对象。CSS 只使用已有变量和现有图标挂载机制，窗口缩放继续由现有 resize 处理。

## Risks / Trade-offs

- 空状态增加了一个次级入口，但不会把用户带离当前模式；能力中心仍由现有宿主路径打开。
- 高级菜单需要覆盖工作台内容，因此只提升局部层级，不改变应用全局 z-index 体系。
- 窄窗口下按钮会换行，但保留完整文本和键盘焦点，不使用横向滚动。

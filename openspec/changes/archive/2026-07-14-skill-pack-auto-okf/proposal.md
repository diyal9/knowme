# Proposal: skill-pack-auto-okf

## 一句话目标

同主题提示词达到 ≥3 条时提示封装为技能包；AI 为每张便签生成一一对应的 OKF 技能文档，可在设置知识库中审阅与修改，并在 AI 助写中引用。

## 目标用户

反复打磨同类提示词、希望沉淀可复用「技能」并在助写时自动带上的重度用户。

## 为什么做

用户多次写同一主题提示词后，知识仍散落在便签；手动收录到 `concepts/` 不够结构化，设置页也不能改。产品侧「≥3 → 封装技能」与开发 Agent 记忆升库无关，需要独立闭环。

## 做什么

1. 按便签 `category`（主题）聚类：未生成技能包且内容有效的卡片 ≥3 → 提示「封装为技能包」
2. 用户确认后：对每张便签 AI 生成专用 OKF 技能正文，写入 `knowledge/skills/`（一便签一文档）
3. 设置 → 知识库：技能主题可预览、编辑标题/正文并保存
4. AI 助写：注入与当前主题相关的技能文档摘要

## 非目标

- 不改 Cursor/`brain/` 开发记忆的 ≥3 升库逻辑
- 不做云端技能市场
- 不强制所有便签必须有 category

## 验收标准

- 同主题 ≥3 张有效便签后出现可操作提示（封装 / 暂不）
- 封装后 `skills/` 内有与便签一一对应的概念，lint 通过，便签记 `skillPackConceptId`
- 设置页可打开技能文档、修改并保存后再次打开可见更改
- AI 助写 system 上下文中包含相关技能摘要（有技能时）
- `npm test` / `npm run lint` 通过

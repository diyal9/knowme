# 工作台拆为「工作流 / 管理」两 Tab

## Why

上一轮 `relocate-agent-authoring-to-capability-hub` 把工作台收敛成单一货架，货架本身干净了，但**运维类操作没有归宿**：

- 「管理」是顶栏右上角一个下拉按钮，点开后从右侧滑出一个覆盖全屏的抽屉。用户看不到它是工作台的一部分，也不知道里面有什么，只有点开才发现是「执行后端 / 自动化」。
- 「新建工作流」按钮挤在货架筛选行的右端，和「全部 / 办公 / 研发 / 视觉」这排**筛选**语义的 chip 并排。筛选是「看什么」，新建是「造什么」，两件事被排在同一行里。
- 我的工作流一旦造出来就只能在货架卡片上「编辑」，没有一个集中的地方查看和清理，货架越长越乱。

这三件事都是同一类问题：**工作台只有「用」的面，没有「管」的面**。抽屉这种形态天然表达「临时浮层」，承载不了「管」这条常驻路径。

### 目标用户

- **主要**：日常靠货架挑流程干活的用户。他大部分时间只在「工作流」Tab，顶栏干净、搜索只服务货架。
- **次要**：会配置执行后端、定自动化、维护自己工作流的进阶用户。他需要一个能反复回来的常驻「管理」面，而不是每次从下拉菜单里翻。

### 商业化与体验价值

把「用」和「管」拆成两条并列的顶部路径，让工作台的能力边界一眼可见——用户不必点开抽屉才知道自己还能配后端、设自动化、造流程。这也为后续管理面继续长出「配额 / 订阅 / 团队共享」等付费相关配置留了正经落点。

## What Changes

- **新增工作台顶栏两 Tab**：`工作流` 与 `管理`，长在顶栏内部、标题右侧左对齐，与能力页 / 知识网的顶栏 Tab 同一套视觉。默认停在「工作流」。
- **`工作流` Tab**：即现有货架（领域筛选 + 卡片网格 + 空态），行为不变。
- **`管理` Tab**：由原管理抽屉升格为常驻 surface，含三个二级分区，`工作流` 排第一位：
  - `工作流`（新增）：「新建工作流」入口 + 我的工作流列表，逐条可「编辑」（进编排）与「删除」（下架）。
  - `执行后端`：原 Daemon 面板，内容不变。
  - `自动化`：原自动化面板，内容不变。
- **BREAKING｜移除顶栏「管理」下拉按钮与菜单**：`#wbManageToggle` / `#wbManageMenu` 退役，其职责由「管理」Tab 承担；抽屉的关闭按钮一并移除（切回「工作流」Tab 即离开）。
- **移除货架筛选行的「新建工作流」按钮**：入口迁至管理 Tab 的工作流分区。货架**空态**里的「新建工作流」按钮保留（空货架需要能自造血）。
- **搜索框按 Tab 显隐**：搜索只对货架有意义，切到「管理」Tab 时隐藏；「进行中」与「刷新」跨 Tab 共用。
- **运行 / 编排全屏页不显示两 Tab**：这两个页面有自己的返回按钮，Tab 在此隐藏，避免出现两套返回语义。

### 验收标准

- 进入工作台，顶栏标题右侧出现「工作流 / 管理」两个 Tab，默认停在「工作流」；顶栏右侧不再有「管理」下拉按钮。
- 「工作流」Tab 的货架筛选行不再有「新建工作流」按钮；空货架时空态里仍能点「新建工作流」。
- 点「管理」Tab 进入常驻管理面（非右滑抽屉），二级分区依次为「工作流 / 执行后端 / 自动化」，默认停在「工作流」。
- 管理 Tab 的工作流分区列出全部「我的」工作流（personal / forked），每条可编辑、可删除；删除后该卡片同时从货架消失。
- 管理 Tab 的工作流分区在没有个人工作流时给出空态，且空态里能直接「新建工作流」或跳去货架复制团队流程。
- 切到「管理」Tab 时顶栏搜索框消失，切回「工作流」Tab 恢复且原搜索词仍在。
- 进入运行页或编排页时两 Tab 隐藏，返回后恢复。
- 旧存档中残留的管理面板值不导致启动报错或空白。

### 非目标（Non-goals）

- 不改执行后端与自动化两个面板的内部内容与行为。
- 不改货架卡片、运行三段式、编排画布的既有行为。
- 不新增工作流共享 / 市场 / 云同步。
- 不把 Agent 的创建 / 调优搬回工作台（仍在能力界面）。

## Capabilities

### Modified Capabilities

- `agent-workbench`：工作台一级导航由「无 Tab」改为「工作流 / 管理」两 Tab；管理由抽屉升格为常驻 surface 并新增工作流分区；编排入口从货架筛选行迁至管理 Tab。

## Impact

- `src/workspace.html`：顶栏新增 `#wbModeTabs`；移除 `#wbManageToggle` / `#wbManageMenu` / `#wbManageClose`；`#wbManageDrawer` 改为 `#wbManageSurface`（`.wb-surface`）；新增 `#wbWorkflowManagePage` 分区；移除 `#wbShelfNewWorkflow`。
- `src/workbench.js`：`setSurface` 支持 `manage`；`MANAGE_PANELS` 新增 `workflows` 并作默认分区；新增我的工作流列表渲染与删除（`workbenchWorkflowPackageArchive`）；顶栏 Tab 路由与搜索框显隐；`closeManageDrawer` 语义改为「切回货架」。
- `src/workbench-shelf.css`：复用既有 `.wb-mode-tabs` 样式；管理由 fixed 抽屉改为 surface 布局；新增工作流管理列表样式。
- `tests/workbench-templates.test.js`：更新 DOM / CSS 断言。

**风险**

- 管理抽屉是 `position:fixed` 覆盖层，改为 surface 后其内部 Daemon / 自动化面板的高度与滚动依赖会变，需确认两个面板不塌陷、窄窗(760px)不破版。
- `setWorkbenchPage('daemon'|'automation')` 是外部调用入口（设置页 / 通知跳转），改造后必须仍能直接落到对应管理分区。

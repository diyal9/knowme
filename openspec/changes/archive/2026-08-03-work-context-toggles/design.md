# 设计：本轮上下文开关

## 核心判断

勾选框是**状态控件**，不是动作按钮。上一轮的实现让勾选框执行了一个「填模板句」的动作，语义错位，用户自然读不懂。修正的关键是让「勾 / 不勾」这两个状态都真实映射到发给模型的内容差异。

## 两类上下文项

| 类型 | 当前实际行为 | 默认态 | 勾选效果 | 取消效果 |
|---|---|---|---|---|
| `collaboration_prefs` | 每轮无条件注入系统提示 | **勾选** | 维持注入 | 本轮不注入 |
| `work_memory` / `preference_match` | 完全没有注入 | 不勾选 | 作为上下文块附加 | 不附加 |

默认态如实反映现状，这点很重要：协作偏好默认勾选是因为它本来就一直生效，如果默认不勾会造成「我什么都没动，行为却变了」的隐性回归。

## 数据契约

`buildWorkHints` 返回项从「推荐」改为「上下文项」：

```js
{
  id: 'collab:prefs' | `memory:${item.id}`,
  kind: 'collaboration_prefs' | 'work_memory' | 'preference_match',
  label: '<实际内容摘要，用于芯片显示>',
  text: '<完整内容，勾选后进入上下文>',
  defaultOn: boolean,
  reason: '<为什么推荐，用于详情区>',
  source: { type, id, text },
}
```

去掉 `action: 'fill'` 与 `payload` 模板句——它们是上一轮空操作的载体。

## 关闭协作偏好的链路

`buildUserPrompt(settings, mode)` 增加第三参 `options`：

```js
buildUserPrompt(s, ctxRole, { includeUserPrompt: memoryToggles.collaborationPrefs !== false })
```

默认 `true`，保证所有未传该选项的调用点（如设置页预览 `main.js:1715`）行为不变。渲染进程通过 `aiGenerate` 载荷新增 `memoryToggles` 字段传递，`preload.js` 是整体透传，无需改动。

只关闭【协作偏好】段，不动【关于用户】——用户资料是身份信息而非本轮策略，不在本次开关范围内。

## 勾选内容如何进入请求

复用 `workspace-agent.js` 已有的 `context` 拼装位（原 `attachedContext` 附近），追加一个显式块：

```
[本轮选用的工作记忆]
- <text>
[记忆结束]
```

用显式分隔块而非混入正文，便于模型区分「用户当前需求」与「历史记忆」，也便于日后审计本轮实际用了哪些记忆。

## 可见性

原逻辑在输入框有草稿时隐藏提示条（`renderWorkHints` 第 168 行、`refreshWorkHints` 第 216 行）。作为上下文选择器，它必须在用户写需求的同时可见可调，因此改为**仅在运行中或用户主动关闭时隐藏**。

刷新时需保留已有勾选状态，避免用户打字触发重渲染后勾选被重置。

## 风险与权衡

- **触屏无悬停**：详情依赖 hover/focus，触屏用户只能靠芯片标签。因标签现在展示实际内容而非分类名，信息量已足够定位，暂不额外做点击展开。
- **勾选状态生命周期**：限定为「当前会话内保留，发送后不自动清空」。若发送后清空，用户连续追问同一话题时要反复勾选；保留则符合「这是本会话的上下文配置」的心智。
- **上下文预算**：勾选项最多 3 条且每条截断，对输入预算影响有限，沿用现有 `slice` 上限。

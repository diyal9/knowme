## Why

工作流运行视图（确认输入 → 执行中 → 产物）功能已通，但确认输入页视觉像半成品：标题与产出说明在顶栏与卡片内重复、必填旁露出原始 `text` 类型名、表单卡片漂在大片空区、后端文案偏工程化（`Local Team Runtime`）。这削弱了从货架「开始」后的专业感，需要在不改执行语义的前提下把运行表面打磨到与货架同级完成度。

## What Changes

- 消除确认输入阶段的信息重复：顶栏承担工作流名与产出，卡片只承载「填写指引 + 表单 + 元信息」。
- 表单字段标签去工程化：必填用轻徽章；不向用户展示原始 `text` / `string` 等类型名。
- 露出参与专家（有节点时）与执行方式的只读披露，文案改为产品语言（如「本机专家团队」）。
- 统一顶栏、步进条、表单卡片的间距、对齐、焦点与层次，使执行中/产物阶段外壳一致。
- 补充静态契约测试与证据；不改启动 IPC、Run 协议与后端选择逻辑。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workbench-workflow-shelf`: 强化运行视图确认输入阶段的信息层级、标签呈现与参与者/后端只读披露的视觉完成度要求。

## 目标用户

- 从货架点「开始」后填写输入并运行工作流的知识工作者。
- 需要一眼看懂「这步要填什么、谁在跑、跑完得到什么」的非开发用户。

## 验收标准

- 确认输入页不再同时在两处显示同名标题与「产出：…」。
- 必填字段显示「必填」徽章，且不出现原始类型串 `text` / `string`。
- 执行方式以只读中文产品文案展示；有工作流节点时可看到参与专家。
- 顶栏返回、标题、步进在桌面宽下视觉对齐；表单焦点与主按钮层级清晰。
- 现有三段流程、必填校验、返回货架与恢复语义不变；相关单元测试通过。

## 非目标（Non-goals）

- 不改工作流 schema、启动路径、backend 自动选择或 Run 执行内核。
- 不重做专家任务双栏对话房（expert task room）。
- 不引入新 UI 框架或依赖。

## Impact

- 主要改动：`src/workbench.js`、`src/workspace.html`、`src/workbench-shelf.css`（必要时微调 `workbench-console.css`）。
- 测试：`tests/workbench-templates.test.js` 与 change 内自测证据。

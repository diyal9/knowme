## Context

悬浮助理完全位于 `workspace.html` 渲染进程，当前由内联 CSS、SVG 与一段无依赖脚本实现。按钮紧贴右缘，默认是 38×48 的深色药丸，并通过 localStorage 保存纵向位置；面板与既有 IPC 调用不需要调整。

## Goals / Non-Goals

**Goals:**

- 用透明点击区域承载单一聊天标记，降低常驻视觉重量
- 保证浅色、深色主题和键盘操作下的可见性
- 将新视觉的默认位置与旧版位置持久化隔离
- 维持零新增依赖、零额外图片解码和零 IPC 变更

**Non-Goals:**

- 不重构悬浮助理脚本或快捷面板
- 不改变主进程、预加载脚本和 IPC 安全边界
- 不扩展自由二维拖动

## Decisions

### 1. 使用现有内联 SVG，而非图片资产

将气泡主体改为 `currentColor`，状态点保留品牌珊瑚色；浅色主题用深蓝灰，深色主题用暖白。这样无需增加资源请求，缩放也更清晰。备选方案是裁切应用图标或引入 PNG，但会带入方形底板并降低小尺寸锐度。

### 2. 点击热区透明但不缩到图形边界

按钮保持 36×36 的可点击区域，SVG 为 30×30；常态没有背景和阴影，仅在悬停时轻微位移并给图标增加柔和投影。这样视觉上“只剩图标”，同时避免降低可点击性。

### 3. 右下角留出固定安全边距

根节点默认使用右侧 14px、底部 18px；纵向拖动后仍保持右侧 14px。面板继续从图标左侧弹出。位置存储键升级为 v2，使旧药丸贴边位置不会覆盖新的默认表现。

### 4. 保持渲染进程边界

本次仅更新渲染层样式和 localStorage 定位键，不新增主进程逻辑、IPC 通道或持久化文件。应用启动性能和内存占用不产生可测增加。

## Risks / Trade-offs

- [透明按钮在复杂背景上对比不足] → 浅色/深色分别指定前景色，并保留小范围图标投影和清晰焦点环
- [点击热区不可见导致发现性下降] → 图标尺寸保持 30px，品牌状态点保留，悬停提供轻微位移
- [升级存储键丢失用户旧位置] → 仅迁移视觉差异较大的 FAB 位置；用户仍可立即纵向拖动并保存新位置

## Migration Plan

1. 发布后使用 v2 位置键，新入口首次显示在右下角。
2. 用户拖动后写入 v2 键；旧 v1 数据保留但不再读取，便于回滚。
3. 回滚时恢复原 CSS、SVG 与 v1 键即可，不涉及用户业务数据迁移。

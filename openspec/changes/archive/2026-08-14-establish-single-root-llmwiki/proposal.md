## Why

KnowMe 当前把 Provider、Wiki、OKF、Fabric、治理和检索等内部实现暴露为多个一级页面，同时默认个人 Wiki 只有身份、没有可靠的初始化与操作契约，导致新用户必须先理解知识架构才能开始使用。现在需要先建立一个开箱即用、可验证、可恢复的根 LLM Wiki，让用户只通过“添加资料、搜索或提问、确认整理建议”完成日常知识工作。

目标用户是希望用本地资料增强 AI、但不愿学习 LLM Wiki/OKF/Fabric 术语的个人用户和小型团队。体验价值是首次启动即可使用、资料始终可见可改、AI 修改可审核；商业化价值是先形成可信的个人知识闭环，再为后续外部知识源、团队知识库和高级治理能力提供稳定底座。

## What Changes

- 首次启动自动建立唯一的默认根 LLM Wiki；左侧产品入口保留“知识网”，进入后的根库首页称为“我的知识”，不要求先连接或选择知识库。
- 将根库 `raw/` 定义为用户资料区，支持在知识界面创建、打开、编辑和保存 Markdown/文本资料。
- 默认知识界面收敛为“我的知识”“待我确认”“来源”三个用户概念；检索融入首页，整理产生待确认提案，织网与治理退出默认主流程。
- 新增严格的 LLM Wiki 操作 Harness，统一校验初始化、目录契约、相对路径、文件类型、读写原子性、索引新鲜度和健康状态；所有根库写操作必须经过该 Harness。
- 新增可供界面、Agent 和其他主进程模块复用的根库服务接口，统一提供 `query`、`ingest`、`lint`；用户界面分别呈现为“查找知识”“添加资料”“检查问题”。
- 根库 `query` MUST 经过现有 qmd 检索适配器；qmd 可用时同步并查询根库 collection，不可用或执行失败时降级为本地词面检索并返回可观测的降级状态。
- 保持个人记忆独立，不将活动记录或偏好混入根 LLM Wiki 事实。
- 保留现有外部知识源、Fabric 和治理能力作为兼容/高级能力，本阶段不把它们作为默认用户流程。

验收标准：
- 新用户首次打开“我的知识”时默认根库已就绪，不出现“先连接 LLM Wiki”或内部技术术语。
- 左侧入口显示“知识网”，根库首屏先展示来自真实根目录与索引的“主题/目录 → 子目录 → 条目”结构；不得用处理流程卡片冒充知识结构。
- 用户可在界面向 `raw/` 添加、打开、编辑、保存资料，重启后内容仍存在且可搜索。
- 非法路径、非允许文件类型、越界写入和陈旧写入被 Harness 拒绝，并返回可读错误。
- AI 整理结果仍需用户确认后写入稳定知识；原始资料不会被整理任务静默覆盖。
- 根库操作 Harness 可独立执行并输出机器可读报告，自动化测试覆盖成功与拒绝路径。

非目标（Non-goals）：
- 不在本阶段删除远程 RAG、Fabric、治理或 Obsidian 兼容代码。
- 不实现多人实时协作、云同步或二进制富文本编辑。
- 不把产品帮助文档或示例事实写入用户根库，避免污染检索。
- 不把个人 Memory 合并进知识库。

## Capabilities

### New Capabilities
- `llmwiki-operation-harness`: 定义默认根 LLM Wiki 的目录契约、严格操作校验、机器可读检查报告与安全写入行为。

### Modified Capabilities
- `knowledge-os`: 将知识入口改为开箱即用的单根知识体验，统一根库 query/ingest/lint 服务，并支持 `raw/` 资料的可视化创建、编辑、保存与 qmd 优先检索。
- `knowledge-steward`: 将整理流程收敛为根库资料分析与用户确认，隐藏默认流程中的内部知识架构术语。

## Impact

- 运行时：`src/lib/knowledge-os.js`、新增根库 Harness 模块、`src/main.js` IPC、`src/preload.js`。
- 界面：`src/workspace.js`、`src/workspace.html` 的知识导航、首页、资料浏览与编辑状态。
- 数据：`%APPDATA%\KnowMe\knowledge-os\` 默认根库目录契约；兼容已有绑定目录和旧数据，不自动删除用户文件。
- 测试：新增 Harness 单元测试，更新 knowledge-os 与知识页面契约测试。
- 依赖：不新增第三方依赖。

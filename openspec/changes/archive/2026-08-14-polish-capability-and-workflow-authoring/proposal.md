## Why

能力界面与工作台编排的后端已经完整（Expert / Skill runtime、Agent Package、Run 树、Team Workflow），但前端把这两个界面串成闭环的最后几步还缺：

**能力界面**——专家（Expert）的闭环是通的：新建 → 编辑 → 一键开始对话 → 看 Run 证据 → 回来调优。但技能（Skill）这一侧是断的：Skill 详情抽屉只有安装 / 更新 / 卸载，没有任何「用一下试试」的入口，用户必须先把它绑到某个专家、或者在对话里碰巧命中快捷任务，才知道这项技能到底能干什么。同时专家与技能之间的装配关系完全不可见：打开一位专家看不到它装了哪些技能，打开一项技能也看不到谁在用它，用户没法判断卸载一项技能会影响谁。安装预检、高风险确认、信任来源确认还在用原生 `window.confirm`，迁移旧技能用 `window.prompt`，与刚打磨过的弹窗体验割裂，且原生弹窗无法展示预检里已经算好的依赖、风险与成本明细。

**工作台编排**——编排 Studio 的步骤配置里没有 Skill 选择器，只有一个「前往能力界面调优 Agent」的跳转，用户为了给某一步换个技能必须离开正在编辑的草稿；而草稿的 `dirty` 状态只在标题旁显示一行文字，返回货架、切换到另一条工作流、切 Tab 都不会拦截，编辑到一半离开就全部丢失。窄窗下检查器在 1051–1100px 之间被 `display:none` 直接隐藏（`workbench-console.css` 的 1100px 断点把它隐藏，1050px 断点才把它恢复），这一段宽度里根本没法编辑步骤参数。轻量模式的步骤只能用鼠标拖拽排序，没有键盘替代。另有一批变量（`elConsolePipelines`、`elGoalInput`、`elModeSelect`）在当前 DOM 中已无对应节点，却仍在绑定事件。

## What Changes

### 能力界面（Capability Hub）

- Skill 详情抽屉展示该技能声明的可用任务（来自 `skill-task-list` 的 display-safe DTO），并提供「试用」入口：安装并启用后一键开一个新对话，把任务提示词预填进输入框由用户确认后发送。
- 专家详情展示已装配的技能与连接器；技能详情展示已装配该技能的专家。两侧互为链接，点击可直接跳到对方的详情。
- 用统一的应用内确认对话框替换安装预检、高风险能力、未知来源信任三处 `window.confirm`，并在对话框中展示预检已算出的风险依据、依赖问题与兼容性结论；旧技能迁移的 `window.prompt` 改为同一套对话框的输入形态。

### 工作台编排（Studio）

- 步骤检查器内可直接为该步骤选择技能，选择结果写入节点 profile 的 `skillRefs`，保存工作流时一并持久化，不再需要跳出去改。
- 草稿有未保存修改时，返回货架、切换到另一条已保存工作流、切换工作台 Tab 都会先确认；确认框提供「保存后离开 / 放弃修改 / 取消」。
- 修复 1051–1100px 宽度区间检查器被隐藏的断点冲突，让检查器在窄窗下折到下方而不是消失。
- 步骤卡片在轻量模式下也提供键盘排序（`Alt+↑` / `Alt+↓`），并为步骤列表加上可聚焦语义。
- 移除已无 DOM 对应的僵尸元素引用与其事件绑定。

### 目标用户

- 在能力界面挑选、试用、装配能力的 KnowMe 使用者。
- 在工作台编排里搭建与调整个人工作流的 KnowMe 使用者。

### 验收标准

- 打开一项已安装技能的详情，能看到它声明的任务，并能从这里直接开一个预填该任务的对话；技能未声明任务时给出明确说明而不是空白。
- 打开一位已安装专家的详情，能看到它装配的技能与连接器；点击其中一项技能可跳到该技能详情；在技能详情能看到装配了它的专家。
- 安装预检、高风险确认、信任确认、旧技能迁移均在应用内对话框中完成，不再出现浏览器原生弹窗；取消时不产生任何安装或迁移副作用。
- 在编排的步骤检查器里勾选技能并保存，重新打开该工作流后勾选结果仍在，且步骤卡片上的「N 个 Skill」计数同步更新。
- 草稿有未保存修改时点击「返回货架」会先弹确认；选择「保存后离开」等价于点保存，选择「放弃修改」直接离开，选择「取消」留在原地且草稿不变。
- 窗口宽度在 1000–1200px 之间连续变化时，步骤检查器始终可见（侧栏或折到下方），不出现整段消失。
- 用键盘聚焦到某个步骤后 `Alt+↑` / `Alt+↓` 可以改变它的顺序，顺序变化后焦点仍在该步骤上。

### 非目标（Non-goals）

- 不把线性步骤编排改成自由连线的 DAG 画布。
- 不统一 Expert / Skill 与 Agent Package 两套模型的产品心智（另开变更）。
- 不新增暗色主题或主题变量。
- 不改动主进程能力安装、专家保存、工作流持久化的 IPC 协议与数据结构（新增的 `skillRefs` 走既有 profile 字段）。
- 不实现 Agent Package 导入向导与运行态 Guided Recovery（由 `improve-agent-package-onboarding-ux` 负责）。
- 不新增前端依赖。

## Capabilities

### Modified Capabilities

- `capability-hub`: 补充技能试用闭环、能力装配关系可见性与应用内确认对话框的要求。
- `agent-composition-studio`: 补充步骤内技能配置、草稿保护、窄窗检查器可见性与键盘排序的要求。

## Impact

- `src/capability-hub.html`、`src/capability-hub.js`、`src/capability-hub.css`：确认对话框节点、技能任务与装配关系区块及样式。
- `src/workspace.js`：新增 `capability-hub-start-skill` 消息处理。
- `src/workspace-agent.js`：新增按技能开启对话并预填任务提示词的入口。
- `src/workbench.js`：步骤技能选择器、草稿离开拦截、键盘排序、死代码清理。
- `src/workbench-console.css`：断点冲突修复与技能选择器样式。
- `tests/capability-hub.test.js`、`tests/workbench.test.js`：静态契约断言。
- 体验价值：技能从「装了但不知道怎么用」变成「点开就能试」；编排从「改一步要跳出去、走开就丢」变成「原地改完、离开有兜底」。

# 制作人体验验收: writing-office-partner-productization

## 核心路径

- [x] 打开写作模式空态时，首屏任务可以直接理解，不需要先猜按钮含义
- [x] 点击「写需求文档」后，即使只给一句目标和几条要点，也能产出结构清晰的草稿
- [x] 点击「写办公文档」后，通知/汇报/周报等常见文体可直接成稿，而不是只给泛泛模板
- [x] 点击「按提纲成稿」后，能围绕提纲补齐段落和过渡，但不乱编事实
- [x] 点击「排版定稿」后，已有草稿能整理成标题、列表、行动项清晰的版本
- [x] 长文默认能在右侧审阅，再选择写入当前编辑器或生成飞书文档草稿

## 体验标准

- [x] 写作入口体现「办公任务」心智，而不是「提示词编辑器」心智
- [x] 默认去 AI 味明显降低套话感，但不破坏专业文档术语和边界
- [x] 飞书草稿生成前后状态清晰，用户能理解「先草稿、再确认、后写入」
- [x] 短文输出不过度打断，长文输出有稳定审阅路径

## 商业化/留存判断

- [x] 用户第一次进入写作模式时就能理解它能解决什么问题
- [x] 写需求文档与办公文档成为高频可复用能力，而不是一次性 demo 功能
- [x] 飞书草稿链路提升团队内协作可交付性，增加日常留存理由

## 阻塞条件

- [ ] 需求文档输出出现明显 AI 模板腔且无法通过默认后处理改善
- [ ] 长文既没有进入右侧审阅，也无法稳定写入编辑器或进入飞书草稿
- [ ] 去 AI 味导致事实丢失、术语变形或文档风格失真

## 反模式清单（测试角色主动挑）

| # | 反模式 | 检查点 |
|---|---|---|
| A1 | 能力否认 | 助手是否还会说「我无法访问外部网页 / 没有联网能力 / 不支持爬取」 |
| A2 | 甩锅用户 | 是否在未调用工具前就要求用户粘贴正文或换成飞书文档 |
| A3 | 假装读过 | 抓取失败后是否仍输出「据该文章所述…」这类幻觉内容 |
| A4 | 报错不可读 | 失败提示是否是 `TypeError: fetch failed` 一类开发者语言 |
| A5 | 静默截断 | 超长网页是否明确告知「内容已截断」而非悄悄丢内容 |
| A6 | 时间线错标 | 工具卡片标题是否为「读取网页」，而不是 `调用工具：fetch_web_page` |
| A7 | 卡死 | 慢站点是否在 15 秒内给出超时反馈，而不是让用户干等 45 秒 |

## 安全用例

| # | 输入 | 期望 |
|---|---|---|
| SEC1 | `http://localhost:3000` | 拒绝 |
| SEC2 | `http://192.168.1.1` / `http://10.0.0.5` | 拒绝 |
| SEC3 | `http://169.254.169.254/latest/meta-data/`（云元数据） | 拒绝 |
| SEC4 | `file:///etc/passwd` / `ftp://x` | 拒绝，说明仅支持 http/https |
| SEC5 | `http://[::1]/` | 拒绝 |
| SEC6 | 公网域名 302 跳到 `127.0.0.1` | 跳转后拦截，不返回内容 |
| SEC7 | 域名解析到私有网段 | 解析后拦截 |

SEC1–SEC7 已由 `tests/web-fetch.test.js` 自动化覆盖；QA 抽查 SEC3、SEC6 的实机表现。

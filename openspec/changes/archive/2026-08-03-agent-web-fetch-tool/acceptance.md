# Acceptance: agent-web-fetch-tool

- 日期：2026-08-03
- 角色：制作人
- 视角：C 端用户 —— 「我把一条链接丢给助手，它能不能替我读完再干活」
- 结论：**PASS**

## 原始诉求是否被满足

截图里的失败是三层叠加：助手没有读网页的工具 → 拿外链去调飞书搜索 → 搜不到就要求用户「手动复制粘贴」。三层均已处理：

| 层 | 处理 |
|---|---|
| 没有工具 | 新增 `fetch_web_page`，公开 http/https 网页可直接读 |
| 选错工具 | 工具描述与系统提示词双写分流：飞书域走 `feishu.read_doc`，其余外链走 `fetch_web_page` |
| 甩锅给用户 | 提示词明令禁止「没有联网能力」「请手动复制粘贴」；未调工具前不得推辞 |

## 体验维度

| 维度 | 结论 |
|---|---|
| 可用性 | 零配置，粘贴链接即可 |
| 可感知 | 时间线映射「正在读取网页 → 网页读取完成」 |
| 诚实 | 失败给具体原因（超时 / 404 / 安全拦截 / 类型不支持），不编造内容 |
| 等待感 | Anthropic 原文实测 714ms；15s 超时上限 |
| 一致性 | 与「设置 → 内容源 → 添加网页资料」共用 `web-fetch` |
| 边界克制 | 只读用户给出的确切 URL，不做联网搜索 |

- 真实抓取原始故障链接：正文约 33k 字符，标题正确，无 HTML 残留、无未解码实体

- 404 / PDF / 云元数据拦截文案可读
- 内容源回归：`example.com` → `index.md` 可读
- 应用启动无报错；`npm test` / `lint` 硬门禁 PASS

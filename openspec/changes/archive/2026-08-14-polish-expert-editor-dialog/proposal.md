## Why

能力 Hub 的「添加自己的专家 / 调优 / 复制为自建」弹窗目前是一份未分组的长表单：正文区没有内边距、与标题栏和底栏左缘不对齐；Skill、Tool 与知识库都以单列原生复选框铺开，一屏放不下几项，用户需要长距离滚动才能确认自己勾了什么；滚动后又看不到任何已选摘要，保存前无法自检。必填项也缺少标识，ID 或名称为空时只有一句 toast，焦点不会落到出错字段。

## What Changes

- 为专家编辑弹窗正文补齐内边距与栅格对齐，使标题栏、表单、底栏共用同一条左缘。
- 将表单拆分为「基础信息 / Skills / Tool 与连接器 / 知识库范围」四个带说明的分组，分组之间用细分隔线区分。
- 把三处多选从单列原生复选框改为响应式卡片式多选网格，提供悬停、键盘聚焦与选中态，并支持分组级「全选 / 清空」。
- 候选项较多的分组（如已安装 44 个 Skill）不再整列平铺：按分类分节、限制列表高度并在组内滚动，同时提供组内搜索与「仅看已选」，全选 / 清空只作用于当前可见项。
- 每个分组标题显示「已选 / 总数」，底栏常驻一条已选摘要，滚动到任何位置都能确认当前配置。
- 必填字段显示必填标识；保存校验失败时高亮该字段并聚焦，而不仅是弹一条 toast。
- 空目录（未安装 Skill / 未配置 Connector / 未配置知识源）使用统一的占位提示样式。

### 目标用户

- 在能力 Hub 中新建、调优或复制专家的 KnowMe 使用者。

### 验收标准

- 弹窗正文与标题栏、底栏左缘对齐，桌面与窄窗口下均无横向溢出。
- Skills / Tool / 知识库在桌面宽度下呈多列卡片排布，可见项数明显多于改造前的单列。
- 每个分组标题显示已选与总数，勾选、全选或清空后计数与底栏摘要实时更新。
- 选项在常态、悬停、键盘聚焦与选中态下均可识别，键盘可用空格切换。
- ID 或名称为空时保存被阻止，对应字段被高亮并获得焦点。
- 保存后写入的 Skill / Connector / 知识库引用与改造前一致，无数据回归。

### 非目标（Non-goals）

- 不改变专家保存、Agent Profile 持久化、能力目录加载或 IPC 协议。
- 不新增专家字段（头像、模型、权限等）。
- 不改造能力 Hub 的导入弹窗与详情抽屉。
- 不新增前端依赖。

## Capabilities

### Modified Capabilities

- `capability-hub`: 补充专家编辑弹窗的分组、可扫描多选、选择摘要与必填校验要求。

## Impact

- 影响 `src/capability-hub.js`（表单渲染与交互）、`src/capability-hub.css`（弹窗与多选样式）、`src/capability-hub.html`（底栏摘要节点）。
- 扩展 `tests/capability-hub.test.js` 的静态契约断言。
- 不改动主进程、preload、用户数据与已保存专家结构。
- 体验价值：把配置专家从「长表单逐项滚动」变成「分组扫描 + 随时可核对」，降低配置出错与反复滚动成本。

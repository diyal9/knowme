## Why

知识库与设置虽然都以全屏中心面板打开，但一级导航分别散落在内容按钮和 iframe 内部，形成重复标题与双层顶栏，也与工作台、能力页已经采用的扁平下划线标签不一致。统一中心面板导航可让用户更快理解页面层级，并降低跨模块操作的视觉切换成本。

## What Changes

- 为知识库增加“浏览 / 知识源 / 知识体检”一级标签，将已有浏览、来源管理与体检能力组织成可直接切换的页面。
- 将设置现有“内容源 / AI 接口 / 助手模式 / 系统配置 / 连接器 / 我的记忆 / 关于”标签提升到中心面板顶栏，移除 iframe 内重复的设置标题与标签栏。
- 抽取知识库、设置和能力页可共用的扁平标签视觉：透明容器、文字标签、激活下划线，以及清晰的 hover / focus / pressed 状态。
- 保留知识库“全部 / 资料 / 已整理”等内容筛选为二级控件，不与一级页面标签混用。
- 保持现有数据、IPC、设置表单和知识库业务能力不变，并补充窄窗口、键盘语义和跨 iframe 状态同步验证。

## Capabilities

### New Capabilities

- `center-surface-tabs`: 定义知识库与设置中心面板的一致一级标签、页面切换、状态同步及响应式行为。

### Modified Capabilities

无。

## Target Users

- 高频在知识浏览、知识源维护和体检之间切换的知识工作者。
- 需要配置内容源、AI、助手、连接器与个人记忆的桌面端用户。

## Acceptance Criteria

- 知识库顶栏显示“浏览 / 知识源 / 知识体检”，切换后仅展示对应页面并保留现有业务操作。
- 设置顶栏显示现有七个分类，内容区不再重复显示“设置”标题或第二套标签栏。
- 知识库、设置与能力页采用一致的扁平文字标签和激活下划线，不显示胶囊容器或实心激活块。
- 标签具备正确的 `tablist` / `tab` / `tabpanel` 与 `aria-selected` 语义，设置父页面与 iframe 状态保持一致。
- 默认与最小窗口宽度下标签可用、关闭操作可见，现有测试、lint 和 Electron 冒烟通过。

## Non-goals

- 不合并、重命名或删除现有设置分类。
- 不改变知识源、知识体检、设置保存、IPC 或持久化协议。
- 不把知识条目筛选、设置表单分区等二级控件改造成一级标签。
- 不改造 Agent 会话标签、文件标签或其他页面导航。

## Business and Experience Value

一致的一级导航降低用户在复杂配置和知识管理场景中的认知负担，使知识库更像可持续使用的工作空间，而不是功能入口集合；设置页去掉重复头部后可释放首屏空间，让用户更快定位配置项，也为后续扩展知识与连接能力保留稳定的信息架构。

## Impact

- 渲染层：`src/workspace.html`、`src/workspace.js`、`src/settings.html`。
- 测试与证据：中心面板、知识库、设置页回归测试及 Electron 视觉冒烟。
- 无新增依赖、无主进程或 IPC 变更、无数据迁移。

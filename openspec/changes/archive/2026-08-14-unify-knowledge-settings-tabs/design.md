## Context

参见 `proposal.md`。中心面板壳层由 `src/workspace.html` 与 `src/workspace.js` 管理：能力页标签位于外层 drawer 顶栏，知识库完全在 workspace 渲染进程中生成，设置则通过 `settings.html?embedded=1&tab=...` iframe 承载。设置 iframe 已支持查询参数选择分类，但其标题与标签仍在 iframe 内部，因此外层关闭栏和内层标题栏形成双层 chrome。

本次仅调整渲染层导航和页面组织。Electron 主进程、preload 暴露的 API 与 IPC 契约保持不变；不增加依赖、后台请求、定时器或常驻数据副本。

## Goals / Non-Goals

**Goals:**

- 让知识库、设置和能力页共享同一套中心面板扁平一级标签视觉与语义。
- 将知识库已有浏览、来源管理和体检能力提升为三个直接可达页面。
- 让设置父级标签与 iframe 分类双向同步，并校验消息来源。
- 保持最小窗口下的可用性、焦点反馈和关闭操作。

**Non-Goals:**

- 不重写知识库数据加载、来源配置或设置表单。
- 不把知识库二级筛选或设置表单分区提升为一级页面。
- 不改变主进程、preload、IPC、存储或启动流程。

## Decisions

### 1. 中心面板壳层拥有一级标签

在 drawer 顶栏增加可动态填充的通用标签容器。知识库和设置打开时由父渲染层根据模块配置生成按钮；能力页现有标签与通用容器共享视觉选择器，但保留现有 DOM 和事件逻辑。

选择外层壳层而不是继续在各内容页内复制顶栏，可保证关闭按钮、激活线、窄宽滚动和模块间垂直基线一致。备选方案是在 iframe 内只做视觉微调，但仍会保留双层顶栏，无法真正统一 chrome。

### 2. 知识库使用轻量页面状态而不增加路由

在现有 `knowledgeUi` 状态旁维护当前一级页。打开或切换标签时复用已有 provider/list API：浏览页继续使用当前三栏工作区；知识源页把现有来源列表从模态内容提升为主内容页，具体来源配置仍使用二级弹窗；体检页复用现有 lint 结果渲染。

选择函数级页面状态而非引入前端路由，是因为应用使用单 HTML 与原生 JS，当前中心面板生命周期短且无需 URL 历史。该方案不会新增持久化或内存副本。

### 3. 设置分类由父级驱动，iframe 回报状态

父级点击设置标签时重新加载带 `tab` 查询参数的当前 iframe，复用既有初始化选择逻辑。嵌入模式下隐藏 `settings.html` 内部标题栏；iframe 在有效分类激活后向父级发送当前 tab，父级仅在消息源等于当前设置 iframe 时同步激活状态。

选择查询参数 + 小型 `postMessage` 协议而不是父级直接访问 iframe DOM，可保持边界清晰并兼容未来内容隔离；消息只携带枚举值，不传设置数据。

### 4. 通用标签提供语义与窄宽退化

通用容器使用 `role=tablist`，按钮使用 `role=tab`、`aria-selected` 和 `aria-controls`，drawer 内容区作为 `tabpanel`。标签容器在空间不足时水平滚动且不换行，关闭按钮固定收缩优先级。键盘 focus 保留可见轮廓，动效遵循 `prefers-reduced-motion`。

## Risks / Trade-offs

- [七个设置标签在最小宽度下拥挤] → 标签容器允许水平滚动，关闭按钮不参与收缩。
- [设置 iframe 重载导致未保存输入丢失] → 分类切换行为与原设置标签一致；切换前不触发隐式保存，现有保存/取消语义不变。
- [知识源从模态提升后配置动作失去上下文] → 来源列表作为一级页展示，具体新增和编辑继续使用现有二级弹窗。
- [跨 iframe 消息被无关页面伪造] → 同时校验 drawer 类型、当前 iframe 和允许的 tab 枚举。
- [重复 CSS 产生风格漂移] → 能力与通用标签共享基础选择器和状态规则。

## Migration Plan

静态资源随应用重启生效，无数据迁移。回滚时恢复 drawer 动态标签、设置嵌入标题栏和知识库按钮入口即可；用户配置与知识数据不受影响。

## Why

当前工作台以 Daemon 编码团队和编码工作流为主要内容，用户看到的是固定的专家目录，而不是可以从能力中心选人、搭建团队并持续运行工作的个人智能空间。KnowMe 需要把编码重新定位为首个“专业处理能力”，建立适用于日常办公、软件研发、视觉创作等岗位的可组合 Agent 工作台，才能让能力、工作流、自动化和知识真正形成产品闭环。

## What Changes

- 将工作台定位为“用户搭建并运行智能体团队的个人工作空间”，区分工作模式配置平面与任务执行平面。
- 新增持久化工作模式模型：用户可以切换工作模式、查看模式绑定的 Agent 与专业能力，并保留当前模式。
- 首期提供日常办公、软件研发、视觉创作三类工作模式；现有 Daemon Agent 与编码工作流归入“软件研发”专业能力，不再定义整个工作台。
- 重构工作台总览：首页展示当前工作模式、我的 Agent 团队、专业能力、常用工作流与进行中的任务，不再以只读 Daemon 专家墙作为主心智。
- 在工作台增加“团队”分栏，允许用户从能力中心进入专家目录，并将已安装、可用的 Expert 添加到当前工作模式或从团队移除。
- 扩展 Capability Hub 专家动作，支持“添加到工作台”；Hub 只发送受限意图，宿主负责持久化绑定与反馈。
- 保持 Daemon、本地 Agent Run 与未来图像执行器为内部执行提供方；首期不重写执行内核，也不伪造尚未接通的自动化或工作流执行状态。

### 目标用户

- 希望用 Agent 处理会议、文档、沟通、研究等日常工作的知识工作者。
- 需要产品、开发、测试等 Agent 协作完成软件交付的研发岗位。
- 需要组合文案、视觉、图片生成等能力的内容与设计岗位。
- 希望按自身岗位配置 Agent 团队和工作方式，而不是理解底层 Daemon、Builder 或模型差异的个人用户。

### 商业化与体验价值

- 从单一编码 Demo 升级为跨岗位个人智能工作空间，扩大 KnowMe 的目标用户与高频使用场景。
- 工作模式和专业能力包可承载精选模板、行业包、企业团队包与后续订阅权益。
- 用户从“安装能力”自然进入“组建团队并完成工作”，提升 Capability Hub 的激活率、工作台留存和结果交付感。
- 保留专业能力的可扩展边界，避免每新增一个行业都重做一级导航和运行界面。

### 验收标准

- 用户可在工作台切换日常办公、软件研发、视觉创作三类工作模式，重启应用后保留当前模式和团队绑定。
- 软件研发模式继续显示并启动现有 Daemon 工作流；Daemon 离线时诚实展示降级状态。
- 工作台总览明确展示当前模式、团队、专业能力、常用工作流和最近任务，首屏不再把所有 Daemon 角色误呈现为全产品专家目录。
- 用户可从工作台进入 Capability Hub 专家页，并将一个可用 Expert 添加到当前工作模式；重复添加不会产生重复绑定。
- 团队页可查看 Agent 来源、职责、能力和可用状态，并能安全移除用户添加的 Agent；模式内置角色不能被误删。
- 日常办公与视觉创作模式不得伪造可运行工作流；未具备运行入口时应提供添加 Agent/能力的明确下一步。
- 新增模型、IPC 与渲染行为有自动测试覆盖，既有工作流启动、Hub 专家对话和工作台任务恢复路径不回归。

### 非目标（Non-goals）

- 本次不重写 `agent-package-and-team-runtime`、Daemon workflow 引擎或 Agent Run Executor。
- 本次不实现任意拖拽 DAG、跨 Builder 调度、真实定时调度器或图像模型供应商接入。
- 本次不把 Daemon Agent 自动安装为 Capability Hub Expert，也不合并两套运行时定义。
- 本次不开放第三方工作模式市场、计费、团队同步或云端配置同步。
- 本次不允许 Renderer 直接读写 `%APPDATA%\KnowMe`，也不自动扩大 Expert 的技能、连接器或工具权限。

## Capabilities

### New Capabilities

- `workbench-mode`: 工作模式的内置模板、用户 Agent 绑定、当前模式持久化和兼容降级行为。

### Modified Capabilities

- `workspace`: 工作台总览、团队分栏、专业能力心智以及工作模式与现有任务/工作流的联合展示。
- `capability-hub`: Expert 可被安全添加到当前工作台，且保留既有安装、启用和开始对话路径。
- `capability-pack`: 专业能力包可声明适用工作模式与执行提供方，编码能力不再等同于整个工作台。

## Impact

- 主进程：新增工作模式 store 与最小 IPC，复用现有 Expert/Capability 安装状态和 Daemon overview。
- 预加载：增加结构化、最小权限的工作模式查询、切换、绑定和移除 API。
- 渲染进程：调整 `workspace.html`、`workbench.js` 与 `capability-hub.js` 的信息架构和跨 frame 消息。
- 数据：新增 `%APPDATA%\KnowMe\workbench-modes.json`；版本化、原子写入，不迁移或覆盖现有自动化、Session 与 Daemon 数据。
- 测试：新增 store、IPC DTO、工作模式切换、Hub 添加 Agent 与工作台渲染回归测试。
- 依赖：不新增生产依赖，不改变现有 Daemon HTTP 协议。

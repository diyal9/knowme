# Why

「专家协作」与「工作流」当前复用了相似的卡片、委托和对话壳，普通工作流甚至沿用管线服务启动与遥测，用户无法判断是在委托一个专业 Agent、运行多专家流程，还是启动外部管线。

## 目标用户

- 需要把一个边界明确的专业任务交给单个 Agent 的知识工作者。
- 需要使用团队模板或自建流程组合多个 Agent 完成复杂任务的专业用户。

# What Changes

- 专家协作固定为用户与单个专业 Agent 的正式任务；先认识专家，再按其输入输出契约委托。
- 工作流固定为至少两个专家节点及明确交接关系；团队模板只读使用或复制为个人版本。
- 普通工作流切换到 Workflow v2 + Team Runner，不再复用 Daemon/Pipeline 启动和运行投影。
- 专家任务房以交付与验收为主，工作流运行房以节点、待处理和介入为主；移除两者的通用“聊天对象”心智。
- 专家任务越界时只生成可确认的工作流草稿；首版不允许工作流嵌入管线节点。

## 验收标准

- 专家卡与工作流卡均先打开各自详情，不会整卡直接开工。
- 专家任务只能绑定一个专家，工作流发布至少包含两个专家节点。
- 普通工作流运行不调用任何 Daemon/Pipeline 接口。
- 用户遮住页面标题后，仍可根据页面结构判断当前是专家任务还是工作流运行。

## 非目标（Non-goals）

- 不重做 Agent 中心的安装与完整配置管理。
- 不把管线服务作为普通工作流节点。
- 不迁移或删除已有专家任务、工作流和管线历史。

## 商业化与体验价值

清楚的能力边界降低首次使用和错误开工成本；稳定的团队工作流可以作为可复制、可版本化的专业资产持续沉淀，而专家 Agent 保持清晰的单节点专业服务定位。

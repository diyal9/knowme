## 根因与修复边界

1. **确认没有用户消息**：按钮原先只推进运行状态；现在显示用户确认气泡并将确认内容带入持久化委托材料。重进按任务 ID 加载规划会话，避免误按专家 ID 读取；恢复确认采用实际确认事件时间，避免被排序到最初需求之前。旧任务若没有保存确认原文，不伪造用户具体选择。
2. **实际生成却判定失败**：工具中转丢失 receipt/effects/artifactRefs，后续又仅根据工具名猜测保存行为。现在保留真实回执，以实际持久化成果支持保存声明；无回执或缺少声明要求的成果仍不能通过。
3. **修改没有真正使用原图**：本地路径被直接传给只接受远程地址或图像字节的服务。共享资源解析器将当前会话中已登记的 artifact 引用转换为受限图片输入，拒绝读取未登记的任意本地路径。
4. **模型靠 Prompt 自称核对画面**：原先生成工具只向模型返回文本。共享执行端现在可将返回图像作为不可信观察证据输入视觉模型；非视觉模型明确告知未检查。视觉输入不是专业判断正确的保证，更不等于逐像素校验。
5. **恢复与状态污染**：保留完整工具历史；失败记录不因发现文件而改成成功；修复修订时间戳和重新执行心跳。显式执行契约未满足不能记为成功，成功纠正后也不因同轮早先失败一律判失败。
6. **完成状态没落盘**：严格日志保护误将 token 统计键识别为敏感数据，导致终态保存拒绝。保存前脱敏，仍保留严格保护。真实最终运行已持久化 done/terminal=true。

平台承担资源、回执、工具调用、上下文、状态恢复和预览契约；是否采用参考图、选哪个模型、如何写编辑指令和如何评价画面属于 Agent SOP 与能力配置。最后一次改用另一图生图模型完全通过对话完成，没有为它再修改 KnowMe。

## 未获证明与残余风险

- 没有真实执行全部 22 个专家，也没有证明任意 Agent 的专业能力正确。
- GPT-image-2 图生图路径仍出现超时/未按要求改色；平台可以保留证据与让用户继续调整，不代表消除外部服务问题。
- Agent 的视觉核对仍可能夸大（例如“逐像素核对”），应在 Agent 包中持续评估，不把接收图片字节当成专业质量通过。
- 当前会话主要展示最新图片，旧资源与失败记录保留在会话/执行证据；完整可视化版本对比尚未验收。
- 本次编辑的内置 Agent SOP 3.3.0 不等于已证明所有已安装包和旧任务快照自动更新；旧任务实际能力与包升级仍需独立测试。

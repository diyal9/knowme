# Why

KnowMe 当前以 Content Source 和全局 `activeSourceId` 承载文件上下文，伙伴会话、工作台任务、自动化、成果与 Brain 各自保存部分关联，缺少一个稳定、可追溯的共同工作边界。用户也需要从“管理文件”升级为“围绕一个持续目标工作”，同时仍保持“打开一个文件夹就是开始一个项目”的简单心智。

# 目标用户

- 使用本地文件夹或 Git 仓库开展持续工作的个人知识工作者。
- 在伙伴、工作台、自动化和 Brain 之间切换，但希望文件与成果始终落到正确位置的用户。
- 需要追溯成果来自哪次对话、任务或运行的用户。

# What Changes

- 新增产品级 Project 聚合，绑定一个主要可写工作来源和零到多个参考来源。
- 新增统一 Project Context；全局当前项目仅作为导航和新建默认值，持久化实体使用自己的 `projectId`。
- 将现有文件入口升级为项目入口，在项目侧栏中继续提供真实文件树，并展示当前任务与最近成果。
- 为伙伴会话、工作台任务、运行成果、自动化绑定和 Brain 证据建立可选或必需的项目归属。
- 提供从现有 Content Source 到 Project 的兼容迁移；无法可靠判断归属的旧数据保持未归属。
- 将远程仓库标识与产品级 `projectId` 语义分离。

# 验收标准

- 用户绑定本地目录后可以看到一个对应项目，并继续浏览原有文件树。
- 新建文件型任务绑定稳定 `projectId`；切换当前项目不会改变已有任务的读写位置。
- 项目侧栏、伙伴、工作台、自动化和 Brain 对项目范围的展示与筛选语义一致。
- Agent 新建或修改的持久化成果可追溯到项目、任务、运行与相对路径。
- 项目归档或工作目录丢失时不会删除用户文件，也不会继续静默写入。
- 旧来源、旧任务和旧会话可以兼容读取；迁移不会依据迁移时的当前项目错误归属。
- 项目存储、IPC、Renderer 和关键运行路径均有自动化测试。

# Non-goals

- V1 不支持一个项目拥有多个并列可写工作根目录。
- V1 不支持隐式跨项目写入或跨项目事务。
- 不将 KnowMe 做成团队项目管理或权限审批系统。
- 不为每个项目复制伙伴、Skill、MCP、工作流模板或 Brain 数据库。
- 不自动删除、移动或重写用户工作目录中的内容。

# Impact

主要影响 Project/Source 存储、主进程 IPC、preload/shared API、Renderer 全局状态和项目侧栏，以及任务、会话、成果、自动化与 Brain 的归属字段。现有 Source 和 FilesPane 保留为底层兼容能力，按阶段消除运行时对全局 `activeSourceId` 的依赖。

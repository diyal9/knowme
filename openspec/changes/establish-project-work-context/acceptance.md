# Acceptance: establish-project-work-context

## 结论

通过。KnowMe 已将“项目”落为伙伴、任务、Agent、自动化、成果和 Brain 共同使用的稳定工作上下文；“当前项目”只负责导航与新对象默认值，不会重定向既有对象。

## 用户结果

- 左侧“文件”入口升级为“项目”，继续展示真实工作区文件树，不复制或迁移用户文件。
- 既有本地/Git 仓库来源会确定性迁移为一个兼容项目；切换项目后，已创建的任务、会话、运行和成果仍保留原项目归属。
- 项目侧栏提供“最近成果”智能视图；成果仍只有一个物理路径或一个虚拟 Artifact 实体，不制造重复文件。
- 无项目会话可继续普通对话；首次项目文件、进程或成果操作前才固定并持久化项目归属。
- 目录丢失时可重新定位；归档与移除只改 KnowMe 元数据，不删除工作区、历史任务、会话、成果或 Brain 证据。
- 自动化和会产出文件的 Agent Graph 会在缺失、归档或只读项目上提前阻断，并给出可行动的错误状态。
- Brain 仍是全局认知层，同时支持“当前项目 / 全部”筛选；项目证据保留自己的 `projectId` 和来源链。

## 验收标准

- [x] Source → Project 兼容迁移幂等且不复制文件
- [x] Project Store / IPC / preload / renderer 状态链路完整
- [x] 当前项目切换不改变既有实体归属
- [x] 文件工具按显式 Project Context 解析，首次操作前完成会话绑定
- [x] 任务快照包含工作区来源、仓库版本和输出策略
- [x] Agent/自动化成果具有 project/source/task/run origin
- [x] 自动化启动请求携带 `projectId`
- [x] Brain Node/Claim/Evidence 支持项目范围与稳定证据来源
- [x] 缺失、归档、只读与重新定位生命周期可用
- [x] 项目侧栏、工作台、伙伴与 Brain 的项目标签/筛选一致

## 残余风险

- 当前是 V1 单工作区项目模型；多工作区项目需要新的权限与冲突策略，不应直接扩展 `referenceSourceIds` 为可写。
- 物理成果路径依赖 Agent 遵循项目上下文中的 `outputPolicy`；既有文件编辑保持原路径，新正式成果默认提示写入 `outputs/`。
- 仓库本身已有大量并行未提交改动，GitNexus 的整仓风险评级受这些改动污染，不能作为本 change 的独立风险评级。

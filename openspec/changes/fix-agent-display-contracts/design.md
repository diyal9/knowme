# 设计

- `src/shared/expert-display.ts` 同时供声明归一化、主进程 readiness 和渲染层使用，避免三处分别拼名称。
- 显式可读 label/name 优先；内置模式使用中文名称；旧包使用描述或带序号的中性名称回退，保留原始执行 ID。
- `validateAndNormalizeManifest` 统一覆盖导入、序列化、加载与新建流程；拒绝无效/重复路由标识。归一化不修改输入对象，重复归一化不改变输出。
- Hub 投影携带技能/连接器，已安装专家使用运行时装配信息；独立加载跨类型参考目录，避免当前专家筛选破坏依赖名称和安装按钮。
- 权限详情展示值、是否允许和具体范围，并说明包声明仍受任务授权约束。
- 授权状态共用 `connectorAuthorizationDisplay`，失败和未知均不能显示已授权。
- 委托交付摘要优先显示确认后的 brief；已验收文件列表继续单独筛选。

## 用户确认后结束协作（2026-09-17）
新委托统一采用 review 策略。执行就绪与用户验收分离：所有必需成果产出后进入 review，接受全部必需成果后才 completed。不操作保持等待；修改意见沿用现有修订通道，生成新版后再次等待。总结卡列出成果、版本和结果摘要，提供继续调整与确认完成。多成果确认顺序调用现有验收接口，任一失败即停止。旧 automatic/completed 且有 not_required 成果的未归档任务在读取时恢复 review，不重跑工具或改变版本；已明确接受的任务保持结束。

# 能力聚合运行说明

## 范围与来源

Agent 配置定义默认工具、Skill 和知识范围。任务授权只作用于该任务；发现摘要不等于授权，连接器认证不等于操作批准。显式禁用、治理 denylist、父任务上限和规划阶段的 no-tools 是硬边界。

知识默认指 KnowMe 的 Brain / 知识库（LLM Wiki）/ RAG。Brain 可在没有外部源时独立查询；Wiki/RAG 延续能力中心的 Provider/Collection 配置和选择。没有选择外部源无需配置飞书；显式选择失效时不自动换源。飞书仍是单独发现、授权、认证的连接器。

无归属证明的旧跨会话工作记忆不注入受限专家，仅有主题相似不足以获得授权；当前会话历史仍由原会话上下文承载。平台不会据此删除或改写旧记忆。

## 渐进加载

- 主进程持有完整目录。模型先使用轻量 `discover_capabilities` / `discover_tools`，必要时分页查看。
- 冷 MCP 连接器只公布宿主 schema 加载入口；选中后才建立连接并加载已授权定义，下一轮使用实际 schema。未选中的离线连接器不会阻塞任务。单连接器的授权目录不受旧 32 项上限约束。
- schema 加载入口仍受显式工具 allowlist/denylist 限制。若自定义 Agent 仅允许某个原始 MCP 操作，需同时明确允许该连接器的宿主加载入口；系统给出依赖提示，不暗中扩大硬权限。既有生图适配工具路径不因此自动改成原始 MCP 路径。
- 正常最多 8 项 schema，扩展最多 16 项，受每轮总预算约束；并非必须填满。
- Skill 先展示摘要，激活完整正文和契约，依赖不足转发现或授权。资源通过有界分页读取，不以截断正文冒充完整激活。
- 重启只恢复激活 ID/hash，正文与权限须重新核验；版本变化须重新激活。
- 每轮联合计算消息、必要 Skill/资源、工具 schema、协议开销和输出预留。关键内容装不下时明确阻塞，不静默丢弃。
- 不新增独立规划模型请求，不默认开启远程向量或新图数据库。

## 操作批准与恢复

能力访问授权与具体工具操作在审批卡中分开。批准具体操作绑定工具、目标、参数和当前任务；变更参数、撤权、取消、重启后过期回调不能继续执行。

运行时先持久化操作记录，再允许继续；批准不等于整个任务完成。已执行结果用于后续证据核验，不重放；结果不确定必须先查证。纯只读暂时失败最多自动重试两次，参数修正有界。系统不凭模型声称制造成功证据。

执行中可提交文字和附件作为同一队列项。选择、授权和验收都是等待边界，不自动代选；最终成果区只显示接受后的版本。

## 本地诊断与回退

任务执行依据中可查看工具选择、预算、失败类别和验收状态；不展示内部推理、凭据或完整原始报错。元数据与检索缓存受配置、身份和范围变化约束。

新选择器可用环境变量 `KNOWME_TOOL_SELECTION=bounded-baseline` 回退到有界基础排序；恢复动态排序则移除该变量或设置为 `dynamic`。此开关只改变排序，不解除范围、审批、HTTP 同源防护或上下文预算，也不恢复全量 schema 注入。

先在伙伴、产品经理、生图专家的测试任务验证，再扩大使用。真实外部写入只能对指定测试资源进行；没有配置资源或模型时记录未执行，不用离线结果冒充生产验收。

## 复验命令

```powershell
npm run check
npm run typecheck:lib
node -r ./scripts/register-ts.js scripts/agent-capability-context-benchmark.js
node -r ./scripts/register-ts.js scripts/context-engine-chat-canary.js --allow-skip
node .cursor/scripts/harness.js gate --json --change unify-agent-capability-context-runtime
```

500 项性能脚本是同一合成任务的 schema/本地选择对照，不测真实模型成功率或供应商延迟。真实模型与连接器闭环状态见 test-report.md。

# 设计

## 主进程与渲染边界

主进程拥有能力目录、有效范围、凭据、Skill 激活、执行契约和审批状态。Renderer 仅提交用户动作并显示安全投影；模型返回的 approved/权限字段不能建立授权。复用现有 Context Engine、工具注册器和任务状态存储，IPC DTO 增量扩展。

## 渐进式数据流

用户补充确认：知识范围以产品现有 `Brain / 知识库（LLM Wiki）/ RAG` 三层为主，不是飞书知识库，也不是开发仓库的 brain/ 分层。Brain 认知在本地，Wiki/RAG 通过 Provider/Collection 授权按需查询；没有配置外挂源时不能因此禁用已获授权的本地 Brain。外部来源选择保留配置入口，可后续选择；飞书是独立工具连接器，不是知识加载的前提。

任务与 Agent 范围 → 本地候选匹配 → Skill 激活/工具发现 → 权限检查 → 单轮上下文与 schema 预算 → 原生工具调用 → 证据与状态更新 → 下轮重规划。

常规轮次不额外调用规划模型；低置信度时由当前模型使用轻量发现入口。完整目录留在主进程，默认投影上限 8、扩展上限 16（包含引导工具）；上限不是必须填满的数量。远程语义排序仍遵从现有 opt-in。

## 安全和兼容

默认 Agent 绑定与任务临时授权区别于硬治理边界。明确拒绝、父级约束、禁用与 no-tools 阶段不能被授权覆盖。发现不等于可执行，执行不等于验收完成。外部操作批准绑定具体参数和目标，草稿准备不重复审批。

HTTP 初始地址及每次重定向必须保持配置源，禁止通过绝对 URL 绕过。结果不确定的非幂等写操作不得自动重放。

Skill 正文保持受限协作上下文，外部描述和知识片段保持不可信数据。必要指令不静默截断，大资源采用有界读取与可续读引用。最终完成状态以有效执行契约及真实证据为准。

## 性能与观测

仅按需加载正文、资源和连接器定义，缓存须受来源/权限/配置版本约束。诊断不记录密钥或默认上传正文。基线对照完整 schema 与选择后 schema 的 token、发现成功率和延迟；没有真实测量不得承诺收益。

## 发布

安全修复先行，再接入范围/发现、上下文、恢复体验。安全门禁不随选择策略回退而撤销。先验证伙伴、产品经理、生图专家，再扩展其余场景。真实外部读写只在已授权的测试资源执行。

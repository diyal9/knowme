# 开发自审

## 已检查

- Knowledge OS 仍由主进程负责文件路径校验、hash 校验、原子写入和索引刷新。
- Renderer 只通过 preload IPC 读取任务/提案和触发用户动作，没有引入 `fs`。
- 原始 LLM Wiki 不被自动覆盖；接受前来源变化会阻止提交。
- 整理、审核、写入使用独立的任务和 proposal 状态，拒绝与稍后处理只更新状态。
- 知识管家 Agent 工具明确区分 read、propose 和 confirmation-gated write。
- 知识页面在窄窗口下将审核列表和内容纵向堆叠，保留资料浏览与知识源入口。
- 无新增第三方依赖；启动性能只读取知识摘要和任务元数据，不在页面首屏调用模型。

## 待角色复核

- 制作人：确认“AI 整理 → 审核 → 写入”的下一步是否足够明确。
- 测试：重点复核空态、来源变化、越权路径、拒绝不写入和窄窗口操作。

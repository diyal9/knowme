## Context

当前 Knowledge OS 已能绑定本地 Wiki、建立索引、执行规则体检、检索命中和生成单条升格草稿，但知识面板仍以浏览为默认主流程。渲染进程通过 preload IPC 访问主进程知识能力；Agent 已有只读 `search_knowledge`，而 ingest、lint 和 promote 主要由知识管家模板或 Work Surface 分散触发。

本设计将原始 LLM Wiki 视为受保护的输入源，将 AI 整理结果视为可审核提案，将用户接受后的概念视为正式知识。实现必须保持 Electron 主进程负责文件 IO 和任务状态，渲染进程只负责展示与用户操作。

## Goals / Non-Goals

**Goals:**

- 将知识面板改为状态驱动的 AI 整理工作台。
- 支持按范围启动可恢复的批量分析任务，并生成可追溯提案。
- 支持逐条和批量审核，拒绝或取消时不改变正式知识。
- 让体检问题、来源和提案可以互相定位。
- 接受后自动刷新索引、体检并让 Agent 检索到结果。

**Non-Goals:**

- 不覆盖原始 LLM Wiki，不实现无审核自动写入。
- 不在本变更中实现完整 Markdown 编辑器或 Obsidian 图谱。
- 不重做远程 RAG 和飞书连接器。
- 不把全部历史资料一次性迁移到新目录。

## Decisions

### 1. 采用任务状态机，不把长任务塞进页面点击回调

任务状态使用 `idle → scanning → analyzing → review → committing → completed/failed/cancelled`。主进程持久化任务摘要、选定范围、进度、错误和 proposal 引用；渲染进程通过 IPC 查询和订阅状态。

选择状态机而不是一次性 IPC 的原因是批量 LLM 分析可能超过页面生命周期，需要取消、重试和恢复。任务记录只保存元数据和提案文件引用，不把大量正文塞进窗口状态。

### 2. AI 只产生 proposal，用户确认后才写盘

每条 proposal 包含来源路径、来源 hash、目标分类、建议正文、变更摘要、置信度、理由和状态。正式写入前重新比较来源 hash；来源发生变化时标记冲突并阻止静默覆盖。

选择 proposal 而不是直接写入的原因是原始 LLM Wiki 必须可回溯，且模型输出可能存在错误、重复或冲突。

### 3. 复用现有 Knowledge OS 文件边界

所有读取和写入都通过 `knowledge-os`，由主进程解析 Wiki 根、校验授权 Source、执行原子写入和刷新索引。渲染进程不接触 `fs`，不获得绝对路径写入能力。

现有 `ingest`、`lintWiki`、`promoteToOkfDraft` 和 `acceptWrite` 作为底层能力；新增批量任务和 proposal 编排，不复制另一套文件系统。

### 4. 页面采用“整理优先、浏览辅助”的信息架构

知识面板保留现有全页模式，但默认显示：

- 当前 LLM Wiki 名称、资料数、已整理数、待审核数和最后同步时间；
- 主操作“开始 AI 整理”；
- 当前状态下唯一的下一步；
- 待审核提案和体检问题入口。

资料树、来源配置和 Obsidian 继续保留为次级入口。长任务使用页面内任务面板，不使用层层 modal。

### 5. Agent 与页面共用同一套任务和检索结果

知识管家模板、知识页主按钮和 Agent 工具都调用同一任务服务。Agent 的知识检索继续使用 active provider；接受提案后必须刷新同一索引，避免页面计数和 Agent 结果不一致。

### 6. 增量优先，避免启动性能回退

默认整理范围为新增或变更文件；全库扫描由用户显式触发。索引扫描、hash 计算和提案持久化分批执行，并在任务状态中报告进度。打开知识面板只读取摘要和任务元数据，不在首屏同步调用模型。

## Risks / Trade-offs

- [模型分析耗时或失败] → 每批限制文件数，记录失败项，支持重试和恢复，不影响已完成提案。
- [源文件在审核期间变化] → 保存来源 hash，提交前重新校验并将变化项转为冲突。
- [批量提案过多造成审核压力] → 默认按主题聚合，提供高置信度批量接受，但仍保留逐条查看。
- [已有知识面板测试依赖旧首屏文案] → 先更新行为测试和 OpenSpec 证据，再做 UI 文案替换。
- [旧的知识管家入口与新页面语义冲突] → 统一入口到同一任务服务，保留旧模板作为兼容触发器，不再提示用户手动粘贴到不存在的面板。

## Migration Plan

1. 先新增任务、proposal 和 IPC 能力，不改变现有浏览与检索路径。
2. 增加新页面首页和审核视图，旧浏览页作为“资料浏览”保留。
3. 将知识管家 ingest/promote 模板接到任务服务，并清理冲突文案。
4. 对新建任务使用新状态数据；没有历史任务时按现有 Wiki 索引初始化为“待分析”。
5. 若任务服务失败，页面回退到只读浏览和现有体检，不阻断知识检索。

## Open Questions

无。批量整理采用用户确认后写入，原始 LLM Wiki 保持不变。

## Context

左侧 rail 的入口顺序由 `src/workspace.html` 中的 DOM 分组决定。能力 Hub 当前位于独立分隔组，自动化位于顶部主导航组；两者的事件绑定和选中态均通过稳定 ID 获取，与父容器无耦合。

本变更只涉及渲染进程静态布局，不触及 Electron 主进程、预加载脚本或 IPC；因此不会增加启动成本或常驻内存。

## Goals / Non-Goals

**Goals:**

- 以最小 DOM 调整互换能力 Hub 与自动化的视觉位置。
- 保持现有 ID、图标、无障碍属性、事件绑定和选中态逻辑。
- 用静态契约测试锁定新的入口顺序及分组。

**Non-Goals:**

- 不重构 rail 组件或导航状态管理。
- 不修改主进程、IPC 和页面内部业务。

## Decisions

### 直接移动现有按钮节点

将 `btnRailCapabilities` 移入顶部主导航并放在 `btnRailWorkbench` 后；将 `btnRailAutomation` 移入分隔组。保持按钮本身不变，可避免事件与状态回归。

备选方案是用 CSS `order` 只改变视觉顺序，但 DOM、键盘浏览和无障碍阅读顺序仍会保留旧结构，因此不采用。

### 将分隔组语义改为自动化

保留现有分隔组样式，同时将 toolbar 的无障碍标签改为“自动化中心”，使容器语义与其内容一致。CSS 类名暂不重命名，以避免与纯视觉需求无关的扩散改动。

## Risks / Trade-offs

- [静态测试仅检查 DOM 契约，无法覆盖最终像素布局] → 结合本地界面截图确认分隔线和顺序。
- [历史 CSS 类名 `rail-capabilities` 与新内容不一致] → 类名仅为内部样式钩子，保留可控制改动范围；后续组件化时再统一命名。

## Migration Plan

无需数据迁移。回滚时恢复两个按钮的原 DOM 分组与顺序即可。

# 专家组合治理、分类认证与生产可用性

## 目标

以用户任务域和真实专业闭环治理 KnowMe 专家体系，不再把当前每个角色都强行修成专家。先对全部内置专家做分类与去重，形成“保留专家、合并到专家、降级为 Skill、转为工作流”四类处置；再只对最终保留的专家执行严格生产资格认证。

平台继续提供通用编排、工具、权限、上下文、成果物和生命周期能力。专业方法、判断标准和异常闭环归 Agent/Skill 包所有，不为单个专家在 KnowMe 运行时增加身份特判。

## 专家资格原则

一个角色只有同时满足以下条件才保留专家身份：

- 需要持续上下文和多轮专业判断；
- 具有独立且不可替代的职责边界；
- 具有专属工具、权限、知识或方法闭环；
- 能独立完成规划、执行、验证、修改和恢复；
- 能通过正常、边界、失败、重试、修改和重开测试。

一次性内容变换优先成为 Skill；固定步骤编排优先成为工作流；与核心专家重叠的角色合并为该专家的执行模式。没有证据证明满足门槛的角色不得使用“专家”称谓。

## 范围与边界

- 以当前 22 个内置专家为治理全集；用户自定义或外部专家单独评估，绝不自动删除。
- 当前基线收敛为 6 个保留专家、12 个合并角色、3 个 Skill-only 角色和 1 个平台工作流角色，详见 `expert-portfolio-governance.json`。
- 合并或降级不等于删除能力：原专业方法必须由目标专家 Skill、通用 Skill 或平台工作流承接。
- 退出目录前必须迁移工作流、模式绑定与用户入口；退出内置专家的安装、任务与包直接清理，不再保留只读兼容负担。
- 每个保留专家至少覆盖专业正常任务、缺少/矛盾输入、依赖/工具异常、反馈修改、验收及重进恢复。相关飞书、知识、代码和文件生成必须有真实证据。
- 平台提供通用权限、工具、资源、上下文、状态与交互契约；专业方法与产出评价归 Agent 包，不引入专家 ID 特判兼容。
- 外部发送/发布/删除及生产系统变更用隔离测试对象与明确授权；不向真实同事发送测试垃圾、不拿私有资料发往未授权服务。
- 质量结论分为静态契约、隔离回归、真实模型/工具、人工专业评价、真实 UI；任一缺项都不能标记该专家生产通过。

## 完成定义

- 22 个内置专家均有经过验证的处置决定、能力承接目标和迁移影响记录。
- 退出专家身份的角色完成入口、绑定和依赖迁移，内置历史安装、任务与包完成清理；用户自定义专家不受影响。
- 最终保留专家逐项具备可追溯任务、输入、输出、SOP 检查、异常/恢复结果和页面证据。
- 修复后的全量门禁通过；主要专业交付由结果本身和独立评价证明，不由模型自评证明。
- 未迁移、未测试或未通过的角色明确标为受限，不冒充生产级专家。

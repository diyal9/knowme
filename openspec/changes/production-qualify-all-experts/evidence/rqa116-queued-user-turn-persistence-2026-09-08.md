# RQA116：执行中用户补充的对话持久化

## 问题

用户在专家仍处于 `starting`、`running` 或 `revising` 时提交的补充内容，会被运行时保存为 `input_queued`。此前协作叙事只把 `input_provided` 识别为用户回合，导致这类内容在对话中被误归为专家更新，或无法以清晰的用户消息呈现。

## 修正

- 将通用事件 `input_queued` 纳入专家协作叙事的用户事件集合。
- 将 `input_queued` 纳入专家任务时间线的用户角色和“用户确认”分类。
- 增加稳定的用户可读事件标签“已收到补充信息”。
- 保持任务材料、输入队列和执行调度逻辑不变；只修正事件在对话/时间线中的语义投影。

## 验证

- 专家叙事定向回归：`12/12` 通过（含执行中补充内容作为用户回合）。
- 专家房真实渲染回归：`68/68` 通过；页面实际展示为“我 + 用户补充内容”，未重复塞入过程标签。
- 后端全量：`3514` 项，`3463` 通过、`51` 跳过、`0` 失败。
- Renderer 全量：`86` 个文件、`624` 项通过。
- `npm run lint`：通过；仅保留既有文件长度 advisory warning。
- `npm run typecheck:renderer`：通过。
- `git diff --check`：通过；仅报告共享工作区既有 Windows CRLF 规范化提示。

## 边界

本修复证明用户补充内容在通用任务活动流中的可见性和持久化语义，不代表真实 Provider、联网/飞书连接器或生图内容质量已通过生产资格；当前 `executionReady` / `productionReady` 仍需真实路线证据和独立专业评审。

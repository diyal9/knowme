## 复现与修复

原 preflightConnectors 在每个连接器的循环内遍历全部 requiredTools。声明 a.read + b.write、连接器 a 仅投影 a.read、b 仅投影 b.write 时，两者分别被要求提供对方工具；calculate 也被错误要求由连接器提供。无连接器则提前成功；缺失 projectedAllowlist 则跳过验证；原始配置 allowlist 被混作实际投影。

先增加隔离状态机测试并运行红灯，再修改源码。红灯涵盖联合工具被误拒、connector + calculate 被误拒、未知投影/空权限/无连接器虚构工具被误放行。测试直接调用 createExpertTaskRuntime 的 execute 和 createStart，不只是源码字符串或 exports 断言。

修复后：

1. 连接器范围取 snapshot 绑定与显式连接器权限的交集；必需依赖仍须通过启用、可见、授权、在线及身份检查。
2. 以实际 status.projectedAllowlist 或 getConnectorTools 返回的已选择投影确认工具归属。配置中的原始 allowlist 不是发现结果；缺失投影不贡献任何工具，显式空投影不回退到猜测。
3. 联合已确认连接器工具与真实内置定义，复用 ToolContractRegistry、buildRunGovernancePolicy、buildToolSurfaceFromRegistry 检查所有 requiredTools。不改变 allowlist/denylist，也不以命名前缀猜归属。
4. 可选绑定可以提供必需工具；无关可选连接器离线不否决完整集合。必需连接器离线仍阻塞。未知投影本身不是通过证明，但其他已确认提供方覆盖完整集合时，不重复要求未知提供方贡献工具。
5. calculate 无连接器可用，但空 allowlist 仍拒绝。连接器不得冒充内置 calculate。重复工具归属、未知工具、未绑定/未授权连接器均阻塞，模型不启动。

## 条件内置工具兼容性

agent-provider-tool-contracts.ts 共享真实生图适配器定义与导入工具定义。生图根据声明提供方及发现结果中的 selected rawName 建立公共别名，不能只靠包声明、未选择的工具或猜测 MCP 前缀放行。

导入工具原有兼容注册路径保留；新增由结构化 requiredTools 触发同一真实工具组的通用入口，预检和正式工具面共享判断，不新增专家 ID 分支。任意专家仍需原有工具授权，写入工具仍保留原审批/显式确认契约。测试以假的 Hub 服务执行真实 preview_external_project handler，并确认空 allowlist 在正式工具面被拒绝；没有扫描真实项目。

当前预检明确支持 knowledge 内置、calculate、声明式导入内置、生图提供方适配器及已发现连接器工具；其他条件式工具若没有可证明的注册来源仍 fail-closed，不将包中的名称当作实现。正式工具面仍再次核验 requiredTools，因此预检不替代最终装配或执行时权限检查。RQA-03 的预检取消/超时问题不在本轮修改范围。

### 包内方法具备什么、缺什么

- `src/catalog/experts/meeting-scribe/EXPERT.md:23` 的 SOP 已要求区分提议/决议、原文锚点、责任/期限/标准未知则待确认。MS-H1/H2违反的是**现有可见 SOP**，不能说包完全没有相关原则。缺的是可操作的逐字段支持检查、主持/承诺角色区分和发布前扫除未标推断；第5步固定列出多种章节，容易在短纪要中重复。
- `src/catalog/experts/data-report-editor/EXPERT.md:20` 的 SOP 已强调比较口径、来源、摘要不藏限制和数字检查，方向专业；“不重新计算”应区分不造新的统计结论与可追溯的基础单位换算，避免绝对/相对变化缺项。第5步预设来源/限制附录，虽第4步禁止摘要藏限制，本题实际没有藏，但固定扩展章节不利于短稿。
- 两个 EXPERT.md:7、简 manifest 以及 capability manifest dependencies 都仅绑定 `writing-polish`。该 Skill 的 `SKILL.md:15` 规定完整润色稿后可再解释三点，`:23` 只有“不改变原意、不虚构事实”。它是通用编辑辅助，不包含会议承诺归属或数据推断边界的细化步骤；把它写长不等于补齐领域方法。
- meeting-scribe capability manifest:56 与 data-report-editor:47 各有两个 required answer（output-1/output-2），结构内容重叠，没有合并指示；短稿默认容易多成果，但本次用户指定 primary，因此观察到的实际均为单成果，不能把风险说成已经重复两份。

### 装配事实，不用错误的 requiredSkills 归因

1. **当前这两个 capability manifest 根本没有 deliverable/route 层 requiredSkills**。dependency.required=true 表示依赖要求，不等价于执行必需的 L1 方法。
2. `expert-execution-profile.ts:62` 按交付ID合约匹配，只有请求与声明都为单项时才单项回退。primary与两个默认ID不匹配确实是问题；但即使默认ID匹配，这两个包仍没有 requiredSkills，因此**不能把它们的 L1 缺口仅归因于ID不匹配**。
3. `expert-execution-profile.ts:53`/`:101` 从合约/route合并 requiredSkills；`expert-task-runtime.ts:316` 预检该列表，`:559` 以 outputSpec.requiredSkills 传 skillRefs；`agent-context-assembly.ts:217` 附近自动匹配只生成L0，`:224`之后显式refs才 loadSkillL1。这是必需方法装配与依赖安装的区别。
4. MS01 retry的user消息明确包含canonical systemPrompt与5步SOP，责任/决议约束是可见的。该消息不是完整provider request dump，不能据其缺少 Skill 正文就绝对断言所有系统上下文都无该正文。批次说明记载未提升L1，但 MS/DR 独立 skillRefs/hash/truncated 回执没有收齐；DR基线还缺完整组装prompt。应把方法接收情况写为证据不充分，而非“已完整L1并被证明无效”。
5. MS01初次被飞书工具挡住属平台工具契约误推导；飞书在包依赖中是 optional，tools.allowlist为空，给定全转写且禁止外部动作不应成为外部工具义务。retry能交付证明本路径恢复，不能证明其他入口都恢复。当前领域输出硬伤则是另一条质量轴。

## 最小通用方法改进建议（本轮不实施）

优先少量操作规则，不写针对陈琳、星期三、10%→12%或N/P的题目补丁；不增加工具/网络权限。先用相同装配条件验证收益，再决定是否抽成独立领域 Skill。

会议方法仅需三条：

1. 内部按“事项状态—原文位置—承诺者—期限—条件”核对；每个责任/期限字段都要能由对应发言支持。发言者、主持人、参加者不自动成为负责人；建议与接受/决议分开，未确定字段保留待确认。
2. 相对日期只锚定材料会议日期；无精确钟点不擅补。把后续条件、依赖、风险再扫一遍，找不到原文支持的确定规则删除，必要推断明确标记，不混入决议表。
3. 按用户长度只交付一份纪要+必要行动表；有字数压力先删重复背景/重复待确认说明，不删责任、条件、证据锚点。

数据报告方法仅需三条：

1. 为每项结论核对“指标/分子分母—两期时间—范围/口径—原文位置”。需要双口径时以给定数值可复算的算式标绝对与相对变化，零基线/不可比口径说明不可计算；不生成新检验或分析数据。
2. 同一管理阅读单元保留结论强度与限制；建议写成下一步证据需求，不把描述变化升级为归因/显著/ROI。交付前查来源名、段号、时间和附加说明是否确实存在，新增建议与来源事实分开。
3. 先给摘要分配长度、再分配全文；全文交付前用冻结计数器复核，避免同一限制重复四次。不要固定附录或润色说明挤占用户预算。

装配是前置验收，不是扩写理由：若决定某方法必需，应在对应执行合约显式声明 requiredSkills，并取得同run的实际 skillRefs、内容hash、截断信息；一份用户答复与默认交付须明确对应。不能仅证明“依赖已安装”就宣布方法已送达；也不能借此把只读任务升级为必需外部工具。

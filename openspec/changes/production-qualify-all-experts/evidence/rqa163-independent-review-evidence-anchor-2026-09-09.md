# RQA163：独立专业评审证据锚点门禁

日期：2026-09-09

## 目的

修正独立专业评审只校验 `evidence` 字段非空的质量漏洞。评审现在必须把每条用户要求和断言绑定到实际助手输出或真实产物，避免用形式完整但不可核验的文字放行专家资格。

## 契约

- 文本证据必须提供 `evidenceQuote`，并且原文必须出现在当前任务的助手消息或文本成果物中；用户提问不会作为证据来源。
- 图片等二进制成果物可以提供 `evidenceRef`，且 ID 必须命中当前任务导出的成果物；如果引用的是文本成果物，仍必须提供原文摘录。
- 摘录经过有限空白归一化，最少 8 个非空白字符；找不到锚点、引用不存在的成果物或缺少锚点时拒绝评审。
- 评审结论仍同时受生命周期通过条件约束，证据锚点通过不等于自动获得生产资格。

## 验证结果

`tests/expert-semantic-review.test.js`：`8/8` 通过，覆盖：

- 合法助手输出摘录通过；
- 用户提示词不能冒充助手证据；
- 候选输出中不存在的摘录被拒绝；
- 二进制图片成果物可用稳定 ID 进行锚定；
- 原有评审覆盖、断言顺序、独立模型和生命周期门禁保持有效。

全量后端串行复跑：`3550` 项，`3499` 通过、`51` 跳过、`0` 失败；lint 通过。并行默认测试曾出现 `web-fetch` 本地网络夹具竞争，单文件复跑与串行全量均通过，属于测试调度环境问题，不是本次改动失败。

## 资格边界

当前六个保留专家的历史资格报告尚未重新生成独立评审文档，因此不创建伪造的评审通过记录。真实 Provider、真实 Feishu/Pango/网络回执及独立专业评审仍是 `productionReady` 的剩余门槛。

# RQA153：文本夹具输出质量边界审查

日期：2026-09-09

## 发现

审读 RQA152 生成的隔离资格报告后确认，本地文本夹具的候选回复主要是：

> 已根据当前任务材料完成一轮结构化处理。

它带有任务摘要和运行事件，但没有真正交付题目要求的 PRD、分析报告、架构决策或测试计划正文。因而：

- 生命周期状态可以正确进入 `review`；
- 任务、路由、交付物和执行证据可以正确持久化；
- 但不能据此判断专家是否满足专业断言；
- 不能创建独立语义评审并将其标记为通过。

## 处理结论

本次不修改通用完成协议来硬编码某一类文档章节。将“必需章节/专业断言”直接下沉到通用完成门禁会影响多个 Agent 执行流程，且当前影响分析将 `validateExecutionCompletion` 判为 CRITICAL（4 个直接调用、2 条执行流程、16 个受影响符号）。

当前保持以下边界：

1. 通用运行时只负责路由、工具/成果物证据、状态和生命周期闭环；
2. 专业正文是否合格由 Agent/Skill 声明的质量复核与独立专业评审判断；
3. 本地夹具只作为运行时和异常闭环证据，不能冒充模型专业输出；
4. 真实生产资格必须使用真实模型输出，并逐条完成独立语义评审。

## 下一步

产品级认证不能由当前文本夹具单独完成。应在可用的真实模型环境中重跑 PM、DA、SE 套件，保存完整候选正文，再提交与执行模型/供应商隔离的独立评审；若真实输出仍是占位摘要，则应修正对应 Agent/Skill，而不是放宽资格门禁。

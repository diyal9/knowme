# RQA56：视觉设计与生图专家深度整改

日期：2026-09-07  
结论：两位专家完成专业方法、依赖更新和通用能力同步整改；尚未通过真实模型、生图服务和完整修改闭环复验，不授予生产资格。

## 1. 能力判断

- `visual-designer 2.3.0` 不再只交付字段清单。必需的 `visual-brief-prompt 2.1.0` 已覆盖视觉主张、信息层级、视觉路径、构图与裁切、多比例安全区、缩略图识别、色彩/光线/材质、可访问性、字体/品牌/版权状态、参考图角色、正负 Prompt、可测验收与修改保留集。
- `image-producer 3.5.0` 的三项必需 Skill 均升至 `1.1.0`：需求受理区分已知/假设/阻塞，Prompt 编译明确约束优先级与参考图映射，生成方法要求真实工具回执、图片 artifact 和可解码文件三重证据。
- 生图专家不得从参数或文件名臆测视觉质量；必须观察真实图片。失败或返回状态未知时不得自动重试，避免重复计费或产生不可见的重复结果。
- 两个专家各自声明四项 package-owned `qualityReview`，用于完整答案复核；平台仍只提供通用编排、工具账本、成果物和复核契约，没有新增专家 ID 分支。

## 2. 通用包管理修复

隔离环境中，用户链接的同名 Skill 会覆盖目录视图，旧实现因此误判“内置依赖不可同步”并阻断专家升级。通用同步逻辑现先读取已安装来源：

- 用户/仓库链接 Skill 保持原文件和版本，不被内置包覆盖；
- 只给出 `dependency_update_not_managed` 提示；
- 内置或缺失依赖继续按目录安装/升级；
- kind 不匹配仍硬失败。

新增回归覆盖三项同名链接 Skill，确认专家可升级、用户内容不变且提示准确。

## 4. 资格边界

尚缺可用模型 Key 与真实生图服务的付费/外部执行证据，没有重新完成视觉 Brief 确认、首轮真实图片、失败回执、修改保留集、二次生成、成果验收和刷新重开全链路。图片预览与完整对话体验也尚未在本轮用真实新产物复验。因此 `visual-designer` 与 `image-producer` 均继续标记为“不合格/待复验”。

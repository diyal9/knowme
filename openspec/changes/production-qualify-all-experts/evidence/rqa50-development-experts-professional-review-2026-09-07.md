# RQA50：软件工程与解决方案架构专业复核

日期：2026-09-07  
结论：两位开发域专家完成包级完整答案复核与隔离安装验证；本轮没有真实模型复验，不授予生产资格。

## 1. 归因与整改边界

- `software-engineer 2.1.0` 的实际答案曾有与给定控制流不成立的库存/并发故事、缺少重复区间和失败不变性测试、把未知覆盖写成缺失，以及无依据的 100k/50ms 性能承诺。
- `solution-architect 2.1.0` 的 SA-N01 实际答案为 1/5：误算 TTL 边界、缺少任务开始后到结果交付前的资格复检、回滚会重新引入已否决的安全策略，并无依据承诺两人四周足够。
- `software-change-verification 1.0.0` 与 `architecture-decision 1.0.0` 已覆盖控制流、失效时序、验证、时间权威、迁移和回滚，因此不再扩写 Skill。整改集中在模型首次完整答案的遵循与自检。

KnowMe 没有新增开发专家特判；复核继续通过通用 package-owned `qualityReview` 执行，权限不扩大。

## 2. software-engineer 2.2.0

- 完整答案复核必须按材料/代码重放控制流、分支可达性、读写时序和最终状态。
- 测试设计逐项覆盖验收、边界、失败不变性和给定反例；审查者补测不能补原答案分。
- 性能、耗时、规模、测试通过和完成声明必须有本轮执行回执，否则只写目标或待验证。
- 代码、注释、测试、风险和结论必须完整一致，禁止未完成句、截断代码或把静态方案写成已落地。

## 3. solution-architect 2.2.0

- 对时间、TTL、起算点、误差和边界事件逐项复算，不把合法边界误判为违约。
- 安全保证覆盖开始资格、执行中变化和结果交付前复检，不能只做入口检查。
- 迁移、灰度和回滚保持相同的权威版本、安全门禁与拒绝策略。
- 人力、工期、成本、性能和容量没有材料/计算/测量时只可写成假设、待测目标或条件分支。

## 4. 安装与测试

- 新契约红测初始 1/3 通过、2/3 失败；实施后 3/3 通过。
- 方法装配、输出合并、自定义交付身份、可选 Skill 隔离和通用复核组合：38/38 通过。
- 隔离运行时更新成功：`software-engineer 2.2.0` 与 `solution-architect 2.2.0` 均 installed/enabled，四项复核进入实际快照，warnings 和 dependencyUpdates 均为空。
- 最终 `npm run check` exit 0：后端 3477 passed / 51 skipped / 0 failed；渲染层 86 files、606 tests 全绿；lint 与 renderer typecheck 通过。

## 5. 资格边界

以上证据证明包、装配、安装和通用复核链路正确，不证明模型已修复 SE-N01/SE-H02 或 SA-N01/SA-H02 的专业错误。仍需真实复跑旧失败题、同机制留出题、失败/重试、用户反馈修订与重开验收。两位继续标记为“不合格/待复验”。

# RQA82 — 运行阶段不再重复渲染为专家对话

日期：2026-09-08

## 问题

任务运行时会产生 `stage_prepare` 等技术阶段事件。协作叙事此前只识别普通 `progress`/`tool_progress`，未识别这些阶段事件，因此“上下文准备完成”可能同时出现在对话流和状态区域，造成重复、像额外的一条专家回复。

## 修复

- 将 `stage_prepare`、工具加载、知识检索、依据核对、输出验证、生成和兼容性阶段统一归入通用进度聚合，不作为新的专家对话轮次。
- 保留最新阶段作为用户可见进展，并将连续阶段折叠到“查看已完成的工作”中；不改变底层运行事件、审计和工具回执。
- 不增加专家 ID 分支，所有使用统一任务事件协议的专家房均适用。

## 验证

- 新增“上下文准备阶段不重复渲染”为回归用例，通过。
- 专家房定向套件单独重跑：68/68 通过。
- 与该变更相关的叙事测试：6/6 通过。
- 全量 `npm run check` 通过：后端 3481 项（3430 pass / 51 skip / 0 fail），Renderer 86 文件、613 项，lint、CSS cascade、脚本作用域和 Renderer 类型检查通过。

## 边界

该修复只治理通用对话呈现，不改变阶段状态机或外部能力执行结果；真实 Provider、生图服务和专家专业质量仍需独立资格验证。

# RQA81 — 专家房统一顶部状态与执行动效

日期：2026-09-08

## 问题

专家协作房存在两条互相竞争的状态展示路径：顶部 `DialogueStatusBar` 已具备状态文案和运行中圆点动效，但 `ExpertTaskRoom` 没有把当前任务状态传入；同时页面底部又使用了第二个 `role="status"` 状态条。结果是用户在专家执行期间看不到稳定的“正在工作”状态，刷新或切换阶段后状态位置也不一致。

## 修复

- `ExpertTaskRoom` 将专家名称、去掉 `task-` 前缀的任务编号、当前状态焦点和统一状态色调传入顶部 `DialogueStatusBar`。
- 运行中状态使用已有的 `tone-running` 脉冲圆点，失败/心跳过期为失败态，完成为成功态，其余为等待态。
- 底部状态区域保留执行详情和操作，但改为 `role="group"`，顶部成为唯一的主状态语义出口，避免重复播报和视觉竞争。
- 沿用通用任务状态映射，不增加任何专家 ID 分支；这套契约同样适用于其他专家和任务房。

## 边界

本修复解决的是通用专家房的状态可见性、动效和语义重复问题，不代表外部 Provider、真实生图连接器或任一专家已经取得生产资格。真实能力执行和独立专业质量评审仍需在具备相应外部能力的隔离环境完成。

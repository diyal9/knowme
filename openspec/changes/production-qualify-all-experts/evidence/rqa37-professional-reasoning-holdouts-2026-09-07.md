# RQA37 专业推理留出题与修改闭环证据（2026-09-07）

## 结论

本轮没有新增“生产合格专家”。三位候选均能完成 KnowMe 的任务创建、执行、落库、重开和待验收展示，但真实留出题证明：运行到 `review` 只表示交付链路完成，不表示专业质量合格。

- `action-owner`：不合格。关键实体纠错和证据边界正确，但把尚未触发的行动写成“进行中”，且 1035 字超过 650 字。
- `requirement-reviewer`：不合格。规则集合判断基本正确，但首版 1829 字并臆造协议/工具/阈值；按主输入框修改后的 v2 仍有 1732 字，并保留题面没有的 UI 设计建议。
- `qa-engineer`：待复验。高风险状态、崩溃窗口、幂等和证据设计较完整，但“两个请求都在检查点看到 generation=20”的屏障描述可能拆开了题面要求的原子检查与更新，不能凭一次样本认证。

因此，24 位专家的总目标继续保持 ACTIVE。本轮只把三位专家从“静态能力包候选”推进到“有真实专业证据的候选/不合格状态”。

## 范围与独立性

- 环境：隔离 KnowMe QA userData；未触及日常 `%APPDATA%\KnowMe`。
- 外部动作：0 次；未联网、未调用连接器、未写外部系统。
- 留出题在执行前冻结于 `skill-evals/rqa37-professional-reasoning-workspace/evals.json`。
- 评审独立性限制：当前没有可用的独立子 Agent 执行面，留出题由主 Agent 编写并按逐条可观察断言评分；因此所有结论都保留任务 ID、原文和逐项证据，不把本轮评分当最终认证。

## 通用运行时门禁缺陷与修复

真实 RR03 在到达专业答复前连续暴露三类误拦截；均按通用语义修复，没有按专家 ID 加分支：

1. 题面中的领域状态“已删除”被误判为 Agent 声称自己执行了删除。现在仅第一人称/明确本次操作的删除声明要求回执；显式必需删除工具仍受工具门禁。
2. Agent 自己写的“评审结论”被误判为外部事实。现在无外部归因、无引用的本地评审判断可通过；“客户/会议已批准”等外部归因仍要求来源。
3. 材料内声明的 `[R1]`—`[R6]` 被误判为未知外部来源。现在唯一、就地声明的行标签映射到包含它的材料；未知标签和跨材料重复标签仍被阻断。

相关回归覆盖第一人称删除、必需工具、外部批准、未知/歧义标签等安全反例，未以放宽所有核验换取通过。

# RQA46–47：质量测试与知识策展专业复核闭环

日期：2026-09-07  
结论：两位历史最低分专家完成包级整改与隔离更新验证；本轮没有真实模型专业复验，不授予生产资格。

## 1. 选择与归因

- `qa-engineer` 在 2.3/2.4/2.5 三轮实际任务中依次为 2/5、2/5、1/5。已有 `qa-test-design` 1.4.0 已明确状态机、并发控制点、未知规则和约 1200 字边界；失败来自模型在完整答案中继续补造数据库、事务、HTTP、锁/CAS、TTL、记录和假设终态。继续扩写 Skill 会增加上下文负担，不能解决遵循问题。
- `knowledge-curator` 的 KC04 为 1/5，核心错误是把材料未提供的知识库归属、权限、现行状态、排序、责任部门和治理时限写成事实。其方法虽有来源台账，但缺少字段级证据状态，专业方法本身仍有缺口。

整改仍遵守平台边界：专业规则归 Expert/Skill 包；KnowMe 只执行既有通用 `qualityReview`、依赖更新和权限合同，没有新增专家 ID 分支。

## 2. RQA46：qa-engineer 2.6.0

- 保留 `qa-test-design` 1.4.0，不再堆 SOP 或提升 Skill 版本。
- 新增包声明全文复核，要求每个预期回指需求/状态机/证据，并从完整答案的主表、附注、缺口和发布建议中删除题外实现假设。
- 显式核对精简/字数要求；默认约 1200 汉字、一张主表、最多三条缺口。
- 权限仍为空工具、空连接器，network/write/externalWrite 均为 false。

隔离运行时 `capabilityUpdate(qa-engineer)` 成功：2.6.0 installed/enabled，四项 qualityReview 进入安装快照，warnings 与 dependencyUpdates 均为空。

## 3. RQA47：knowledge-curator 2.2.0 / knowledge-curation-method 1.1.0

- 来源台账新增逐字段证据状态：`已提供`、`可观察`、`待确认`、`建议`。
- 责任人、权限、地域/知识库归属、现行/失效状态、优先级、复核日期和保留期不得由文件名、目录或行业惯例默认推断。
- 包级全文复核覆盖来源、重复/冲突/过期结论强度，以及台账、表格、摘要、生命周期与权限风险中的事实—建议一致性。

隔离运行时 `capabilityUpdate(knowledge-curator)` 成功：expert 2.2.0 installed/enabled；必需 Skill 自动从 1.0.0 升到 1.1.0；warnings 为空，dependencyUpdates 准确记录该升级。

## 4. 测试证据

- 新冻结契约初始 2/5 通过、3/5 失败；实施后 5/5 通过。
- 包、目录、依赖升级、通用运行时与全专家矩阵组合：87/87 通过。
- 首次全量检查发现一个 RQA37 历史测试写死 QA 2.5.0；迁移为当前 2.6.0 后，相关 8/8 通过。
- 最终 `npm run check` exit 0：后端 3470 passed / 51 skipped / 0 failed；渲染层 86 files、606 tests 全绿；lint 与 renderer typecheck 通过。

## 5. 资格边界

安装成功、测试全绿和复核合同存在，只证明包与平台执行链路具备候选能力，不证明当前模型一定会删除臆测或正确保持字段证据状态。必须重新执行 QA 旧失败题及同机制留出题、KC04/KC05 及变体，并完成反馈续作、异常与重开验收后，才能进入资格判断。两位继续标记为“不合格/待复验”。

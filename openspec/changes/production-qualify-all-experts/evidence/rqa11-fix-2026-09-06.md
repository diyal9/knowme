## 实现边界

1. **统一内部过滤。** 先按 allowlist、denylist、expertToolNames、connectorId / mcpConnectorId 与编排限制过滤候选，再做工具预算裁剪，避免拒绝工具挤掉获准工具。definitions 与 records 同源，isAllowedTool 与词法 validator 共用授权判断，实际执行仍先走该 validator。
2. **保留真实契约。** 不伪造 metadata。既有部分 legacy knowledge builtin 的契约字段不完整，本轮仅统一其权限过滤；v1 仍通过原 registry 做契约注册、参数 schema、执行封装、审计与审批/资源路径，未替换这些机制。
3. **权限来源不丢失。** run / deps / session / canonical manifest 的显式 allowlist 与连接器列表取交集，denylist 取并集。缺失数组维持普通伙伴既有默认；显式 [] 拒绝全部。空 payload 不再抹掉已有 session 工具限制，canonical snapshot-only 权限也参与治理。
4. **分支候选仍不同。** 不为 minimal 强行构造完整文件/连接器工具集。legacy 保留原候选限制，通过 surface.withGovernancePolicy 内部重建闭包，保留 collector handler 与 close 生命周期，不做公开方法 override。真实 connector collector 即使不理解新策略，最终面仍受约束。
5. **策略不被依赖上下文覆盖。** resolver 的 effective governancePolicy 不被 deps.governancePolicy 覆盖；buildFullToolSurface 有 sparse deps 时仍保留顶层权限声明。
6. **no-tools 是本轮限制。** planning/no-tools 不暴露或执行任何工具，但其临时空工具面不会作为新 deny-all 声明污染后续轮次。
7. **RQA01 控制信封。** builtin 接收 per-call signal；额外 handler 接收第三参数 handlerCtx，包含可信 signal / timeoutMs。注册 handler 的预算适配通过 getRemainingTimeoutMs 与已有预算取较小值。父取消的运行中 relay 由主线 loop 负责；surface 同时保留已取消 deps.signal 的入场拒绝。不从模型 args 获取控制参数，不改恢复策略或强杀机制。

本轮未放宽包 allowlist、连接器选择、文件/知识库资源 ACL、sandbox 网络/写权限、审批或信任确认。工具可调用不等于资源可读；kb_get 的拒绝结果仍保留。没有新增专家 ID 分支。

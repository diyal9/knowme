## 真实格式与资源边界

- 接受并测试：静态 PNG、JPEG、GIF、WebP、AVIF；GIF/WebP 多帧也实测全帧解码。保存通过验证的原始字节，不用转码替换原图。
- SVG 在进入解码器前明确拒绝，避免主动内容/外部资源；APNG 也拒绝，因为当前 PNG 解码器不验证其后续动画帧。TIFF、HEIC、其他格式不在允许列表。AVIF 不接受 large-size/EOF-size 顶层 box；PNG/JPEG/GIF/WebP 容器末尾不完整等情况保守拒绝。不能宣称覆盖所有原声明格式/所有格式变体。
- 单图压缩输入上限 24 MiB；单边 8192；累计解码像素 32×1024×1024（宽×每帧高×帧数）；最多 100 帧；输入通道最多 4。输出固定 sRGB + alpha raw，像素输出预算最多约 128 MiB，**不是进程总内存上限**。
- 进程内最多一个实际验证解码任务，活动+等待最多 4 个；关闭 libvips 保留缓存，failOn:warning、unlimited:false、limitInputPixels 开启。**更正：sharp.timeout({seconds:5}) 不覆盖 metadata/header 解析。** sharp 0.35.4 的 `node_modules/sharp/src/metadata.cc:33` 调用 OpenInput，MetadataBaton 不含 timeoutSeconds；`pipeline.cc:48` 先 OpenInput，到 `pipeline.cc:950` 才 SetTimeout；`common.cc:851`/`:866` 通过像素 eval 进度回调设置 kill。它只约束协作式像素求值，不覆盖头解析、metadata、挂钩之前的工作或 libuv 排队，不是整个任务的硬总超时。
- 不用 Promise.race 假称 CPU 解码被取消。外部取消在排队/metadata 后/raw 完成后检查；正在执行的 native 操作等待返回/原生超时后才释放队列槽，期间不会保存。libvips 超时是协作式停止，**无子进程隔离、无 OS 级硬内存/CPU 限额**；恶意解码器漏洞仍属原生依赖残余风险。

## URL 下载的复用、增加与风险

现有 `web-fetch` 是文本提取接口，不适合无损图片；`capability-import.downloadHttpsBuffer` 先 arrayBuffer 后检查长度且自动跟随重定向，不满足这里的流预算。因此新增图片专用实现，复用 `web-fetch-ssrf.assertSafeUrl`，未复用不受限 buffer 路径。

新实现仅 HTTPS，拒绝 URL 凭据；每跳检查所有 DNS 地址，禁止本机/私网，再让 https.request 的 lookup 返回同一组已验证地址；agent:false 避免复用未经当前校验的连接。相对重定向支持，最多 4 次请求（3 次跳转）；不携带 Pango Authorization/cookie，不转发凭据。请求 identity 编码，拒绝服务端 HTTP 压缩响应，避免隐式解压。

单 URL 总时限最多 15 秒（包括 DNS、重定向和读取），一批 URL 共用 30 秒剩余窗口；读取前查 Content-Length，逐 chunk 累计至最多 24 MiB，超限/取消/超时/重定向立即销毁响应和请求，不无界 arrayBuffer。DNS 自身不可取消；这里只对 DNS 等待使用 race，deadline 后不会再打开连接。外部网络未实测，单测替换 transport/DNS，不伪称 CDN 可达。

仍有边界：私网策略继承既有 SSRF 地址分类；不支持需 cookie/授权的 CDN、HTTP 或压缩 HTTP body。提供商最初的 MCP JSON response.json() 在本轮之前仍无响应字节硬上限；本轮限制从 image 内容进入校验/URL 下载开始，**未解决 JSON 接收前的全链路内存预算**。上游这一点需单独安排，不可把本修复描述成所有网络输入均已受限。

# QA Plan

## Smoke Scope

逐个专家的真实入口 → 输入完整需求/材料 → 适量澄清 → 显示并保存用户确认 → 实际按 SOP 执行 → 对话/文件合理交付 → 主输入框反馈 → 正确修订 → 验收 → 重进。每个案例必须关联专家版本、task/run/artifact 标识。

## 分层证据

1. 静态：专业 SOP、输入输出契约、工具权限与真实启用依赖一致。
2. 隔离：工具成功/空结果/权限拒绝/超时/取消/修复后重试/陈旧异步返回，验证不伪造完成、不丢消息、不重复副作用。
3. 真实：实际模型和工具结果；核对数据、计算、文件内容与引用；没有可访问外部环境的项目标记未完成。
4. 专业：逐个 rubric 而非通用关键词；数值与来源可复查，假设与未知明确，没有明显模板填充。
5. UI：1280×820 与1600×1000；单一输入、头像和内容对齐、阅读行宽、图片完整预览、长段落/表格无横向挤压、键盘可用。

## 反例

通用“已完成”+假文件、所有工具桩返回ok、仅修改manifest、只测一个专家、无真实确认的自动执行、缺资料仍编造交付、生成成功但专业结果错、失败后把旧成果当新版，均不能作为生产通过。

# Code Review：全部专家生产资格

## 当前结论

**阶段工程审查通过，但不批准 24 位专家整体生产放行。** 当前实现已经形成通用执行合同、来源与工具回执门禁、能力依赖更新、统一对话/成果呈现以及包声明专业复核等基础设施；专家专业质量仍必须逐个通过真实任务双轨评测。

## 架构审查

- KnowMe 运行时不按具体专家 ID 分支；任务路线、必需 Skill、工具、证据、成果和专业复核标准由能力包声明。
- 已安装/启用不等于已加载，已加载不等于已执行，已执行不等于专业合格。运行时分别维护依赖预检、L1 方法装配、工具/证据账本、成果合同和验收状态。
- 写操作、审批、未知副作用、失败重试和恢复按通用工具合同处理；文字描述不能冒充工具回执或成果文件。
- 对话、进度、成果和验收是独立语义对象；主输入框承担澄清、确认和修改，不创建专家专属输入路径。

## 本轮 RQA42–43 审查

- 历史执行状态仅允许在明确用户归因且材料存在同状态族时通过；第一人称/current-run 状态仍要求真实回执。
- `qualityReview` 是有界、禁工具、单次的包声明合同；fact-checker 的专业标准位于自身包内，平台没有嵌入事实核查专属规则。
- 内置目录新增依赖闭包测试，阻止专家可更新但 required Skill 不可安装、目录与 sidecar 版本漂移等发布缺陷。
- 复核失败采用 fail closed，不把未复核候选持久化为可验收成果。

## 验证

- 最新 `npm run check`：后端 3459 passed / 51 skipped / 0 failed；渲染层 86 files、606 tests passed；lint 与 typecheck passed。
- `git diff --check` 无空白错误，仅报告共享工作树中 4 个既有 CRLF→LF 提示。
- GitNexus 全共享工作树：338 files、720 changed symbols、172 affected processes，risk=CRITICAL。该结果覆盖长期累积的多人脏改动，不能归因于 RQA42–43；本轮修改的既有高风险符号已分别执行 impact 分析并以聚焦回归约束。
- `openspec:health` 仍为软失败：另一个 active change 缺 qa-plan/evidence，且 active change 数量超过建议值；本 change 原缺 code-review 已由本文件补齐。

## 残余风险与不放行原因

1. 当前隔离环境无可用模型 API Key，RQA43 尚无真实模型 A/B 和修改轮证据。
2. fact-checker 的旧 FC01/FC03 专业失败尚未真实关闭；其他专家也不能因增加 Skill 或结构测试通过而自动晋级。
3. 两个自定义专家不受内置目录结构检查完整覆盖，仍需按相同实战标准取证。
4. 24 位专家的正常、反例、工具失败、重试、修改、重开和视觉验收尚未全部完成。
5. 两个运行时文件超过 1200 行的 advisory 预算，后续应在稳定基线下按职责拆分，不能在当前大脏树中做无关重构。

审查判断：允许继续逐专家资格整改；禁止宣称总体目标完成或生产验收通过。

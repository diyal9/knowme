## 版本并发与崩溃恢复测试用例设计

基于 V1/V2 规则及 E1/E2 证据，设计以下 6 条高风险用例。本轮仅静态分析，所有用例执行状态均为**未执行**。

| ID | 前置条件 | 操作 (可控交错) | 可观察预期 | 执行状态 |
| :--- | :--- | :--- | :--- | :--- |
| **TC-01**<br>冲突拒绝 | 当前 rev=6<br>请求 A: base=5, content=X | 暂停 A 于“条件检查前”<br>提交 B: base=6→7<br>恢复 A | A 返回冲突码(待定)<br>存储仍为 rev=7/B内容<br>A 不得覆盖 B | 未执行 |
| **TC-02**<br>原子性校验 | 当前 rev=6<br>请求 A: base=6, content=Y | 暂停 A 于“持久化后、确认前”<br>重启服务<br>读取数据 | 重启后读取结果为：<br>rev=6/旧内容 **或**<br>rev=7/Y<br>**禁止** rev=6/Y 或 rev=7/旧 | 未执行 |
| **TC-03**<br>串行基线复现 | 当前 rev=6<br>请求 A: base=6, content=x | 正常提交 A<br>重启服务<br>读取数据 | A ack rev=7<br>重启后读取 x/7<br>日志含完整读写断言 | 未执行<br>(对标E1) |
| **TC-04**<br>并发同基冲突 | 当前 rev=6<br>A: base=6/x<br>B: base=6/y | A、B 同时到达<br>服务端按序处理 | 仅一方成功(rev=7)<br>另一方返回冲突<br>最终态无混合内容 | 未执行 |
| **TC-05**<br>崩溃后新写入 | 承接 TC-02<br>若重启后为旧态 | 在旧态基础上<br>提交 C: base=6/z | C 应成功<br>最终态 rev=7/z<br>验证崩溃未破坏后续一致性 | 未执行 |
| **TC-06**<br>自动合并边界 | 当前 rev=6<br>A: base=5/x<br>B: base=6/y | A 因 base 过期失败<br>触发自动合并策略<br>(策略未定义) | 记录实际行为<br>验证是否产生脏写<br>或错误覆盖 y | 未执行<br>(阻塞) |

### 证据范围与发布判断

1.  **材料支持度**：
    *   **E1 (B7/S1)**：仅证明 TC-03（串行+重启）通过。其包含的“读取断言+完整日志”是有效证据，但**不能外推**至并发或崩溃中间态。
    *   **E2 (B6截图)**：**无效证据**。无日志、无用例ID、无环境标识，且“全绿”结论与 V1 冲突响应码未规定的事实矛盾，不可采信。

2.  **关键缺口**：
    *   V1 冲突响应码与自动合并策略未定，导致 TC-01/TC-06 预期结果不可判定。
    *   测试台暂停能力本轮未实际使用，TC-02/TC-04 的交错时序仅为理论设计。

3.  **B7 发布建议**：
    *   **不予通过**。
    *   理由：核心并发路径（TC-04）与崩溃原子性（TC-02）**零执行证据**；唯一有效的 E1 仅覆盖串行场景，无法支撑 V2 的断电保留承诺。需补齐 TC-01~TC-05 的实际执行日志后方可重新评估。

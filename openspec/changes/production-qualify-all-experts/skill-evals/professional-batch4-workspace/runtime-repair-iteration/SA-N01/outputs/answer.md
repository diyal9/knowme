# 架构决策记录：桌面资料检索权限与缓存机制

## 1. 约束冲突与必须拍板的决策点

| 冲突项 | 已批准硬约束 (安全) | 待批准需求 (销售) / 当前建议稿问题 | 决策影响 |
| :--- | :--- | :--- | :--- |
| **撤销时效** | 撤销后 ≤5min 禁止新查询/打开/缓存命中 | A3建议“每10min同步”直接违反；A3“重启从零计时”违反单调性要求 | **保留硬约束**。放弃离线无限期访问，或需显式放宽为“离线宽限期”并重新审批。 |
| **离线可用性** | 无（仅要求诚实客户端不绕过） | 销售要求断网8h可用；A3“离线用上次成功权限”无法区分W1/W2 | **待批准分支**。若坚持8h离线，必须引入“离线授权令牌”或接受“离线只读旧缓存但禁止新搜索”的降级。本ADR按**严格满足硬约束**设计。 |
| **工作区隔离** | W1撤销不得永久影响W2 | A3“合并成一个缓存”导致撤销W1时无法精准失效，只能全清或超时 | **否决A3合并缓存**。必须按 `(account, workspace)` 物理或逻辑分区存储许可与索引元数据。 |
| **性能承诺** | 无基准数据 | A3声称“换独立服务即保P95<200ms” | **标记为未验证假设**。本方案不承诺具体延迟，仅提供可观测接口供后续压测。 |

**核心取舍声明**：本推荐方案优先保障**安全硬约束**与**工作区隔离**，牺牲“完全离线下的实时全文检索能力”。若业务方坚持8小时离线搜索，需另行审批“离线预授权包”方案，该方案将显著增加密钥管理与泄露风险。

## 2. 可行备选方案比较

### 方案 A：短效许可 + 本地加密分区缓存（推荐）
- **机制**：服务端签发 `TTL≤5min` 的签名许可（含 `workspace_id`, `perm_version`）。客户端按 `(user, ws)` 维护独立加密索引分片。每次查询/打开前校验本地许可有效性；过期则拒绝新请求，仅允许读取已解密且在有效期内的内存结果（若有）。
- **适用前提**：网络间歇性可用；能接受离线状态下超过5分钟后无法发起新搜索。
- **失败模式**：时钟漂移导致误判过期（通过单调计时器缓解）；许可重放（通过 `perm_version` 高水位检查缓解）。
- **成本**：中。需改造客户端许可管理模块与服务端签发接口。

### 方案 B：逐次在线授权（无离线能力）
- **机制**：每次搜索/打开均强制调用服务端鉴权接口。本地仅存明文文档副本，不建持久化索引或索引不绑定权限。
- **适用前提**：对离线体验零容忍；网络极其稳定。
- **失败模式**：断网即不可用；服务端压力大。
- **成本**：低。复用现有服务端鉴权，客户端改动小。
- **评价**：严重违背“桌面资料检索”的离线场景预期，仅作为极端安全合规下的兜底。

### 方案 C：离线预授权包（待批准分支）
- **机制**：联网时下载未来N小时的加密许可包。断网期间使用包内许可。撤销时依赖下次联网拉取黑名单或等待包自然过期。
- **冲突**：**无法满足“撤销后≤5min生效”**，除非引入推送通道（超出当前能力范围）。
- **评价**：违反已批准硬约束，**不作为可行备选**，仅在安全负责人书面豁免时效要求时考虑。

**结论**：选择 **方案 A**。它在4周工期、2人团队、不引入新托管服务的约束下，唯一能同时满足“5分钟撤销时效”和“工作区隔离”的可实现路径。

## 3. 组件、数据所有权与关键接口

### 数据所有权与边界
- **服务端（权威源）**：拥有文档版本、用户工作区成员关系、权限版本号 (`perm_version`)。负责签发/撤销许可。
- **客户端（执行者）**：拥有本地索引文件、加密缓存、单调计时器状态。**不拥有**权限的最终解释权，仅做保守校验。
- **信任边界**：许可签名由服务端私钥生成，客户端公钥验签。本地缓存加密密钥绑定 `(user_id, workspace_id)` 且受系统Keychain保护。

### 关键接口契约

#### 1. 服务端：获取/刷新许可
```http
POST /api/v1/auth/workspace-license
Request: { "account_id": "...", "workspace_id": "..." }
Response (200): 
{
  "license_token": "<JWT>", // 包含 exp, iat, perm_ver, ws_id
  "perm_version": 1024,     // 单调递增整数
  "ttl_seconds": 300        // 最大5分钟
}
Error (403): 权限已撤销或不存在
```
*注：响应可能乱序，客户端必须以 `perm_version` 为准，忽略旧版本。*

#### 2. 客户端：内部许可校验模块
- **输入**：`workspace_id`, `current_monotonic_time`
- **输出**：`ALLOW` | `DENY_EXPIRED` | `DENY_REVOKED`
- **逻辑**：
  1. 检查本地是否存有该 `ws_id` 的有效许可。
  2. 若存在，比较 `monotonic_elapsed < license.ttl`。
  3. 若过期，尝试静默刷新（若在线）；若离线或刷新失败，返回 `DENY_EXPIRED`。
  4. **重启/休眠恢复**：若无法证明时间连续性（如挂钟跳变），视为许可失效，强制在线刷新或拒绝。

#### 3. 客户端：检索入口
- **前置条件**：必须先通过上述许可校验模块。
- **缓存命中处理**：即使缓存中有结果，若许可已过期，**禁止**返回标题/摘要/正文。仅当许可有效时，才从本地索引读取。

## 4. 失败与恢复时序验算

### 场景 1：正常撤销（满足硬约束）
1. T=0s: 用户在W1有有效许可（剩余4min）。
2. T=10s: 管理员撤销W1权限，服务端 `perm_version` 升至 V+1。
3. T=10s~4m50s: 用户发起新查询。客户端检查本地许可，发现 `exp` 未到，**允许查询**？
   - **修正机制**：仅靠本地TTL无法在5分钟内感知撤销。必须引入**“软失效”**或**“短轮询”**。
   - **方案A增强**：客户端在许可有效期内，若检测到网络可用，应在后台异步拉取最新 `perm_version`。若发现版本落后，立即使本地许可失效。
   - **最坏情况**：若全程离线，撤销后5分钟内用户仍可查。但这符合“诚实客户端”定义吗？**不符合**。硬要求是“服务端撤销后至多5分钟...不得获取”。
   - **关键缺口**：纯本地TTL无法保证“撤销后5分钟生效”，除非**许可本身有效期就是5分钟且每次操作都检查**。
   - **正确时序**：
     1. T=0: 签发TTL=5min许可。
     2. T=4: 撤销发生。
     3. T=4.5: 用户查询。客户端检查本地许可，显示“有效”。**违规！**
     4. **解决方案**：必须将“撤销通知”纳入机制。鉴于无推送，**唯一满足“撤销后≤5min”的机制是：每次敏感操作（打开/新查询）都尝试在线校验，或许可TTL远小于5min（如1min）且频繁刷新。**
     5. **调整后的方案A**：许可TTL设为 **60秒**。客户端每60秒或每次操作前检查。若离线，缓存最多存活60秒。撤销后，下一次60秒周期或操作时，因无法刷新或收到403而失效。这满足“至多5分钟”（实际更严）。

### 场景 2：重启/休眠
1. 设备休眠，本地计时器暂停。
2. 唤醒后，客户端无法确定经过了多少真实时间。
3. **动作**：立即将所有本地许可标记为 `UNKNOWN`。
4. **结果**：任何新查询触发在线刷新。若离线，拒绝所有工作区访问。
5. **隔离性**：W1被拒不影响W2，因为W2可独立刷新。

### 场景 3：乱序/重放
1. 客户端持有 `perm_ver=100`。
2. 网络恢复，收到旧响应 `perm_ver=99`。
3. **动作**：比对本地高水位 `max_seen_ver`。若 `99 < 100`，丢弃响应。
4. **结果**：防止旧权限复活。

## 5. 可逆迁移计划

### 阶段 1：双写与影子校验（第1-2周）
- **动作**：部署新版许可校验模块，但不拦截请求。记录“若启用新规则会被拒绝”的日志。
- **回退**：关闭日志开关，代码无副作用。
- **验收**：统计误杀率（合法请求被判定过期的比例）。

### 阶段 2：灰度切换（第3周）
- **动作**：对10%用户启用强制校验。保留旧版“合并缓存”作为只读备份（不再写入）。
- **回退**：配置中心一键切回旧版校验逻辑（需确保旧版不依赖新版数据结构）。
- **验收**：监控撤销生效延迟 P99 是否 < 5min。

### 阶段 3：全量与清理（第4周）
- **动作**：全量启用。删除旧版合并缓存代码。
- **回退**：发布紧急补丁恢复旧版二进制（非热修）。
- **注意**：一旦切换到分区缓存，旧的全局缓存数据作废，需重建索引。这是**不可逆的数据格式变更**，需在发布说明中标注“首次启动需重建索引”。

| 验证项 | 刺激/前置状态 | 观测位置 | 通过判据 | 限制/备注 |
| :--- | :--- | :--- | :--- | :--- |
| **撤销时效** | 在线状态下，服务端撤销W1权限 | 客户端日志 & UI反馈 | 从撤销API返回成功到客户端拒绝W1查询的时间间隔 ≤ 5min | 测试需模拟网络延迟波动 |

## 7. 给技术负责人的拍板建议

1.  **否决 A3 建议稿**：其“10分钟同步”和“合并缓存”直接违反安全硬约束和工作区隔离要求。
2.  **批准方案 A（改良版）**：采用 **60秒短效许可** + **按工作区物理分区缓存** + **重启即失效**。
3.  **明确离线体验降级**：向销售团队澄清，在不引入推送服务的前提下，“断网8小时连续搜索”与“撤销后5分钟生效”互斥。本方案选择后者，离线时仅支持查看已加载内容（若许可未过期）或完全不可用（若过期）。
4.  **资源投入**：2名工程师4周足够完成客户端许可模块重构和服务端签发接口微调。无需新托管服务。
5.  **下一步行动**：
    *   与安全负责人确认“60秒TTL”是否比“5分钟上限”更可接受（更严更安全）。
    *   与销售负责人沟通离线体验的预期管理，或申请预算开发“离线预授权包”（需重新评估安全风险）。
    *   启动阶段1的影子校验开发。

## 1. 契约核对与缺陷诊断

**授权范围**：纯静态分析与代码交付，无工具调用、无文件读写、无测试执行。
**验收标准**：严格遵循 M1 接口契约（输入校验、不可变性、引用隔离、端点接触不合并）；提供完整修正代码、决定性反例及定向测试设计；区分静态推演与实际执行状态。

### 当前实现 (M2) 的致命缺陷
1. **违反输入不变性**：`ranges.sort()` 原地修改了传入数组，直接违反“不得改变输入外层数组”的契约。
2. **排序语义错误**：默认 `sort()` 按字符串字典序比较。对于数值区间（如 `[2,7]` vs `[10,14]`），字典序判定 `"10" < "2"`，导致排序结果完全错误，后续归并逻辑必然失效。
3. **合并条件违背业务规则**：`r[0] <= last[1]` 会将端点接触的区间（如 `[6,9]` 和 `[9,10]`）错误合并为 `[6,10]`。契约明确要求“只在端点接触的两段要保留为两段”，正确条件应为严格小于 `r[0] < last[1]`。
4. **缺失输入校验**：未对非数组、子项长度、非负安全整数及 `start<end` 进行校验，也未抛出规定的 `Error('INVALID_RANGE')`。
5. **返回引用共享**：`result.push(r)` 将原数组中的子数组引用直接放入返回值，违反了“不与输入共享数组引用”的隔离要求。

### 为什么仅改成数值排序仍不够？
即便修复了排序函数（如使用 `(a,b)=>a[0]-b[0]`），以下三个核心契约依然被破坏：
- **副作用未消除**：`sort()` 依然会污染原始输入数组。
- **边界语义未修正**：`<=` 依然会错误吞掉“业务交接边界”。
- **内存隔离未建立**：返回的子数组依然是原对象的引用，外部修改返回值会反向篡改输入数据。

## 2. 完整修正代码

```javascript
/**
 * 归一化区间数组
 * @param {any} ranges - 待处理的区间集合
 * @returns {Array<[number, number]>} 归一化后的新数组
 */
function normalizeRanges(ranges) {
    // 1. 严格输入校验
    if (!Array.isArray(ranges)) throw new Error('INVALID_RANGE');
    
    for (const r of ranges) {
        if (!Array.isArray(r) || r.length !== 2) throw new Error('INVALID_RANGE');
        const [start, end] = r;
        // Number.isSafeInteger 同时排除了 NaN, Infinity, 小数和非数字类型
        if (!Number.isSafeInteger(start) || !Number.isSafeInteger(end)) throw new Error('INVALID_RANGE');
        if (start < 0 || end < 0 || start >= end) throw new Error('INVALID_RANGE');
    }

    // 2. 创建浅拷贝副本，保护原始输入不被 sort 修改
    const sorted = [...ranges].sort((a, b) => a[0] - b[0]);
    
    const result = [];
    for (const r of sorted) {
        const last = result[result.length - 1];
        
        // 3. 正确的合并条件：严格小于才合并，等于(端点接触)保留为两段
        if (last && r[0] < last[1]) {
            // 取最大右端点，处理包含关系（如 [1,8] 包含 [2,3]）
            last[1] = Math.max(last[1], r[1]);
        } else {
            // 4. 引用隔离：push 新数组对象，而非原引用
            result.push([r[0], r[1]]);
        }
    }
    
    return result;
}
```

**复杂度分析**：
- **时间**：$O(N \log N)$，瓶颈在于排序。遍历归并为 $O(N)$。适合 100,000 段规模。
- **空间**：$O(N)$，用于存储排序副本和结果数组。满足额外空间线性约束。

3.  **剩余风险**：
    -   若运行环境存在极端的原型链污染或自定义 `Symbol.iterator` 干扰，当前浅拷贝 `[...ranges]` 可能不足以防御（但契约已排除 Proxy/元编程输入，此风险在约定范围内可忽略）。
    -   性能方面，$O(N \log N)$ 在 100k 量级下通常 <50ms，但若 JS 引擎对 `Math.max` 内联优化不佳，可考虑手动比较 `if (r[1] > last[1]) last[1] = r[1]` 作为微优化备选。

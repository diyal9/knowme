# 复盘模板两周内部推广方案

## 一个主张
**"复盘不是补写总结，是给下个项目留一条能用的决定。"**
不宣传"更好的复盘方法"，只回应 M2 里两条真实疑问：模板三栏（目标与结果 / 关键决定及依据 / 下次要验证的问题）解决的是"流水账"和"没达成目标没法写"两个卡点。所有文案不承诺节省工时或绩效——M2 明确没有这类数据。

## 三次内容的分工与顺序

| 载体 | 承担内容 | 为什么排在这里 |
|---|---|---|
| 周报短栏① | 直面质疑：回答"这和流水账有什么区别""项目没达标还能复盘吗"，用 M2 虚构示例展示"结果尚未统计"也能填 | 先拆掉心理门槛。此时放下载链接转化低，因为读者还没认同问题 |
| 知识页 | 一页示例说明：空白模板 + 填好的示例对照 + 两条 FAQ 完整版 | 承接短栏①的好奇心，让人在收尾前随时可取；不靠它做说服 |
| 周报短栏② | 收尾场景实操：本期正好有项目收尾的人，怎么在既有归档流程外多花 10 分钟填一栏；附登记表反馈入口 | 排在第二周：此时 16 位收尾负责人临近节点，且已看过一次主张，行动成本最低 |

顺序逻辑：**先解决"凭什么信"，再解决"去哪拿"，最后解决"这周就用"**。反过来先发模板，只会变成又一次没人点的归档要求。

## 短栏②可用示例（约 150 字）
> **本周只说一件事。** 如果你手上正好有项目收尾，试试复盘模板的第三栏："下次要验证的问题"。
> 一位负责人的写法是：这个项目目标是减少交接遗漏，结果还没统计出来——但他在第二栏写下"在交接表增加接收确认"，第三栏留了"下个版本看这条确认是否真的减少了返问"。
> 这就是它和流水账的区别：流水账记录发生了什么，这个模板留下一条**下个版本能验证的决定**。没达成目标的项目尤其值得填，因为"为什么没到"正是下一栏的原料。
> 自愿试用，不进考核，归档流程不变。用完在收尾登记表勾一下并留一句反馈即可（不公开名单）。

## 沟通对象判断
- **重点**：16 位本期收尾负责人——唯一有真实使用场景的人群，全部内容围绕他们设计。
- **不必催**：30 位本期无收尾项目的负责人。对他们只做"顺带曝光"（周报自然触达），不单独引导、不制造参与压力；否则既无场景可验证，也会污染反馈质量。

## 怎么算有用
分两层，避免把访问量当成采用量：
1. **行为信号**：登记表中勾选"实际采用"的人数 + 有效反馈条数（这是主指标，去重可靠）。
2. **兴趣信号**：知识页访问/下载次数的**相对变化**（第一周 vs 第二周、短栏发布前后），仅作趋势参考——M3 说明无法按人去重，不能换算成转化率。
合格线建议：16 人中至少若干人勾选采用并留下具体反馈（如"第三栏最难填"），即算跑通；一人未动则说明主张没打中。

## 一个调整办法
第二周短栏定稿前设一次检查点：读登记表反馈原文。若集中在"不知道填多细"→ 短栏②改成示例逐栏批注；若集中在"跟归档重复"→ 改口径强调"归档存结论、模板留下个问题的钩子"；若几乎无人反馈 → 放弃继续推模板本身，改为只征集"你最想从上个项目带走什么"的一句话，先找真问题。

*以上为方案，尚未执行任何发布或表格操作。*

# 业务异常归因

## 工作步骤

1. 将异常拆成时间、渠道、用户、产品、地区和业务事件等维度。
2. 建立至少两个可竞争的解释，列出各自支持证据和反证。
3. 区分观测到的事实、合理推断和仍需验证的假设。
4. 为关键假设设计最小验证，说明所需数据、负责人和判断标准。

## 约束

- 不把相关性、时间先后或单一案例写成因果结论。
- 证据不足时降低结论强度，不强行归因。
- 不能访问数据或业务事件时，明确列出输入缺口。

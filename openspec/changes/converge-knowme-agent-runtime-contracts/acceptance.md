# 制作人验收

## 验收目标

用户在专家协作中看到一条清晰回答、一个明确动作和真实执行状态；KnowMe 公共运行链路在伙伴、专家和工作流三类场景中保持一致的上下文边界、事件判定和恢复保障。

## 必验场景

### 1. 原问题闭环

- 相同专家回答只出现一次。
- 页面标题、目标、交付与状态完整可读，无横向截断和多余边框。
- 点击确认后进入正式执行，不再次回复“请先确认再执行”。
- 执行失败时保留输入框，用户追问不会自动重试。

### 2. 确认语义

- 待澄清时没有确认入口。
- 调整内部执行步骤不反复打扰用户确认。
- 改变范围、交付物、验收、外部目标、材料边界或风险时明确要求重新确认。
- 确认计划后，高风险具体操作仍需自己的批准。
- 交付完成后按 review 等待用户接受，工具成功不冒充用户验收。

### 3. 恢复与诚实状态

- 刷新和重启不增加消息、不重放已知副作用。
- 取消后不继续启动工作；迟到外部结果以审计/待核实状态展示，不把任务改成成功。
- 无法安全恢复时说明原因和下一步，不伪造完成或静默重跑。

### 4. KnowMe lane 兼容

- 伙伴简单问答不出现专家规划确认。
- 伙伴工具调用继续使用公共治理和 canonical answer。
- 工作流保留图、节点 attempt、human/gate 与父子 Run；没有伪造聊天消息。
- 三类 lane 的消息和任务数据保持隔离。

## 工程证据

- 专项测试和新增 failure-first 用例记录。
- 最终 `npm run check`、`npm run typecheck:lib`、OpenSpec health 与 change gate 日志。
- GitNexus impact/detect_changes 记录，说明公共符号影响和既有脏工作区边界。
- Electron 目标场景的执行前、执行中、刷新后、重启后截图或录像。
- test-report 明确真实模型、真实连接器和真实外部写入哪些已执行、哪些未执行。

## 通过标准

所有必验场景通过，硬门禁无新增失败，旧任务兼容读取，partner/workflow 回归无产品语义变化，且没有将自动化测试结果表述为未执行的真实外部验证。

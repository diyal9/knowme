## Context

参见 `proposal.md` 的 Why。当前 Runtime 已实现真实父子 Run、持久化、审批和治理，但遗留双轨状态与远程链路不稳定仍增加操作复杂度。该设计以“可靠收敛 + 可审计降级 + 可控成本”为主线，保持现有架构不破坏兼容。

## Goals / Non-Goals

**Goals:**

- 统一 Run 状态权威为 RunManager，移除 legacy 并行状态源依赖。
- 建立远程健康探针与自动降级执行策略，确保可控失败而非静默挂起。
- 建立 Package 信任策略（签名、来源、吊销）并在安装与运行前强制校验。
- 建立 Team/Workspace 级预算和 SLO 守卫，支持治理熔断。

**Non-Goals:**

- 不替换现有本地执行器或重写消息总线协议。
- 不引入云端集中式密钥托管系统。
- 不扩展到多组织共享计费结算。

## Decisions

1. **状态源收口策略**
   - 决策：所有 run 查询、取消、恢复、重试 API 仅从 RunManager 获取状态，legacy `activeSubRuns` 只保留短期兼容读通道并逐步移除。
   - 原因：避免状态分歧导致的误判与边界 bug。
   - 备选：继续双写双读；放弃原因是复杂度和一致性风险长期上升。

2. **远程健康探针与降级策略**
   - 决策：对远程 adapter 增加探针窗口（握手成功率、超时率、恢复时延），超过阈值时按策略降级到本地 adapter。
   - 原因：把“失败后重试”升级为“失败前预防”。
   - 备选：仅人工切换；放弃原因是故障响应慢且依赖人工值守。

3. **Package 信任校验链**
   - 决策：安装前执行签名与来源校验，运行前复核吊销列表；失败即 fail-closed。
   - 原因：供应链风险一旦进入运行态代价高，必须前置阻断。
   - 备选：仅记录告警不阻断；放弃原因是无法满足企业治理预期。

4. **预算与 SLO 守卫**
   - 决策：在 Scheduler 引入 Team/Workspace 维度预算计量与阈值熔断，并输出结构化 SLO 指标。
   - 原因：单 run 预算不足以防止团队级资源失控。
   - 备选：仅离线报表；放弃原因是无法实时止损。

## Risks / Trade-offs

- **[风险]** 自动降级可能引发结果差异  
  **→ 缓解**：在结果中记录降级原因、执行后端和置信提示。

- **[风险]** 签名校验增加导入路径耗时  
  **→ 缓解**：缓存可信发布者元数据并增量校验。

- **[风险]** 预算熔断误伤高优先任务  
  **→ 缓解**：支持优先级白名单和临时提升配额审批。

## Migration Plan

1. 引入状态源收口开关，先镜像比对再切换到 RunManager-only。
2. 上线远程健康探针与降级策略，默认告警模式，验证后切强制模式。
3. 增加 Package 签名与吊销校验，先对新导入生效，再覆盖存量重校验。
4. 启用 Team/Workspace 预算与 SLO 指标，并接入熔断动作。
5. 完成 Daemon live E2E 稳定门禁后，移除 legacy 双轨代码。

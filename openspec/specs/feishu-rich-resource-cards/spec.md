# feishu-rich-resource-cards Specification

## Purpose

让用户在 Agent 对话中快速识别飞书资源和图片的类型、标题与可用动作，并在不同消息宽度和显示主题下保持清晰、稳定、可访问。

## Requirements

### Requirement: 飞书资源必须按类型展示

系统 MUST 根据安全飞书 URL 的路径类型，将资源展示为包含类型标识、可读标题和操作提示的资源卡片。

#### Scenario: 展示常见飞书资源

- **WHEN** Agent 回复包含文档、电子表格、多维表格、知识库或妙记链接
- **THEN** 卡片显示与 URL 类型一致的名称和视觉标识
- **AND** 标题不显示原始长 URL

#### Scenario: 展示未知飞书资源

- **WHEN** Agent 回复包含无法进一步分类的安全飞书 URL
- **THEN** 系统以“飞书资源”通用类型展示
- **AND** 链接仍可使用原有打开动作

### Requirement: 资源卡片必须适配对话布局

系统 MUST 保证飞书资源卡片在常规宽度、窄宽度和现有应用主题下保持可读且不撑破消息。

#### Scenario: 长标题与窄消息

- **WHEN** 资源标题超过卡片可用宽度或消息区域变窄
- **THEN** 标题以省略或安全折行方式收敛
- **AND** 类型标识与打开动作仍然可见

#### Scenario: 键盘与悬停反馈

- **WHEN** 用户悬停卡片或通过键盘将焦点移到卡片
- **THEN** 系统显示明确但克制的边框、背景或焦点反馈
- **AND** 文本对比度保持可读

### Requirement: 对话图片必须以媒体卡片展示

系统 MUST 为 Markdown 图片提供稳定容器、加载反馈、错误回退和放大入口。

#### Scenario: 图片加载成功

- **WHEN** 对话中的图片成功加载
- **THEN** 图片在稳定尺寸的媒体容器中显示
- **AND** 用户可以点击图片打开大图查看器

#### Scenario: 图片加载失败

- **WHEN** 对话图片无法加载
- **THEN** 系统显示不会破坏布局的错误状态
- **AND** 错误状态包含可读的图片说明

### Requirement: 现有链接安全行为必须保留

系统 MUST 保留飞书链接现有的 URL 安全校验和打开动作。

#### Scenario: 点击资源卡片

- **WHEN** 用户左键点击或从右键菜单操作资源卡片
- **THEN** 系统沿用既有外部打开、右侧预览和复制链接行为
- **AND** 非安全协议或非飞书域名不会被当作飞书资源卡片处理

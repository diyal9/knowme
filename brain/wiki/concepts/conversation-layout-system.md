# KnowMe 通用对话排版系统

## 目的

KnowMe 的对话不是一组同形卡片，而是四种不同信息的连续阅读流：用户提出问题，系统说明执行状态，助手交付正文，交互块承载确认或操作。本规范统一智能伙伴、专家协作、工作流对话和管线对话的排版与输入体验，同时保留各场景自己的业务内容。

设计目标：

- 用户消息像消息，助手回答像文章。
- 执行过程像附注，不与正文争夺注意力。
- 只有需要操作或确认的内容才使用容器和边框。
- 所有聊天入口共享同一条阅读基线、消息节奏和 Composer。
- 表单输入共享基础 token，但不伪装成聊天输入框。

## 适用范围

### 对话场景

| 场景 | 容器 | 消息 | 输入 |
|---|---|---|---|
| 智能伙伴 | `AssistantPane` | `AgentMessageBubble` | `AgentComposer` |
| 专家协作 | `TaskDialogueShell` | `TaskDialogueMessages` | `AgentComposer` |
| 工作流对话 | `TaskDialogueShell` | `TaskDialogueMessages` | `AgentComposer` |
| 管线对话 | `TaskDialogueShell` | `TaskDialogueMessages` | `AgentComposer` |

任务委托、工作流启动、验收意见、HITL 审批属于表单或决策输入。它们共享字号、焦点环、圆角和状态色，但不采用聊天消息布局。

## 信息模型

一轮对话按以下顺序组织：

1. `UserTurn`：用户问题或补充要求。
2. `ExecutionDisclosure`：运行状态、步骤、耗时和工具过程。
3. `AssistantArticle`：可连续阅读的 Markdown 正文。
4. `StructuredBlock`：计划、来源、审批、产物或下一步操作。
5. `MessageActions`：复制等对当前答复生效的操作。

执行过程与正文必须是同一条助手消息内的兄弟区块，禁止把执行日志嵌入正文段落或再套一层助手卡片。

### 回答操作

- 助手完整回复的末尾固定提供四个纯图标操作，顺序为：复制、回复优秀、回复不佳、分支到新聊天。
- 默认不显示文字标签；鼠标悬停显示提示，键盘和读屏通过 `title`、`aria-label` 与 `aria-pressed` 获得完整语义。
- 回复优秀与回复不佳互斥，再次点击当前项可取消；选中态使用品牌强调色，不改变正文布局。
- 分支操作复用会话分支能力并切换到新聊天；执行期间禁用按钮，防止重复创建。

## 布局

### 双轨宽度

- 对话轨 `--conversation-track-max: 920px`：用户消息、Composer、执行过程、宽表格、代码和媒体。
- 阅读轨 `--conversation-reading-max: 920px`：标题、段落、列表、引用和来源摘要。
- 桌面端对话表面居中；窗口变窄时轨道自动收敛为 `100%`。
- 小于 760px 时页面左右安全边距为 16px。

两条轨道共用同一左右边界。用户消息在轨道内右对齐，助手正文、执行过程和 Composer 的右边缘与用户消息一致；代码、表格和图片不得拉宽整个页面。

### 垂直节奏

- 对话首尾留白：20px / 12px。
- 消息行间距：20px；章节间距：28–32px。
- 段落间距：12px；列表项间距：8px。
- 标题前间距必须大于标题后间距。
- Composer 与最后一条消息之间至少保留 12px 可感知间隔。

## 排版

| 语义 | 字号 / 行高 | 字重 |
|---|---|---|
| 助手正文 | 16px / 1.75 | 400 |
| 用户消息 | 14px / 1.6 | 400 |
| H1 | 24px / 1.32 | 600 |
| H2 | 20px / 1.38 | 600 |
| H3 | 17px / 1.45 | 600 |
| 辅助信息 | 12px / 1.5 | 500 |
| 代码 | 13px / 1.6 | 400，等宽 |

中文界面继续使用 `Microsoft YaHei UI / Segoe UI / system-ui`，数字状态启用等宽数字。正文使用 `text-wrap: pretty`，标题使用 `text-wrap: balance`。

## 组件规范

### UserTurn

- 右对齐，宽度随内容变化，最大不超过阅读轨的 72%。
- 浅中性背景，无阴影；圆角 14px，右下角收紧以提示发言方向。
- 附件在文本下方独立成行。
- 长文本允许扩展，但不得超过阅读轨。

### ExecutionDisclosure

- 运行中默认展开，展示当前步骤；完成后默认折叠。
- 摘要格式为“状态 · 步数 · 轮次 · 操作数 / 耗时”。
- 仅运行、成功、失败标记使用状态色，其余文字保持中性。
- 执行详情字号 12px，禁止使用与正文同级的大标题或重卡片阴影。

### AssistantArticle

- 使用语义化 `article`，不绘制外框、背景和阴影。
- Markdown 标题、段落、列表、引用、代码、表格均有稳定间距。
- 普通正文使用阅读轨；宽内容可以扩展到对话轨。
- 流式期间保持与终态相同的正文尺寸，避免提交后跳版。

### StructuredBlock

只有以下内容允许使用有边界容器：

- 决策：确认、审批、选项和 HITL。
- 任务：计划、步骤、进度和失败恢复。
- 产物：文件、表格、图片和可执行动作。

来源、个性化和记忆说明默认使用弱化的可展开附注，不使用醒目卡片。

飞书资源按信息密度区分呈现：

- 飞书会议 / 妙记使用结构化卡片，展示场次、标题、时间、组织者和预览操作。
- 飞书文档、知识库、电子表格、多维表格、幻灯片和文件使用带飞书标识的行内超链接，不占用独立卡片空间。
- 两种形态均支持左键在右侧预览，右键提供飞书或外部打开、复制链接等操作。

### ContentResourceLink

对话正文中的普通 URL、飞书文档和 Markdown 文件统一使用共享链接组件：

- 普通 HTTP / HTTPS 链接左键在右侧内置浏览器打开。
- 内容源内的相对 `.md` / `.markdown` 链接左键在右侧读取并渲染文档正文；绝对路径与 `..` 路径穿越必须拒绝。
- 右键菜单固定提供“在外部浏览器打开 / 在系统中打开”和“复制链接”，不得依赖浏览器默认菜单。
- 飞书会议 / 妙记继续使用信息卡片，但飞书文档链接复用共享组件与交互。
- 链接必须具备一致的 hover、active、focus-visible 状态，并通过资源标识区分网页、Markdown 与飞书文档。

### Composer

- 空态最小高度约 88px，随输入增长，最大输入高度 180px。
- 输入字号 14px / 1.6；工具栏字号 12px。
- 输入区在上，模型、知识库、附件和发送操作在下。
- 有可发送内容时发送按钮显示为 30px 炭黑圆形；生成中复用同一位置显示停止。
- `Enter` 发送，`Shift+Enter` 换行；附件和文本任一存在即可形成可发送状态。
- 焦点环统一使用矿物青绿，但不改变输入框的白色阅读表面。

## 状态

| 状态 | 表现 |
|---|---|
| 思考中 | 单行弱提示，不创建空白正文卡片 |
| 流式输出 | 正文稳定增长，光标只出现在末尾 |
| 已完成 | 执行过程折叠，正文保持展开 |
| 失败 | 行内错误块并提供恢复操作 |
| 等待用户 | 决策块出现在正文之后、Composer 之前 |
| 超宽内容 | 块内横向滚动，不改变页面宽度 |
| 减少动态效果 | 禁用呼吸、跳动与位移动画 |

## 无障碍与交互

- 对话容器、用户消息和助手文章具有可识别的 `aria-label`。
- 所有可操作元素必须有 `focus-visible` 状态。
- hover、pressed 和 focus 不能只通过颜色表达。
- 触屏场景不依赖 hover 才能发现关键操作。
- 结构化消息不得使用不可聚焦的伪按钮。

## 实现约束

- 不引入新 UI 框架或字体依赖。
- 共享 token 位于 `src/renderer/app/tokens.css`。
- 通用对话布局位于 `src/renderer/styles/agent-chrome.css`。
- Markdown 基础样式位于 `src/renderer/features/content-view/content-view.css`。
- 业务场景不得复制一套私有消息气泡或 Composer CSS；差异通过容器 modifier 表达。
- 表单 textarea 可以消费输入 token，但不得依赖 `.agent-composer` DOM 结构。

## 验收标准

1. 四类对话场景具有相同正文大小、标题层级、消息间距和 Composer 结构。
2. 用户消息右对齐，助手回答无整体卡片，执行过程可折叠。
3. 普通正文、执行过程、用户消息与 Composer 共用右边界，代码和表格不拉宽页面。
4. Composer 在空输入、长输入、附件、生成和停止状态下不跳位。
5. 760px 以下保持 16px 安全边距，工具栏可用且不遮挡发送按钮。
6. 键盘焦点清晰，减少动态效果设置生效。

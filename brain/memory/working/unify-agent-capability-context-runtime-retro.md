# Agent 能力聚合专项复盘

## 产品约定

Agent 是范围边界，当前任务决定加载内容；发现、任务授权、身份认证与具体操作批准必须分开。KnowMe 知识指产品原生 Brain / LLM Wiki / RAG，飞书只是可选连接器，不能误把外部 Wiki 当成知识前提。

## 工程经验

- 单测通过不足以证明审批闭环：从 registry 到 IPC、任务 checkpoint、重启恢复和模型证据必须连起来测，使用计数副作用验证“只执行一次”。
- 同一目标经历多次审批时，要保留宿主执行回执的恢复关系；仅保存最后一个 run 指针容易漏掉旧操作。
- 权限“重新计算”若仍读取闭包旧 session，并非实时检查。必须读取主进程持久化身份、当前配置及父级限制。
- 模型只看到 8 项工具并不代表连接器懒加载；冷缓存服务器连接也须由选择触发。
- 摘要、Skill、schema 与输出预留需要联合预算，且已验证产物不能因最后文案生成失败而丢失。
- 主题匹配是相关性，不是知识或记忆的授权证明。未知归属要安全排除并解释。

## 验收边界

保留本地严格模拟与真实供应商测试的区别。环境没有测试模型或授权资源时明确未执行，不把 canary skip 当通过。大型既有脏工作区要做范围审查，不用专项绿灯代表整棵树可发布。

本文件记录本次实现经验，不自动升级全局 Skill 或永久用户授权。
